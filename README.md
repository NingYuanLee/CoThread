# 共序 CoThread

让每次讨论都有承接，让每个决定都有出处。

这是独立于 `D:\work\dsh` 的协作应用。项目是长期工作空间，一次迭代对应一个群聊。成员用自己的本地 AI 读取上下文、提交产物，团队人工审核后归档。Makers 云端使用原生沙箱；本地开发可显式使用本机执行器，也保留 ACS 适配。MySQL 是业务数据和附件的持久化存储。

## 本机启动

需要 Node.js 22.19+（本机已具备 Node 24）。本地 MySQL 为 Oracle 官方 MySQL 8.4.9 Windows ZIP 版，不注册系统服务，监听 `127.0.0.1:3307`。

```powershell
npm install
npm run setup
npm run mysql:start
npm run db:migrate
npm run db:seed
npm run dev
```

打开 <http://localhost:3100>。`npm run setup` 将首次初始化的账号和随机密码保存在 `.local/initial-admin.json`，`npm run db:seed` 将账号及密码哈希写入数据库。可以在「账号设置」中修改；数据库中只保存加盐密码哈希。新增成员由项目负责人操作。

本机执行设置 `LOCAL_SANDBOX_ENABLED=true`，工作文件默认位于 `.local/sandboxes`。命令由本机 Git Bash 执行，进程不会继承数据库或服务密钥；它仍能访问当前 Windows 账号可访问的系统资源，因此只应运行可信任务。容器级隔离需要另行安装 Docker、WSL 沙箱或其他隔离运行时。

本地 `.env` 保留数据库、模型和执行后端配置及 `CREDENTIAL_ENCRYPTION_KEY`。普通参数使用代码默认值；部署差异仍可通过环境变量覆盖，详见 [云端配置](docs/cloud-environment.md)。

`npm run setup` 不覆盖已有 `.env`。如果原项目的 `D:\work\dsh\.env` 存在，只复制 ACS 和 DeepSeek 必需的配置，MySQL 配置单独生成。不要提交 `.env` 或 `.local`。

```powershell
npm run mysql:stop   # 优雅关闭本地数据库
npm run build        # 类型检查及前端生产构建
npm start            # 使用构建后的静态页面
npm test             # 真实 MySQL 集成测试，独立随机测试数据库，结束后清理
npm run app:start    # Windows：后台启动生产版应用；仅连接本地 3307 时启动本地 MySQL
npm run app:stop     # Windows：停止本项目的后台应用
npm run db:backup    # 完整备份业务数据与文件内容
npm run db:restore-check # Windows 本地：导入独立测试库，校验后删除测试库
```

也提供 `compose.yaml`，安装 Docker 的机器可用官方 `mysql:8.4.9` 镜像。先设置 `MYSQL_PASSWORD`、`MYSQL_ROOT_PASSWORD`，并让 `DATABASE_URL` 中的用户密码与前者相同。不要同时启动 Docker 和便携版 MySQL 占用 3307。

## 已实现

- 登录、全局账号目录与项目成员分离；同一账号可加入多个项目，各项目分别分配负责人／成员／只读权限。负责人可新建通用账号，账号创建后不会自动获得任何项目权限。
- 项目与迭代群聊，消息按数据库序号排序，多人页面定时刷新。
- 文档二进制内容入库，5 MiB 单文件限制、SHA-256、不可覆盖的版本和并发版本编号。
- 文档人工审核记录；上传不代表审批通过，本地 AI 令牌不能审批或归档。
- 消息引用精确文档版本；归档事务保存结论、消息、审核、版本摘要和执行结果，归档后不可修改。
- 下一次迭代可以继续引用旧版本。
- 账号单令牌、30 天有效、可重置的本地 Agent 连接，使用哈希鉴权与 AES-256-GCM 加密保存，按项目成员权限访问。浏览器中默认遮罩，可点击眼睛查看。
- 7 个 Streamable HTTP MCP 工具，自带使用说明，调用者身份由服务端凭据确定。
- 内置 DSH Agent：读取项目资料、在沙箱创建/编辑文件、执行命令与测试、将成果保存为文档版本。云端使用 Makers 原生沙箱。
- 小祥对用户始终是一个身份，内部按三级组织：项目的一级小祥昵称“老翁”、名称“项目知识库管理员”，每个迭代的二级小祥是任务调度员，每项执行工作的三级小祥是任务执行者。一级上下文不长期累积，成员认识、文档摘要、任务关联、资料目录和原始资料都持久化在项目数据库中；二级和三级先查知识库索引，再按 ID 读取所需资料。
- 单个迭代最多同时运行 7 个三级执行任务，加上二级接待流程共 8 个工作上下文，项目级记忆层不占执行名额。第 8 个新执行请求到来时，小祥会说明当前工作太多、暂时只能陪用户聊天，不把请求静默排队。同一成员再次 @ 补充执行要求时更新已有任务，通过 DSH 原生 steering 在下一执行步骤接收，不新建任务。
- 各执行任务使用独立 DSH 上下文与工作目录，完成后释放进程及执行名额；这些内部结构不会作为不同身份展示给用户。Makers 同一会话共享原生沙箱，一个任务结束或停止不会关闭其他任务使用的实例。正文、附件引用、已发布成果和执行记录保留，各任务可单独停止。
- 每个迭代的二级小祥只保留五段投影：当前迭代历史、任务记录、当前相关文档摘要、本次最新消息和项目成员。成员项含个性签名及项目级持续认识；成员本人发言或被 @ 时只写入待整理队列，一级小祥定期刷新认识，允许认识自然滞后。事实依据只采用该成员亲自表达的内容。其他迭代原文、完整文档和全部执行记录不复制进上下文，需要时从 MySQL 按需读取。
- 新文档版本及三级小祥提交的摘要候选也先进入待整理队列，由一级小祥定期生成正式 Wiki 摘要。同一不可变版本只保存一份正式摘要，多个任务只增加关联。
- 每个三级执行任务使用独立 Agent 会话；会话快照、工具过程与已发布产物入 MySQL。文档摘要按不可变版本全局去重并可被其他任务复用。Makers 沙箱按需创建，工作目录使用平台检查点持久化，长期成果仍需发布到文档库。
- 聊天显示执行进度、工具输入与结果，支持停止、失败重试。服务重启后运行中任务标记中断，避免自动重复执行有副作用的操作。
- 右侧项目文档与弹窗复用同一文件树，支持拖拽整理；顶部「文档库」与侧栏「项目文档库」入口，支持可折叠的多级文件树、新建文件夹/文档、上传、移动、重命名、回收站恢复、@ 引用、版本切换、预览和下载。默认文件夹优先，文件按类型与名称排序，也可切换最近修改。Markdown、文本/代码、图片、PDF 可预览，Office 等格式下载查看。
- 输入框默认勾选「交给 Agent 处理」，取消则仅发送给团队。成员本地 AI 提交不会触发回复循环。
- 当前迭代的成员发言增量纳入二级上下文，每条纳入后检查 900K 自动压缩阈值；上下文同步、压缩与接待流程分开执行。三级执行任务继承相关摘要和消息，在独立上下文中继续工作。
- 「梳理讨论」准备一条基于已有上下文的请求，不弹出消息条数选择框，也不要求助手重新读取整个会话。需要核查缺失原文时，讨论工具支持游标分页。
- 页面先加载最近 50 条消息，向上滚动加载更早的消息；切换使用有界缓存并取消旧请求，后台刷新增量读取新消息，执行详情展开时获取。隐藏页面暂停轮询。
- 头像上传前缩至 256 像素并压缩，页面懒加载并按内容版本缓存。已有头像可使用 `node --env-file=.env scripts/compress-avatars.mjs` 预览压缩，确认结果后加 `--apply` 更新；需要 Python 和 Pillow，更新前会在 `.local/` 备份原图。
- 旧 DSH 快照恢复时清理历史头像等冗余资料，保留聊天原文和原始日志；压缩失败或计量状态过期不会永久禁用重试。

## 文档与文件存储

打开项目后点击顶部「文档库」，即可查看该项目各迭代已提交的文件。Agent 必须调用保存产物工具，文件才会进入文档库；沙箱中的临时工作文件可能过期。

当前文档原始字节和不可变版本保存在 MySQL，每个文件最多 5 MiB，沙箱回收不会删除已提交文档。**当前未接入对象存储。** 后续大型附件、压缩包、视频等应接入阿里云 OSS：MySQL 保留文档/版本/权限/校验值，OSS 保存文件本体，由服务端鉴权后提供访问。此迁移需要存储适配和旧文件搬迁，不能只改数据库连接。

## 连接本地Agent

在工作空间设置点击「连接本地Agent」，创建账号令牌，并按客户端要求配置 Streamable HTTP MCP。一个账号只需一个令牌，重置时旧令牌全部失效；旧版项目令牌在重置前仍保持原有项目范围。

```json
{
  "mcpServers": {
    "cothread": {
      "type": "http",
      "url": "http://localhost:3100/mcp",
      "headers": { "Authorization": "Bearer <你的账号令牌>" }
    }
  }
}
```

工具：`get_connection_guide`、`list_projects`、`get_project`、`get_iteration_context`、`get_document_version`、`post_message`、`submit_document`。点击「复制安装文档」自动获取当前令牌，缺失、过期或旧版仅保存哈希时自动创建或更新，完整文档已填入真实令牌，无需手工替换。多次复制复用同一有效令牌。直接粘贴给本地 Agent，它可据此配置客户端并只读验证连接。无需 SKILL：MCP initialize 的 instructions 与 `get_connection_guide` 内置完整使用协议。安装文档仅附带当前真实会话（如已选中），不包含示例消息或占位会话 ID。

账号令牌加密密钥由 `CREDENTIAL_ENCRYPTION_KEY`（32 字节 base64）指定，未配置时自动保存在 `.local/credential-encryption.key`。部署迁移和备份时须保留这份密钥（与数据库备份分开保管），否则旧令牌无法再次解密查看；显式重置可重新建立令牌。密钥和令牌明文不应进入版本库。

在迭代输入框上方点击「复制会话信息」获取 `projectId` 和 `threadId`，粘贴给本地 Agent。这是目标定位信息，不是额外的秘密令牌。也可依次调用 `list_projects` → `get_project` → `get_iteration_context` 找到并核对目标，同名目标需要用户确认。

`post_message` 支持一次发送 `body` 文本、`files` 多个文件、`refs` 已有版本 ID（等同 `/关联文件`），以及 `mentionAgent: true`（也兼容正文 `@Agent助手`）触发内置助手回复。本地 Agent 不显式提及时不会触发自动回复。文件直接保存到项目文档库，消息和全部文件在同一事务内写入，任一失败全部回滚。最多 10 个文件，单文件 5 MiB、合计 20 MiB，文件与已有引用最多 30 个。`files` 每项包含 `title`、`filename`、`contentBase64`，可选 `mime` 与 `folderId`。`submit_document` 用于单独提交文件或新版本，可指定 `folderId`；审核、归档和成员管理仍由人工进行。完整配置和调用示例见界面的「连接本地Agent」。

## 本机 Codex 连接器

左侧「本地连接器」可下载免安装的 Windows 单文件绿色版并查看自己的设备。程序已内置 Node 运行时，无需安装 Node、npm 或 .NET SDK；首次双击后检测 Git 和 Codex CLI，缺失时在界面提供安装入口，Git 优先使用系统可用的 `winget` 安装，否则打开官方页面，Codex 打开官方桌面版下载页。安装完成后点击「重新检测」即可。随后连接器打开共序网页，由用户登录并确认设备授权；授权后以一行一个项目的方式列出该账号加入的项目。一个账号同一时间只保留一台连接器，重新授权另一台电脑会替换旧连接；这一台连接器可同时绑定多个项目。用户可为每个项目分别选择或直接粘贴本地 Git 根目录、是否允许 Git 推送并开启连接。本地路径和上述本机配置仅保存在电脑上，云端不保存路径或上传仓库。

「本机 Codex」开关按项目判断：只要项目内任意一名可编辑成员的已关联连接器在线即可开启。发起人自己的连接器在线时可不 @，默认分给自己；自己的连接器离线时，必须且只能 @ 一名连接器在线的项目成员。小祥读取项目资料后生成待确认任务，被分配成员可编辑后确认、取消，或在确认前转交给另一名有在线连接器的成员。确认后任务锁定到一台设备并使用唯一短期租约，其他设备不能领取。是否提交以确认后的任务正文为准；只有项目在该连接器上明确开启“允许 Git 推送”时，任务才可要求推送（包括 `main`）。修改范围由确认后的任务正文决定，完成后通过任务结果和 Git Diff 人工审核。

连接器任务列表展示项目、迭代、提出人、接收时间、首次开始时间、最新时间、目标和状态。任务由执行成员手动开始，可暂停、继续或结束；完成和失败先进入“待通知”，点击通知后才把结果发布到迭代。状态包括待开始、执行中、暂停、终止待通过、失败待通知、成功待通知、终止、成功和失败，并按状态提供放弃、立即开始、暂停、继续、结束、重试和通知操作。

构建 Windows 单文件程序使用 `npm run connector:build`。构建脚本固定使用经过官方 SHA-256 校验的 Node 22 LTS x64 运行时，发行版支持主流 Windows 10/11 64 位电脑，不支持 32 位 Windows；可用 `CONNECTOR_NODE_EXE` 指定另一个已验证运行时。程序无需安装，运行数据和诊断日志写入当前用户的 `%LOCALAPPDATA%\\CoThreadConnector`；“开机自动启动”使用当前用户启动项，无需管理员权限。发布前设置 `CONNECTOR_UPDATE_PUBLIC_KEY` 写入更新验签公钥；设置 `CONNECTOR_CODESIGN_CERT_SHA1` 可在 SEA 注入后对最终 EXE 做 Authenticode 签名。服务器配置与该公钥配对的 `CONNECTOR_UPDATE_PRIVATE_KEY` 后，超级管理员可在“系统管理 → 连接器管理”上传 EXE 并填写版本号，服务端会自动计算 SHA-256、签名并提供自动更新。也可用 `npm run connector:sign -- <exe> <version> <download-url>` 生成传统环境变量发布清单。私钥和代码签名证书不能进入仓库；面向其他电脑分发时应配置受信任的 Authenticode 证书，避免 SmartScreen 或企业策略拦截未签名 EXE。

## 普通服务器／容器部署

阿里云 RDS 默认 MySQL 端口为 `3306`，以下示例中的 `YOUR_RDS_HOST` 请替换为实际连接地址。在 `.env` 中将 `DATABASE_URL` 配置为 `mysql://RDS_USER:RDS_PASSWORD@YOUR_RDS_HOST:3306/cothread`，使用实际 RDS 账号、密码和库名（账号密码中的特殊字符须进行 URL 编码）。应用所在主机需要能访问该地址，并加入 RDS 访问白名单。已有应用需重启才能读取新配置；切换连接地址不会自动迁移本地数据。

1. 创建 MySQL 8.4 数据库，迁移本地完整备份（包含附件内容）。空库则运行迁移与初始账号创建。
2. 修改 `DATABASE_URL`，需要 TLS 的云数据库设置 `DATABASE_SSL=true`；自签发 CA 通过 `DATABASE_SSL_CA` 指向证书文件。
3. 配置 `HOST=0.0.0.0`、实际 HTTPS `APP_ORIGIN`、`COOKIE_SECURE=true`，在应用前配置 HTTPS 反向代理。
4. 复制 ACS／模型配置到云端密钥配置中。运行 `npm ci && npm run build`，然后启动单个 `npm start` 实例。
5. MySQL 的 `max_allowed_packet` 建议至少 32 MiB。配置定期备份并演练恢复。
6. DSH 与 SDK 已作为应用依赖安装，宿主机仅编排 Agent，执行工具走 ACS。应用需要可写 `.local/agents` 缓存目录，权威会话快照保存在 MySQL。升级 DSH 时需同步验证会话恢复适配器。

仅迁移数据库时无需修改业务代码或搬运附件目录；部署主机、HTTPS、数据库网络访问与 ACS 网络连通性仍须正常配置。

## 项目结构

```text
web/                 React 页面
server/              HTTP API、权限、协作业务、MCP、ACS
migrations/          版本化 MySQL 结构
scripts/             安装初始化、迁移、示例、连接检查
tests/               真实数据库集成测试
docs/                架构与部署说明
.local/              本机 MySQL 程序、数据、私有配置（不入库）
```

首版面向小团队单实例试用。暂不包含邮件邀请、SSO、密码找回、推送通知、全文搜索、文件在线编辑、对象存储和多实例作业调度。不要把当前版本当作完成全部生产加固的公共 SaaS。
