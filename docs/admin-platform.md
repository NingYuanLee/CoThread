# 共序管理平台

管理平台地址为 `/admin`，沿用现有成员账号、密码和登录会话。未登录时使用现有登录页，登录后回到管理平台。有管理页面权限的成员可在个人设置中点击“进入管理平台”。

## 页面与功能

左侧为“工作管理 / 组织管理 / 平台管理”菜单及第二级页面；右侧顶栏显示当前位置、当前成员和工作空间入口，内容区提供以下页面：

品牌与侧栏收缩控制复用工作空间组件，顶栏高度为 48px，图标按钮为 30px。内容区直接展示统一的 30px 筛选控件与表格，详情、新增、编辑及确认操作通过弹窗完成；弹窗复用工作空间的遮罩、关闭按钮和进入/退出动画。成员角色分配在成员列表弹窗完成，角色权限页仅维护角色与权限树，插件页通过下拉框切换 Agent 层级与插件类型。

| 页面     | 功能                                                                                                                                  |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 项目管理 | 搜索与状态筛选、新增、归档、恢复，通过“详情 / 成员 / 记录”独立弹窗查看项目资料                                                        |
| 迭代管理 | 跨项目查询、按项目和状态筛选、分页、修改进行中的迭代名称                                                                              |
| 任务管理 | 跨项目查询、筛选、分页，查看目标、约束、结果、状态和进度记录                                                                          |
| 成员管理 | 沿用成员目录，搜索、状态筛选、新增、停用、恢复、重置密码，展示头像，分配管理角色；通过“详情 / 项目 / 变更记录 / 登录记录”独立弹窗查看 |
| 插件管理 | 保留各 Agent 层插件清单与系统提示词，新增、编辑和归档自定义 Skills                                                                    |
| 角色权限 | 创建、编辑、删除未分配的角色，配置三级权限树                                                                                          |

任务执行、接受、转派和取消仍按原工作空间的流程操作。运行中和已结束的任务、已归档的项目与迭代无法通过管理平台修改资料。

## 授权

权限目录在 `shared/admin-permissions.js`，结构为“菜单 → 页面 → 功能”。角色保存在 `admin_roles`，成员与角色的关联保存在 `admin_user_roles`，成员身份仍以 `users.id` 为准。

- “分配成员角色”功能归属成员管理页，沿用既有 `roles.assign` 权限键。分配选项接口按该功能鉴权，成员管理员无需获得角色管理页访问权限。
- 多角色权限取并集；功能权限自动包含所属页面与菜单。
- 只勾选页面时仅允许读取，不包含新增、编辑等功能；只勾选菜单不获得页面操作能力。
- 现有 `is_super_admin` 账号拥有全部权限，无需另建管理员或分配角色。
- 普通成员默认没有平台权限。超级管理员在“角色权限”中建立角色，再到“成员管理”分配角色后即可访问。
- 管理 API 每次请求都重新读取角色权限；撤销或变更授权后下一次请求立即生效。
- `/api/admin` 接口按 HTTP 方法与路径明确映射权限，未登记的管理接口默认拒绝访问。领域方法也校验相应权限。
- 委派管理员不能授予超出自身范围的权限，不能修改更高权限角色或成员的角色与账号，不能给自己修改角色。
- 超级管理员账号受保护，不能停用自己的账号或最后一位有效超级管理员。重置密码会使目标账号的现有登录失效。
- 角色修改、成员角色分配和迭代、任务资料修改记录在 `admin_change_logs`；项目、账号、Skill 的记录沿用原审计表。

## 数据库迁移与验证

新增迁移 `100_admin_rbac.sql`。本地开发启动按既有流程自动迁移，其他环境按项目原有迁移/部署流程应用。迁移仅创建角色、关联和管理审计表，保留全部已有成员及超级管理员标记。

针对权限边界的测试：

```powershell
node --env-file-if-exists=.env --test --test-concurrency=1 tests/admin-permissions.test.js tests/admin-rbac.test.js tests/system-administration.test.js tests/plugin-management.test.js
npm run build
npm run lint
```

集成测试使用独立测试数据库，不使用或清空日常开发数据库。
