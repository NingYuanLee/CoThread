# 架构优化执行记录

日期：2026-10-17。范围：现有单实例应用的代码职责、状态归属、依赖方向与执行生命周期；保留 HTTP、MCP 和业务数据契约。

## 工作台状态

- 项目任务列表由 `use-project-tasks.ts` 提供共享资源，轮询与手动刷新拒绝旧请求覆盖新结果；作用域实例变化即隐藏旧快照，A→B→A 也不会短暂回显失效列表。
- `TaskListDialog.tsx` 管理搜索与选择，按任务 ID 重建的 `TaskDetailPanel.tsx` 管理详情轮询、时间线筛选、操作草稿和提交状态；工作台只传递上下文与业务回调。操作前后失效旧轮询，防止旧详情覆盖提交后的状态，卸载时取消请求。
- `use-account-session.ts` 管理当前身份、记住的账号、忘记/退出/切换操作；工作台在身份变化时失效缓存，身份未完成初始化时不显示旧工作区。
- `use-conversation-selection.ts` 管理附件、文件夹、引用与预览；作用域包含账号、项目与迭代，A→B→A 切换也不会接收旧回调或恢复已失效引用。
- 创建/操作成功与后续刷新失败分开反馈，避免提示用户重复执行已成功的写入。

## 后端职责

`service.js` 保留公开方法并显式委派，领域模块不反向导入该门面：

| 模块 | 职责 |
| --- | --- |
| service-access.js | 项目、迭代与平台的访问控制 |
| service-members.js | 成员、负责人、管理员与成员审计 |
| service-projects.js | 项目设置、页签、列表与项目视图 |
| service-iterations.js | 迭代上下文、背景目标、归档工作流入口 |
| service-messages.js | 消息读取、发送、引用及已读回执 |
| service-monitor.js | Agent 运行状态、轨迹与事件查询 |
| service-notification-operations.js | 通知公开方法到既有通知领域的适配 |
| service-support.js | 校验、消息行解析及共享查询片段 |

`task-pool.js` 只保留兼容导出。政策常量、访问控制、文档引用、查询、派发、任务命令、指派、拒绝/恢复决策和 L3 执行生命周期分别归属 `task-*.js`；内部引用具体模块，保留原有事务与授权检查。架构门禁检查领域模块的反向依赖和循环依赖。

归档 HTTP 入口可注入 `startArchiveDraft`。生产默认使用既有启动器；验收最终归档状态的测试显式保留队列并使用模拟总结器，避免与真实模型认领竞争。

## Agent 监控

- `agent-monitor-types.ts` 定义数据契约。
- `agent-monitor-model.ts` 负责会话筛选、任务去重、执行槽位及状态推导。
- 卡片、历史、会话及事件弹窗分别归属独立组件。
- `use-agent-monitor-resource.ts` 负责轮询、手动刷新、取消与过期响应处理；主组件负责视图编排和用户选择。

## 沙箱恢复与回收

- 持久 provider 必须注册并实现 create/connect；名称不可覆盖已有实现，同一实现只能对应一个持久名称，同名同实现重复注册仍幂等。
- 旧无前缀引用只属于 local；自定义 provider 使用 `cothread:<provider>:<id>` 在既有字段内保存所属身份。
- acquire/release 按工作区串行处理，缓存记录所属 provider；切换 provider 时拒绝复用旧句柄。
- 释放通过引用所属 provider 恢复资源；未知 provider、网络故障或回收失败不清空绑定。数据库清理只比较并清除本次引用，不覆盖新绑定。
- 新资源持久化失败时执行回收；已结束的句柄不会因数据库清理失败被复用。健康检查报告实际配置的 provider。
