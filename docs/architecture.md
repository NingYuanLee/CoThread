# 共序架构与运行边界

## 协作与存储

浏览器/成员本地 AI → 共序 HTTP/MCP → 鉴权业务服务 → MySQL。

MySQL 保存账号、项目、成员、迭代讨论、文档原始字节、不可覆盖的版本、审核、归档、任务状态、工具事件与 Agent 会话快照。文档每文件上限 5 MiB，保存 SHA-256 校验值。顶部和侧栏都有文档库入口，窄窗口也可打开；可搜索、切换版本、预览、下载和引用。文件树支持多级文件夹和整理操作；默认文件夹优先，然后按扩展名、名称（中文拼音/字母）排序，也支持最近修改排序。新版本、重命名和移动更新文档修改时间。删除文档为可恢复的软删除，旧版本引用仍可读取；只允许删除空文件夹。

消息引用精确版本。写消息、提交版本、审核和归档先锁定迭代，避免归档边界遗漏。上传和 Agent 发布均不代表人工通过；Agent 无权审批或归档。运行中 Agent 阻止归档，归档会取消排队任务。每次工具调用重新验证成员权限和任务状态，发布在事务内再次验证。

当前没有对象存储。ACS 只放工作副本；已发布文件在 MySQL，不依赖沙箱寿命。后续接入 OSS 时，保留版本 ID、权限和哈希，将文件字节迁移至私有 Bucket；访问仍需应用鉴权，不能使用公共读作为权限替代。

## DSH Agent 与 ACS

应用宿主机安装官方 DSH/SDK 0.1.2-rc.1，启动独立进程编排 Agent。模型可见工具严格限定为：project_context、read_document、read_iteration、sandbox_command、sandbox_read、sandbox_write、publish_artifact。命令与工作文件操作只在 ACS 执行，没有宿主机命令降级路径。

私有回环桥接接口使用每任务随机令牌；DSH 子进程只接收必要模型凭据与桥接配置，不继承 MySQL/ACS 密钥。ACS 工具环境不注入这些密钥。迭代使用独立工作区，沙箱按需创建、按工具调用续期 15 分钟；没有工作副本永久保存的保证。

任务最长 10 分钟，最多 40 次工具调用，单次命令最长 90 秒，输出有长度限制。工具过程、实际输入输出与执行进度入库，界面支持展开查看和停止。停止不能撤销已经完成的外部操作或已保存版本。发布依据消息、文档和内容哈希去重；失败重试前仍需检查已生成成果。

每次任务结束关闭 DSH 并将会话目录压缩保存到 MySQL（上限 10 MiB）；下次恢复缓存再运行。该 SDK 同名 session 默认走 create，runtime/sdk-resume.mjs 对固定版本 SDK 做显式 resume 适配。升级依赖必须重新验证该适配。异常关闭可能丢失本轮尚未写入的会话快照，但已提交文档和工具记录仍在数据库。运行中任务在应用重启后标记中断，不自动重放。

「梳理讨论」单独使用直接模型调用，只总结最近最多 50 条消息、80 KB 上下文，不使用 Agent 工具。SUMMARY_MODE=dsh 保留可选旧 ACS headless 总结链路；该模式可能需要临时安装环境，速度较慢。

## 部署和备份

本机官方 MySQL 8.4.9 监听 127.0.0.1:3307，数据在 .local/mysql-data，不能当作临时缓存删除。完整备份需包含 versions.content、agent_sessions.checkpoint 和工具事件。

npm run db:backup 导出完整数据库；npm run db:restore-check 在随机独立数据库中恢复，比较业务表数量、文件 SHA-256 和会话快照哈希，再清理演练库。npm test 同样使用独立随机测试库，不改动真实项目。

云迁移应先导入数据库，再修改 DATABASE_URL。数据库 TLS 验证证书；公网入口需 HTTPS，正确 APP_ORIGIN 与安全 Cookie。应用缓存目录应可写。当前仅支持单服务实例，扩容前需要独立队列和任务租约。

## 实际验收

Agent 在 ACS 创建求和脚本、执行断言、保存 v1；后续读取并修改脚本，执行五项测试并保存同一文档的 v2。回收旧沙箱并移开宿主 Agent 缓存后，仍能从 MySQL 恢复 v2，在新 ACS 沙箱运行五项测试，退出码 0。会话恢复适配后，新轮事件已进入更新后的 MySQL 快照。

文档库在浏览器窄窗口验证可打开并预览脚本。Markdown 不渲染原始 HTML，禁用外部图片；文本/代码、图片和 PDF 可预览，其余格式下载查看。目前不含在线 Office 编辑、大文件存储、任务多实例调度。
# 对话附件

每个项目自动创建系统文件夹“对话临时文件”，由 `system_key=chat_uploads` 标识。服务端禁止重命名、移动、删除该文件夹，也禁止普通文件或子文件夹移入；其中的文件可移出到根目录或普通文件夹。

登录用户通过 `/api/threads/:id/attachments` 上传文件，沿用 MySQL 文件版本持久化和项目权限校验。上传不会自动发布消息；发送时使用不可变版本 ID 引用附件。输入区支持多文件拖拽、粘贴、真实上传进度、图片预览、文件图标，`/` 选择项目文件，`@` 选择项目成员并插入姓名。单文件最多 5 MiB，每条消息最多引用 30 个文件。

上传成功后点击附件叉号，会将上传文件移入文档回收站；对已有项目文件点击叉号仅取消引用。上传过程中点击叉号会在保存请求完成后回收文件，避免中止网络请求后遗留不可见附件。发送后的文件继续保留在文档库。


### Agent 成员与按需参与

Agent助手作为内置成员出现在项目成员列表和 @ 候选中。每条登录成员发言都会排入持久任务：明确 @Agent助手，或发言时项目中只有该成员与内置助手时，直接回复；多人项目中没有明确 @ 时先请求模型判断是否参与，模型可选择沉默。成员数量按项目实际成员计算，不按发言人数或在线人数计算。沉默只保存任务状态，不生成聊天消息或启动执行沙箱。模型决定参与后才执行完整 Agent 流程；本地 AI 或 Agent 自身发言不会触发循环。

“梳理讨论”在输入框预填一条 @Agent助手 的请求，成员发送后按普通消息处理；兼容的 summary 接口也提交同样的提及消息。每轮事件通过触发消息 ID 关联，完成后通过 reply_id 放入对应助手回复，进行中、失败和停止状态归属各自轮次。执行过程和正文共用消息内容列，左边缘对齐。


### 会话上下文与压缩

每个迭代会话对应一个独立的 DSH 持久会话，默认容量 1,000,000 tokens，自动压缩阈值 900,000 tokens。已处理消息的位置与原生快照一起保存，新请求只追加尚未纳入的成员消息；原生助手输出与压缩摘要直接沿用，不再重复拼接最近 30 条聊天。即使助手选择沉默，该消息也保存到同一套上下文，参与判断使用原生会话投影。

输入框左上方展示上下文用量。总量读取原生 token meter 的模型计量锚点与当前增量；组成占比使用该计量器的估算口径，分为系统指令、工具定义、成员讨论、助手回复、文件与工具结果、压缩摘要和待纳入消息。未读取的文档正文不计入上下文，组成估算不伪装成精确计费 token。

默认采用 DSH 原生压缩，将较早的内容替换为模型摘要，保留近期约 64K 内容，摘要输出上限 8192 tokens。启动请求前及执行步骤之间检查压力，900K 起自动压缩。手动入口为 POST /api/threads/:id/context/compact，按会话持久排队，当前回复任务结束后由同一个后台工作器处理；失败可重试。压缩不删除群聊消息、执行记录或文档，快照提交成功后才标记手动压缩完成。应用启动后会无模型调用地补齐旧快照的用量信息。

验证包含原生运行时的自动/手动压缩、压缩后继续请求、快照恢复与会话隔离、增量消息去重、实时用量去重、队列状态、错误恢复和访问控制；模型请求在这些测试中由本地固定响应服务提供。
