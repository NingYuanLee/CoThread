# 共序架构与运行边界

一次部署对应一家公司：服务独立运行，MySQL 与其他部署隔离。公司内的协作层级是项目 → 迭代 → 任务。角色层级是公司成员管理（仅人类，含超级管理员）→ 项目成员（本项目人类、项目级 Agent L1、调度角色 L2；本地执行器隶属于人类成员，L3 隶属于 L2，均不单独列成员）。L2 是项目内同一角色，各迭代只是该角色的独立会话，不是按迭代各算一名成员。L1/L2/L3 对外都是小祥，不进入 `users` 表。

## 协作与存储

浏览器/成员本地 AI → 共序 HTTP/MCP → 鉴权业务服务 → MySQL。

MySQL 保存账号、项目、成员、迭代讨论、文档原始字节、不可覆盖的版本、审核、归档、任务状态、工具事件与 Agent 会话快照。文档每文件上限 20 MiB（MCP 单次工具参数约 10KB，更大文件必须分片），保存 SHA-256 校验值。文档在右侧文件浏览器中查看；对话里的引用和文档链接会展开该侧栏。可搜索、切换版本、预览、下载和引用。文件树支持多级文件夹和整理操作；默认文件夹优先，然后按扩展名、名称（中文拼音/字母）排序，也支持最近修改排序。新版本、重命名和移动更新文档修改时间。删除文档为可恢复的软删除，旧版本引用仍可读取；只允许删除空文件夹。回收站可由项目成员永久清空：未被消息或任务引用的文件会从数据库删除；仍被引用的版本保留内容供历史查看，但不能再恢复到文件树。Agent 与 MCP 不能清空回收站。

消息引用精确版本。写消息、提交版本、审核和归档先锁定迭代，避免归档边界遗漏。上传和 Agent 发布均不代表人工通过；Agent 无权审批或归档。运行中 Agent 阻止归档，归档会取消排队任务。每次工具调用重新验证成员权限和任务状态，发布在事务内再次验证。

当前没有对象存储。执行工作区只放工作副本；已发布文件在 MySQL，不依赖工作区寿命。后续接入 OSS 时，保留版本 ID、权限和哈希，将文件字节迁移至私有 Bucket；访问仍需应用鉴权，不能使用公共读作为权限替代。

## DSH Agent 与执行环境

应用宿主机安装官方 DSH/SDK 0.1.2-rc.1，启动独立进程编排 Agent。L1 的成员发言、文档摘要、文档整理、迭代归档按项目各维护独立 DSH 会话，同项目多次整理接续同一套上下文与轨迹；迭代归档同时总结该轮并更新项目长期记忆。L2 每个迭代一套上下文与轨迹。L3 每个任务一套独立 DSH 会话，七个槽位只限制并发；监控里可打开该任务的原生会话并追加要求。模型可见工具严格限定为共序注入的能力。本地服务固定使用 `.local/sandboxes` 下的本机工作区和 Git Bash；Makers 部署固定使用请求注入的原生沙箱。两条路径之间不做回退。

插件管理读取项目内的 DSH 注册表，并通过 DSH 官方 composition API 合成 `sdk-minimal + model patch + 层级 patch + 动态 patch`，不把原生插件、原子能力或层级合同复制进业务数据库。系统管理按 L1/L2/L3 展示 `dsh-plugins`、`cothread-dsh-plugins`、`自定义skills` 三个视图。插件状态区分 `assembled`（生产 patch 组合结果中已装配，不是当前进程的实时加载状态）、`exposed`（当前 Agent 层可见）和 `callable`（当前层合同允许调用）；共享进程中物理装配的 AgentTeam 插件不会因此自动暴露给 L3。`dsh-plugins` 只展示未包装的 DSH 原生运行时插件，其中系统提示词插件可展开查看各层角色提示段、注入来源和变量注释；`cothread-dsh-plugins` 展示共序按 DSH/Cordis 规则新增或改造的插件，并在插件行内列出其 Tool/MCP。可执行插件与权限上限只能通过代码、依赖和 patch 发布。每层插件及能力合同固定分为 required、optional、forbidden；optional 必须声明代码内默认启用状态，账号、项目资料和自定义 Skill 都不能扩大该边界。

未改造的 DSH 原生插件保留原包、原 ID 和原实现。共序修改过或新增的实现使用独立 `cothread-*` plugin ID，声明标准 `name`、`inject` 和 `apply` 导出，并通过 Cordis patch 装配；Tool 和 MCP 是这些插件暴露的能力，不再作为平行注册目录。

dsh-plugins 视图同时按 L1/L2/L3 展示提示词变量注释。基础 patch 的 persona 保持为空，L1/L2/L3 稳定角色、人格、权限边界只由 `cothread-system-prompt` 插件按 Agent ID 注入；每轮 prompt 只传递项目 ID、任务、动态上下文和本轮运行指令。自定义 Skills 由独立 Skill Provider 追加。`system` 层变量是 DSH `systemPrompt` 注入内容，`task` 层变量是每次运行时由后端构造的任务资料，`runtime` 层变量仅用于身份识别和层级选择。变量注释记录变量名、来源和语义；任务资料和数据库 Skill 都不能覆盖层级契约或扩大原子能力边界。

数据库只保存超级管理员后添加的纯提示词自定义 Skills、不可变版本和审计记录，初始化时没有任何 Skill 数据。Skill 按 L1/L2/L3 隔离，可新建、编辑、启停和归档，但不引用 Tool、MCP 或原子能力，也不能携带代码、模块路径或自定义 MCP 地址。运行时把已启用提示词作为 DSH `systemPrompt` 附加段注入；L1 的全工具拒绝、L2/L3 的 DSH 工具守卫和后端业务权限始终独立执行。

本机执行器只限制文件接口的工作目录，并清除子进程中的数据库和服务密钥。命令本身仍以当前操作系统账号运行，可以访问该账号有权访问的其他资源，不具备容器或虚拟机级安全边界，只用于受信任的本地开发任务。

私有回环桥接接口使用每任务随机令牌；DSH 子进程只接收必要模型凭据与桥接配置，不继承 MySQL 或沙箱服务密钥。工具环境不注入这些密钥。迭代使用独立工作区，工作区按需创建；没有工作副本永久保存的保证。

单次沙箱命令最长 90 秒，输出有长度限制。工具过程、实际输入输出与执行进度入库，界面支持展开查看和停止。停止不能撤销已经完成的外部操作或已保存版本。发布依据消息、文档和内容哈希去重；失败重试前仍需检查已生成成果。

L2/L3 另有受限的 `capture_preview_screenshot` 视觉验收工具，只能渲染当前项目文档树、项目文档版本预览和当前 L3 沙箱中的 HTML，不接触宿主机屏幕或任意外部 URL。涉及 HTML、网页或可视化产物时，截图是完成验收的必要证据，不能用命令退出码、源代码或数据库状态替代。L1 文档整理在实际目录变更后自动渲染文档树截图，并把图片作为同一维护会话的二次输入；视觉复核未通过时，整理任务不会标记为完成。运行截图需要 `npm run setup:preview-browser` 安装 Chromium。
截图同时作为模型图片输入和受项目权限保护的内部视觉附件保存，因此 L1/L2/L3 的轨迹和 L3 会话可以直接预览同一张截图，不把完整 Base64 写入事件日志。若当前模型不支持图片输入，可将对应的 `KNOWLEDGE_MODEL_VISION`、`COORDINATOR_MODEL_VISION` 或 `EXECUTOR_MODEL_VISION` 设为 `false`；此时视觉验收会返回 `model_no_image_input` 并明确跳过，不会伪造通过。

L2 一轮结束后停住进程内 AgentTeam：有在跑的 L3 时保持 harness，空闲 5 分钟且无子 Agent 后才关闭并把会话目录压缩进 MySQL（上限 10 MiB）。下次恢复缓存再运行。该 SDK 同名 session 默认走 create，runtime/sdk-resume.mjs 对固定版本 SDK 做显式 resume 适配。升级依赖必须重新验证该适配。异常关闭可能丢失本轮尚未写入的会话快照，但已提交文档和工具记录仍在数据库。运行中 L3 在应用重启后标记中断，写入 `coordinator_events.child_result` 唤醒 L2 重新评估，不自动重放。

「梳理讨论」单独使用直接模型调用，只总结最近最多 50 条消息、80 KB 上下文，不使用 Agent 工具。`SUMMARY_MODE=dsh` 可在当前本地或 Makers 沙箱中运行 headless 总结；该模式可能需要临时安装环境，速度较慢。

## 部署和备份

本机官方 MySQL 8.4.9 监听 127.0.0.1:3307，数据在 .local/mysql-data，不能当作临时缓存删除。完整备份需包含 versions.content、agent_sessions.checkpoint 和工具事件。

npm run db:backup 导出完整数据库；npm run db:restore-check 在随机独立数据库中恢复，比较业务表数量、文件 SHA-256 和会话快照哈希，再清理演练库。npm test 使用 `TEST_DATABASE_URL`（或回退 `DATABASE_URL`），但禁止清库日常开发库 `cothread` / `cothread_dev`；测试持有命名锁后清空表并重新迁移，绝不能使用生产库或日常开发库。本机可在同一台 3307 上另开 `cothread_test`。

云迁移应先导入数据库，再修改 DATABASE_URL。数据库 TLS 验证证书；公网入口需 HTTPS，正确 APP_ORIGIN 与安全 Cookie。应用缓存目录应可写。当前仅支持单服务实例，扩容前需要独立队列和任务租约。

## 实际验收

Agent 在当前运行环境的沙箱中创建求和脚本、执行断言、保存 v1；后续读取并修改脚本，执行五项测试并保存同一文档的 v2。回收旧沙箱并移开宿主 Agent 缓存后，仍能从 MySQL 恢复 v2，在新沙箱运行五项测试，退出码 0。会话恢复适配后，新轮事件已进入更新后的 MySQL 快照。

文档库在浏览器窄窗口验证可打开并预览脚本。Markdown 不渲染原始 HTML，禁用外部图片；文本/代码、图片和 PDF 可预览，其余格式下载查看。目前不含在线 Office 编辑、大文件存储、任务多实例调度。
# 项目文档库

文档绑定在项目下，项目内全部迭代共享同一套文档库。右侧文件浏览器以单树展示三个区：

- **对话缓存**：只接受对话框上传或 MCP `post_message` 的 files。按 Asia/Shanghai 自然日进入 `对话缓存/YYYY-MM-DD`。内容对 Agent 只读；Agent 不能往缓存区新增。人工可重命名、软删除、恢复、审核、引用和下载。
- **沙箱产物**：主要由云端 Agent 在沙箱中生成、编辑并发布（含从别处下载后保存到此，以及按对话缓存修改后的结果）。人工不能把对话附件丢进沙箱产物区；可重命名、软删除、恢复、审核、引用和下载。
- **正式文件**：已确认的缓存/产物可另存至此，或人类在正式文件区手动上传。正式文件不分版本叠加，不走「需要修改」。

消息可引用本项目文档库中的有效版本。点「需要修改」必须填写意见，确认后以人类消息发到**当前迭代**群聊：沙箱产物 @小祥；对话缓存若不是本人上传则 @来源人，本人上传的对话缓存则 @小祥。单文件最多 20 MiB，每条消息最多引用 30 个文件。仍兼容历史上按迭代隔离的 cache/outputs 目录，展示时归入对应项目区。

登录用户只能通过对话框或 MCP 的 `upload_cache_draft` 上传需要随消息发送的对话缓存；MCP 的 `upload_official_file` 独立对应用户手动上传正式文件，但其返回版本仍可被消息引用。任务生成的文件默认进入沙箱产物。

「正式文件整理」随时可排队给一级小祥后台执行，不生成聊天提示词；执行期间正式文件区锁定写入（上传、另存、恢复与整理操作）。「迭代归档」由成员在迭代内确认结论后执行：固定讨论与引用版本，已确认产物最新版另存至正式文件，并排队给一级小祥总结本轮、更新项目长期总结记忆；同项目多次归档接续同一套上下文与轨迹。文档库本身不随归档消失。

上传成功后点击附件叉号，会将上传文件移入文档回收站；对已有项目文件点击叉号仅取消引用。上传过程中点击叉号会在保存请求完成后回收文件，避免中止网络请求后遗留不可见附件。发送后的文件继续保留在文档库。


### Agent 成员与按需参与

小祥不是公司目录里的人类账号，也不会写入 `users` 表。L1 与 L2 作为项目 Agent 成员出现在项目管理中。L1 只维护项目知识库，不进入会话，也不出现在 @ 候选。@ 候选只露出进会话的对外身份小祥（对应 L2）。L2 是项目内同一调度角色，各迭代使用独立 DSH 会话；监控页按迭代展示这些会话与 7 个 L3 执行槽，但不把 L2/L3 按会话拆成多名项目成员。每条登录成员发言都会排入持久任务：明确 @小祥，或发言时项目中只有该成员与助手时，直接回复；多人项目中没有明确 @ 时先请求模型判断是否参与，模型可选择沉默。按需参与像人类编辑回复：先起草一句对当前讨论的整合理解，发出前若又有新消息则改稿或改为不发；一段连发只落一条可见回复，并吸收其间的待判消息（含此前被判沉默、仍未被回复的连发）。硬规则必回：句首点名「小祥，…」、催沉默/不说话、同内容连发满 3 次、以及紧跟小祥发言的短点评（夸快/感谢/追问，不含「好的/收到」纯确认）。要写文档/总结/分析等实活，或成员语气明显着急/不满时，轻量路径不回「我这就开始」，而是提醒对方 `@小祥` 以启动完整模式。硬规则可沉默：纯确认、冷却期内闲聊。模型口头承诺「每条都回」不作数。轻量判断不走完整调度会话，但仍把模型用量、用时写入 `assistant_replies.usage_stats`，并落 `participation_judge` / `assistant_final` 到二级轨迹。轻量 prompt 带最近约 12 条、每条约 240 字截断正文，输出上限约 768 tokens。约 60 秒冷却可被上述必回规则打断。人类成员数量按项目 `members` 表计算，不把 L1/L2/L3 算作人类，也不按发言人数或在线人数计算。沉默只保存任务状态，不生成聊天消息或启动执行沙箱；本地 AI 或 Agent 自身发言不会触发循环。

二级小祥是项目内的调度角色：在某个迭代被唤醒后快速思考、决策、回应；需要查代码、改文件、写文档或长分析时，先说出理解，再创建任务并派给空闲 L3。辅助任务（Ask）要求当时有空闲 L3，直接进入执行中。沙箱正式任务有空闲 L3 则执行中，否则待指派，L3 空闲后主动回报二级。人类任务先待确认，被指派人拒绝或发起人取消后结束；确认后本人执行或下发其本项目本地执行器。创建人类任务时可引用本项目正式文件中的有效版本（最多 30 个），详情与本地执行器指令会带上这些引用。任务状态变更以及本地执行器汇报进度时，会在来源迭代中 @任务来源人。对本迭代锁定的任务具备全部安排能力。自己责任（目标是本 L2 / 已派 L3）的任务随时可安排；成员名下或其他非自己责任的任务，以及把任务指派给人类成员，必须有人类成员账号在本轮明确授权。三级只执行，结束前必须交活；成败都写入 `coordinator_events.child_result` 再唤醒二级。失败或卡住的 L3 由二级恢复；对人的任务重启回到待确认。可见正文就是群聊发言。L3 工具鉴权看自己的 execution run。有子 Agent 时二级 harness 不关，群消息仍可进入下一轮。

“梳理讨论”在输入框预填一条 @Agent助手 的请求，成员发送后按普通消息处理；兼容的 summary 接口也提交同样的提及消息。成员消息通过 `agent_requests` 唤醒 L2，L3 交活通过 `coordinator_events` 唤醒；可见发言按消息本身展示，不靠时间线位置推断隐藏内部帖。


### 会话上下文与压缩

每个迭代会话对应一个独立的 DSH 持久会话。容量按角色分层：二级调度长驻，默认 256,000 tokens、自动压缩约 70%（≈179K），避免拖到模型约 1M 硬顶才压、拖贵后续轮次；三级执行与一级维护是用完即结束的任务会话，保留满窗 1,000,000 tokens，以便单次任务或大批量文档整理顶得住。轻量按需参与仍只用极短截断上下文，不走上述预算。一级四类维护 Agent（成员发言、文档摘要、文档整理、迭代归档）各有一套项目级会话：启动维护任务前检查压力并自动压缩，监控页可手动排队压缩。三级每个执行任务各有一套会话：首次启动可从二级快照播种，之后只接收该任务的追加要求，不再灌入整段群聊。沙箱与轨迹也按任务隔离。已处理消息的位置与原生快照一起保存，新请求只追加尚未纳入的成员消息；原生助手输出与压缩摘要直接沿用，不再重复拼接最近 30 条聊天。即使助手选择沉默，该消息也保存到同一套上下文，参与判断使用原生会话投影。

输入框左上方展示二级上下文用量。监控页在一级维护卡片、二级迭代行展示用量、预警与手动压缩；三级在任务卡片的「聊天」弹窗中展示原生会话、用量与压缩。总量读取原生 token meter 的模型计量锚点与当前增量；组成占比使用该计量器的估算口径，分为系统指令、工具定义、成员讨论、助手回复、文件与工具结果、压缩摘要和待纳入消息。未读取的文档正文不计入上下文，组成估算不伪装成精确计费 token。

默认采用 DSH 原生压缩，将较早的内容替换为模型摘要；二级保留近期约 32K、一级约 64K，摘要输出上限 8192 tokens。启动请求前及执行步骤之间检查压力，达到会话阈值（约 70%）后自动压缩。二级手动入口为 POST /api/threads/:id/context/compact；一级四类维护会话为 POST /api/projects/:id/l1-context/compact；三级任务会话为 POST /api/threads/:id/replies/:messageId/context/compact。均按会话持久排队，当前任务结束后由后台工作器处理；失败可重试。压缩不删除群聊消息、执行记录、维护记录或文档，快照提交成功后才标记手动压缩完成。应用启动后会无模型调用地补齐旧快照的用量信息。
