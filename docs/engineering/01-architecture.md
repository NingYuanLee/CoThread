# 共序架构与运行边界

一次部署对应一家公司：服务独立运行，MySQL 与其他部署隔离。协作围绕项目、迭代和任务展开。项目中有两名 Agent 成员：老翁负责项目记忆（项目知识、成员认识、文档索引）；小祥参与讨论、协作与任务安排。Agent 不划分等级。小祥在不同迭代使用独立会话，可委派子 Agent 执行任务。子 Agent 与小祥使用相同的插件、工具清单和自定义 Skills，不另设配置对象，也不单独计为项目成员。本地执行器属于人类成员；Agent 不进入公司人类账号目录。

## 协作与存储

浏览器/成员本地 AI → 共序 HTTP/MCP → 鉴权业务服务 → MySQL。

数据库通用层只负责连接、查询计时、受限的读重试和事务，不解析业务 SQL 来触发额外写入。迭代列表使用 `threads.last_active_at` 排序：消息写入在原有迭代写事务中显式推进活跃时间；Agent 事件结束通过单条多表 UPDATE 同时保存结束状态和活跃时间。沙箱执行结束不能与 `threads` 写在同一条语句里，因为 `sandbox_runs` 触发器已经更新 `threads`；结束状态和活跃时间放在同一事务中，活跃时间取本次 `finished_at`。直接插入已完成事件时，两次写入共用事务。启动中断清理只推进本次受影响的迭代，不扫描“最近几秒”的记录。活跃时间使用 `GREATEST` 保持单调，附加更新时间失败时不得留下已提交的主写入。归档确认仍在同一条 `threads` UPDATE 里写入状态、快照和活跃时间。

工作台组件按实际状态归属组织：新建任务弹窗拥有表单草稿、提交锁和错误状态，父组件只传入项目、迭代、初始引用及关闭/创建完成回调。切换上下文或重新打开会重建草稿；创建成功与列表刷新失败分别反馈，避免刷新失败被误解为创建失败。

Service 按访问控制、成员、项目、迭代、消息与监控拆分领域模块；任务池按查询、命令、指派、调度、恢复与执行生命周期拆分，公开入口保留兼容委派。领域模块不得反向依赖兼容入口，架构门禁检查依赖方向与循环。工作台的账号、项目任务列表和会话引用分别使用独立状态资源；监控数据加载、状态推导与各类弹窗独立。沙箱持久引用记录 provider 身份，恢复与回收沿用原 provider。模块边界以本文件为准。

MySQL 保存账号、项目、成员、迭代讨论、文档原始字节、不可覆盖的版本、审核、归档、任务状态、工具事件与 Agent 会话快照。文档每文件上限 20 MiB（MCP 单次工具参数约 10KB，更大文件必须分片），保存 SHA-256 校验值。文档在右侧文件浏览器中查看；对话里的引用和文档链接会展开该侧栏。可搜索、切换版本、预览、下载和引用。文件树支持多级文件夹和整理操作；默认文件夹优先，然后按扩展名、名称（中文拼音/字母）排序，也支持最近修改排序。新版本、重命名和移动更新文档修改时间。删除文档为可恢复的软删除，旧版本引用仍可读取；只允许删除空文件夹。回收站可由项目成员永久清空：未被消息或任务引用的文件会从数据库删除；仍被引用的版本保留内容供历史查看，但不能再恢复到文件树。Agent 与 MCP 不能清空回收站。

消息引用精确版本。写消息、提交版本、审核、任务变更及归档先锁定迭代，避免归档边界遗漏。上传和 Agent 发布均不代表人工通过；Agent 无权代替人类确认归档。仅迭代创建人或当前项目负责人能发起、撤回、重试及确认归档。迭代状态为进行中 → 归档中 → 已归档；存在运行中任务、助手、执行器、工具或上下文同步时不能开始归档。进入归档中即冻结普通业务写入，待确认、待指派和未运行的阻塞任务由人类在归档方案中决定留档或交接；撤回后恢复进行中。最终确认才收口旧执行队列、落实任务去向并排队更新长期记忆。详见 [迭代归档与交接](02-iteration-archive.md)。

当前没有对象存储。执行工作区只放工作副本；已发布文件在 MySQL，不依赖工作区寿命。后续接入 OSS 时，保留版本 ID、权限和哈希，将文件字节迁移至私有 Bucket；访问仍需应用鉴权，不能使用公共读作为权限替代。

## DSH Agent 与执行环境

模型配置存在数据库记录时只读 `platform_model_settings`：默认一条路由同时服务老翁、小祥和子 Agent，老翁可以单独覆盖。没有记录时才回退到环境变量，此时老翁仍看 `KNOWLEDGE_MODEL_*`，小祥与子 Agent 共用 `MODEL_*`。`EXECUTOR_MODEL_*` 只在没有数据库记录、也没有 `MODEL_*` 时作为迁移兼容。管理空间保存前会做普通 Responses、流式和老翁结构化探测，三项都成功才原子切换；失败、版本冲突或密钥无法解密都不会改用新配置，也不会在已有坏记录时退回环境变量。运行中的任务和它的子任务保持启动时捕获的模型，空闲会话在切换后关闭；同迭代仍有子任务时，新请求保持排队，子任务结束后重建会话并使用新配置。用量记录写入当时的模型名、推理强度和配置版本，之后的切换不能改写这条身份。代码和库存只使用 laoweng、xiaoxiang、child_agent。旧的 l1、l2、l3、dsh_l3 由迁移改写，管理页只在展示历史文本时翻译，不再作为第二套名字。

应用宿主机安装官方 DSH/SDK 0.2.0-rc.2，启动独立进程编排 Agent。老翁的成员发言、文档摘要、迭代归档、项目记忆按项目各维护独立 DSH 会话，同项目多次整理接续同一套上下文与轨迹；迭代归档同时总结该轮并更新项目长期记忆。小祥每个迭代一套上下文与轨迹。每个子 Agent 任务一套独立 DSH 会话，七个槽位只限制并发；监控里可打开该任务的原生会话并追加要求。模型可见工具严格限定为共序注入的能力。所有 Agent 固定使用 `.local/sandboxes` 下的本机工作区和 Git Bash，只有这一条执行路径，不做跨环境回退。

插件管理读取项目内的 DSH 注册表，并通过 DSH 官方 composition API 合成 `sdk-minimal + model patch + Agent patch + 动态 patch`，不把可执行插件或能力配置复制进业务数据库。管理空间只按老翁、小祥展示 `dsh-plugins`、`cothread-dsh-plugins` 和 `自定义skills`。小祥与子 Agent 共享同一套插件策略和工具清单。插件状态区分 `assembled`（生产 patch 组合结果中已装配，不是当前进程的实时加载状态）、`exposed`（该成员可见）和 `callable`（配置允许调用）。系统提示词可查看成员身份、任务身份、注入来源及变量注释。可执行插件与权限上限只能通过代码、依赖和 patch 发布；自定义 Skills 不能扩大能力边界。

未改造的 DSH 原生插件保留原包、原 ID 和原实现。共序修改过或新增的实现使用独立 `cothread-*` plugin ID，声明标准 `name`、`inject` 和 `apply` 导出，并通过 Cordis patch 装配；Tool 和 MCP 是这些插件暴露的能力，不再作为平行注册目录。

dsh-plugins 视图按老翁、小祥展示提示词变量注释。基础 patch 的 persona 保持为空；稳定成员身份和子 Agent 的任务身份由 `cothread-system-prompt` 按 Agent ID 注入，每轮 prompt 只提供项目、任务和动态上下文。自定义 Skills 由独立 Skill Provider 追加。`system` 变量用于系统提示词，`task` 变量用于本次任务资料，`runtime` 变量用于识别成员与任务会话；这些兼容字段不表示 Agent 等级。

数据库只保存超级管理员添加的纯提示词自定义 Skills、不可变版本和审计记录，初始化时没有 Skill 数据。Skills 按老翁、小祥配置，可新建、编辑、启停和归档；小祥与子 Agent 加载相同的已启用 Skills。历史 `child_agent` Skills 与 `xiaoxiang` Skills 合并读取，新建和编辑统一保存到小祥配置，历史版本保留。Skills 不能携带代码、模块路径或自定义 MCP 地址。工具共享不扩大业务授权：成员权限、Chat 只读限制、项目与迭代范围、任务归属、人类审批继续在后端执行。子 Agent 的任务管理操作检查当前绑定执行记录，不继承唤醒小祥的人类授权。

本机执行器只限制文件接口的工作目录，并清除子进程中的数据库和服务密钥。命令本身仍以当前操作系统账号运行，可以访问该账号有权访问的其他资源，不具备容器或虚拟机级安全边界，只用于受信任的本地开发任务。

私有回环桥接接口使用每任务随机令牌；DSH 子进程只接收必要模型凭据与桥接配置，不继承 MySQL 或沙箱服务密钥。工具环境不注入这些密钥。迭代使用独立工作区，工作区按需创建；没有工作副本永久保存的保证。

单次沙箱命令最长 90 秒，输出有长度限制。工具过程、实际输入输出与执行进度入库，界面支持展开查看和停止。停止不能撤销已经完成的外部操作或已保存版本。发布依据消息、文档和内容哈希去重；失败重试前仍需检查已生成成果。

小祥与子 Agent 另有受限的 `capture_preview_screenshot` 视觉验收工具，只能渲染当前项目文档树、项目文档版本预览和当前子 Agent 沙箱中的 HTML，不接触宿主机屏幕或任意外部 URL。涉及 HTML、网页或可视化产物时，截图是完成验收的必要证据，不能用命令退出码、源代码或数据库状态替代。老翁的文档整理已于 2026-10-25 下线，这条「改完目录再截图复核」的路径随之停用。运行截图需要 `npm run setup:preview-browser` 安装 Chromium。
截图同时作为模型图片输入和受项目权限保护的内部视觉附件保存，因此老翁、小祥与子 Agent 的轨迹和子 Agent 会话可以直接预览同一张截图，不把完整 Base64 写入事件日志。若当前模型不支持图片输入，可将对应的 `KNOWLEDGE_MODEL_VISION`、`COORDINATOR_MODEL_VISION` 或 `EXECUTOR_MODEL_VISION` 设为 `false`；此时视觉验收会返回 `model_no_image_input` 并明确跳过，不会伪造通过。

小祥一轮结束后停住进程内 AgentTeam：有在跑的子 Agent 时保持 harness，空闲 5 分钟且无子 Agent 后才关闭并把会话目录压缩进 MySQL（上限 10 MiB）。下次恢复缓存再运行。该 SDK 同名 session 默认走 create，dsh-layer/sdk-resume.mjs 对固定版本 SDK 做显式 resume 适配。升级依赖必须重新验证该适配。异常关闭可能丢失本轮尚未写入的会话快照，但已提交文档和工具记录仍在数据库。运行中的子 Agent 在应用重启后标记中断，写入 `coordinator_events.child_result` 唤醒小祥重新评估，不自动重放。

六段提示词与请求控制的改造契约见 [Agent 提示词与请求上下文](11-agent-prompt-context.md)。该文档区分已接入的工作区原型、目标行为和验收要求；静态系统提示词查看不等于实际调用预览，文件存在不代表功能已发布。

## 部署和备份

本机官方 MySQL 8.4.9 监听 127.0.0.1:3307，数据在 .local/mysql-data，不能当作临时缓存删除。完整备份需包含 versions.content、agent_sessions.checkpoint 和工具事件。

npm run db:backup 导出完整数据库，只保留最新一份 `cothread-*.sql`，并清掉半截 `.partial`；`mysql-all-before-binlog-clean*` 这类手工快照不动。npm run db:restore-check 只恢复最新一份 `cothread-*.sql`，在随机独立数据库中比较业务表数量、文件 SHA-256 和会话快照哈希，再清理演练库。npm test 使用 `TEST_DATABASE_HOST_*` + `TEST_DATABASE_AUTH`（或遗留 `TEST_DATABASE_URL` / `DATABASE_URL`），但禁止清库日常开发库 `cothread` / `cothread_dev`；测试持有命名锁后清空表并重新迁移，绝不能使用生产库或日常开发库。本机可在同一台 3307 上另开 `cothread_test`。

云迁移应先导入数据库，再配置 `DATABASE_HOST_*` / `DATABASE_AUTH`（或修改遗留 `DATABASE_URL`）。数据库 TLS 验证证书；公网入口需 HTTPS。应用缓存目录应可写。当前仅支持单服务实例，扩容前需要独立队列和任务租约。

## 实际验收

Agent 在当前运行环境的沙箱中创建求和脚本、执行断言、保存 v1；后续读取并修改脚本，执行五项测试并保存同一文档的 v2。回收旧沙箱并移开宿主 Agent 缓存后，仍能从 MySQL 恢复 v2，在新沙箱运行五项测试，退出码 0。会话恢复适配后，新轮事件已进入更新后的 MySQL 快照。

文档库在浏览器窄窗口验证可打开并预览脚本。Markdown 不渲染原始 HTML，禁用外部图片；文本/代码、图片、PDF 与 Office（Word / Excel / PowerPoint）可预览，其余格式下载查看。目前不含文件在线编辑、对象存储、任务多实例调度。

# 项目文档库

文档绑定在项目下，项目内全部迭代共享同一套文档库。右侧文件浏览器以单树展示三个区：

- **对话缓存**：只接受对话框上传或 MCP `post_message` 的 files。按 Asia/Shanghai 自然日进入 `对话缓存/YYYY-MM-DD`。内容对 Agent 只读；Agent 不能往缓存区新增。人工可重命名、软删除、恢复、审核、引用和下载。
- **沙箱产物**：主要由云端 Agent 在沙箱中生成、编辑并发布（含从别处下载后保存到此，以及按对话缓存修改后的结果）。人工不能把对话附件丢进沙箱产物区；可重命名、软删除、恢复、审核、引用和下载。
- **正式文件**：已确认的缓存/产物可另存至此，或人类在正式文件区手动上传。正式文件不分版本叠加，不走「需要修改」。

消息可引用本项目文档库中的有效版本。点「需要修改」必须填写意见，确认后以人类消息发到**当前迭代**群聊：沙箱产物 @小祥；对话缓存若不是本人上传则 @来源人，本人上传的对话缓存则 @小祥。单文件最多 20 MiB，每条消息最多引用 30 个文件。仍兼容历史上按迭代隔离的 cache/outputs 目录，展示时归入对应项目区。

登录用户只能通过对话框或 MCP 的 `upload_cache_draft` 上传需要随消息发送的对话缓存；MCP 的 `upload_official_file` 独立对应用户手动上传正式文件，但其返回版本仍可被消息引用。任务生成的文件默认进入沙箱产物。

「正式文件整理」已于 2026-10-25 下线：入口返回 410，调度链移除，正式文件区不再因整理而锁定。「迭代归档」复用老翁原有的 `iteration_archive` 持久会话：先基于冻结的讨论、引用版本和任务快照生成归档与交接草案；人类批准后，才完成归档、可选创建承接迭代并更新项目长期总结。留档任务保持真实状态，交接任务保持 ID、产物和执行历史，原迭代保留冻结时的任务与处置记录。文档库本身不随归档消失。

上传成功后点击附件叉号，会将上传文件移入文档回收站；对已有项目文件点击叉号仅取消引用。上传过程中点击叉号会在保存请求完成后回收文件，避免中止网络请求后遗留不可见附件。发送后的文件继续保留在文档库。

### Agent 成员与按需参与

小祥不是公司目录里的人类账号，也不会写入 `users` 表。老翁与小祥作为项目 Agent 成员出现在项目管理中。老翁只维护项目记忆，不进入会话，也不出现在 @ 候选。问老翁是只读私聊，工具名单里不再有 search_knowledge。@ 候选只露出进会话的对外身份小祥。小祥是项目内同一调度角色，各迭代使用独立 DSH 会话；监控页按迭代展示这些会话与 7 个固定人设槽（槽位归属人设，不归属单个会话），但不把小祥或子 Agent 按会话拆成多名项目成员。每条登录成员发言都会排入持久任务：明确 @小祥，或句首「小祥，」，或发言时项目中只有该成员与助手时，直接回复；多人项目中没有点名时先请求模型判断是否参与，模型可选择沉默。正文明确 @ 了除小祥以外的人、且没有同时点名小祥时，不请求模型，也不写「正在斟酌是否参与」，直接保持沉默。同一条里只要也 @ 了小祥，仍在收消息时进入完整调度，不走这条忽略。群聊不能再选已下线的有问必答。按需参与像人类编辑回复：先起草一句对当前讨论的整合理解，发出前若又有新消息则改稿或改为不发；一段连发只落一条可见回复，并吸收其间的待判消息（含此前被判沉默、仍未被回复的连发）。硬规则必回：催沉默/不说话、同内容连发满 3 次、以及紧跟小祥发言的短点评（夸快/感谢/追问，不含「好的/收到」纯确认）。句首「小祥，」在收消息时已经进入完整模式，不再走这层轻量判断。要写文档、总结、改代码、派任务，或催开工时，轻量路径仍先让模型写一句短回复，提示词不提 @ 和完整模式。这句先不发到群里。实活、催开工，或草稿已经在许诺时，直接换成「需要麻烦你再@小祥，我才会真的开始。」，不再把许诺和提醒叠在一起。规则没有判定要提醒时，不再为拿不准另调一次模型。轻量路径不因此升级完整调度。硬规则可沉默：纯确认、冷却期内闲聊。模型口头承诺「每条都回」不作数。轻量判断不走完整调度会话，但仍把模型用量、用时写入 `assistant_replies.usage_stats`，并落 `participation_judge` / `assistant_final` 到小祥轨迹。轻量判断先看最近 12 条。正文合计超过 4000 字就逐条丢掉最旧的一条再量，直到只剩最新一条；这一条仍超过 4000 字才不再调用模型，直接沉默；点名、催沉默、连发和短跟帖仍用短句模板，不把过长正文交给模型。未超限时全文进入判断，不再按条截断。输出上限约 768 tokens。约 60 秒冷却可被上述必回规则打断。人类成员数量按项目 `members` 表计算，不把老翁、小祥和子 Agent 算作人类，也不按发言人数或在线人数计算。沉默只保存任务状态，不生成聊天消息或启动执行沙箱；本地 AI 或 Agent 自身发言不会触发循环。

小祥是项目内的调度角色：在某个迭代被唤醒后快速思考、决策、回应；需要查代码、改文件、写文档或长分析时，先说出理解，再创建任务并派给空闲子 Agent。辅助任务（Ask）要求当时有空闲子 Agent，直接进入执行中。沙箱正式任务有空闲子 Agent 则执行中，否则待指派，子 Agent 空闲后主动回报小祥。人类任务先待确认，被指派人拒绝或发起人取消后结束；确认后本人执行或下发其本项目本地执行器。创建人类任务时可引用本项目正式文件中的有效版本（最多 30 个），详情与本地执行器指令会带上这些引用。任务状态变更以及本地执行器汇报进度时，会在来源迭代中 @任务来源人。对本迭代锁定的任务具备全部安排能力。自己责任（目标是本小祥 / 已派子 Agent）的任务随时可安排；成员名下或其他非自己责任的任务，以及把任务指派给人类成员，必须有人类成员账号在本轮明确授权。子 Agent 按绑定任务工作，结束前必须交活；成败都写入 `coordinator_events.child_result` 再唤醒小祥。失败或卡住的子 Agent 由小祥恢复；对人的任务重启回到待确认。可见正文就是群聊发言。子 Agent 工具鉴权看自己的 execution run。有子 Agent 时小祥 harness 不关，群消息仍可进入下一轮。

子 Agent 的 7 个人设（大娃～七娃，key 为 p1～p7）是持久身份，定义在 shared/agent-personas.js；会话不是持久身份，每次派发都新建一个 DSH 子会话（UUID，写入 agent_task_execution_runs.executor_id）。任务和运行记录各存一列 persona，监控与昵称按人设归属；同一个人设可以并行多个会话（多个任务），互不共享上下文。旧数据没有 persona 时按执行会话首次出现顺序回退到人设。人设目前只有名字、没有功能性内容，默认全部由大娃（p1）执行；create_task.persona 仅用于将来需要区分时显式指定。小祥仍遵守相关性规则：与进行中/等待中任务会改同一文件、同一模块或做同一件事的任务不要并行。

「梳理讨论」快捷语与 summary 接口已于 2026-10-25 下线，讨论改由老翁自动沉淀为讨论记忆，不再通过 @小祥 触发。成员消息通过 `agent_requests` 唤醒小祥，子 Agent 交活通过 `coordinator_events` 唤醒；可见发言按消息本身展示，不靠时间线位置推断隐藏内部帖。发消息时记录本次请求的 `dialogue_mode`：`default` 走按需参与；`chat` 强制回复且只读工具；`miniprogram` 约束为仅小程序，`cloudbase` 联动 CloudBase 侧栏与 steering。模式在浏览器按迭代记忆，每条请求保存自己的模式；执行来源贯穿子任务的改造边界见上述提示词契约。

### 会话上下文与压缩

每个迭代会话对应一个独立的 DSH 持久会话。容量按会话用途设置：小祥调度长驻，默认 256,000 tokens、自动压缩约 70%（≈179K），避免拖到模型约 1M 硬顶才压、拖贵后续轮次；子 Agent 执行与老翁维护是用完即结束的任务会话，保留满窗 1,000,000 tokens，以便单次任务或大批量文档摘要顶得住。轻量按需参与不走上述预算：最近最多 12 条，正文合计超过 4000 字就从最旧逐条丢掉；只剩最新一条仍超限则直接沉默，硬规则仍用短句模板。未超限时全文进入判断，不再按条截断。老翁四类维护 Agent（成员发言、文档摘要、迭代归档、项目记忆）各有一套项目级会话：启动维护任务前检查压力并自动压缩，监控页可手动排队压缩。每个子 Agent 任务各有一套会话：首次启动可从小祥快照播种，之后只接收该任务的追加要求，不再灌入整段群聊。沙箱与轨迹也按任务隔离。已处理消息的位置与原生快照一起保存，新请求只追加尚未纳入的成员消息；原生助手输出与压缩摘要直接沿用，不再重复拼接最近 30 条聊天。即使助手选择沉默，该消息也保存到同一套上下文，参与判断使用原生会话投影。

输入框左上方展示小祥上下文用量。小祥监控跟随工作空间左侧选中的迭代：上方整行列出已建但尚未绑定子 Agent 的待派发任务，下方左栏是 7 个子 Agent 槽位、右栏是该槽位当前绑定的任务（任务转派后只出现在最新执行者的槽位）。弹窗内不再切换迭代、不展示模型路由；子 Agent 在任务卡片的「聊天」弹窗中展示原生会话、用量与压缩。总量读取原生 token meter 的模型计量锚点与当前增量；组成占比使用该计量器的估算口径，分为系统指令、工具定义、成员讨论、助手回复、文件与工具结果、压缩摘要和待纳入消息。未读取的文档正文不计入上下文，组成估算不伪装成精确计费 token。

默认采用 DSH 原生压缩，将较早的内容替换为模型摘要；小祥保留近期约 32K、老翁约 64K，摘要输出上限 8192 tokens。启动请求前及执行步骤之间检查压力，达到会话阈值（约 70%）后自动压缩。小祥手动入口为 POST /api/threads/:id/context/compact；老翁五类维护会话为 POST /api/projects/:id/laoweng-context/compact；子 Agent 任务会话为 POST /api/threads/:id/replies/:messageId/context/compact。均按会话持久排队，当前任务结束后由后台工作器处理；失败可重试。压缩不删除群聊消息、执行记录、维护记录或文档，快照提交成功后才标记手动压缩完成。应用启动后会无模型调用地补齐旧快照的用量信息。
