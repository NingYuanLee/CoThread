# 全局操作提示

`web/main.tsx` 中的 `TipHost` 统一承接登录页、工作区和管理页的操作结果。提示固定在右上角，旧提示在上、新提示在下，间距 10px。每条按内容自然收窄并右对齐，最大宽度 340px，窄屏最多占视口宽度减去 36px。容器不设滚动条，避免退场动画产生临时滚动条。关闭时向右渐隐，同时收起占位，下方提示平滑上移。不会按数量裁掉尚未关闭的提示。

```tsx
import { showTip, dismissTip } from "./Tip";

showTip("已保存"); // success，默认 1800ms
showTip("正在处理", "info"); // 默认 2800ms
showTip("上传失败，请重试", "error"); // 保留到手动关闭，默认可复制报错
const id = showTip("请先检查配置", { kind: "warning", duration: 0 });
if (id !== undefined) dismissTip(id);
```

提示为单行玻璃质感，无左侧色条和类型标题；长文本省略显示，悬停可看全文。图标统一使用 Lucide，`success`、`error`、`warning`、`info` 分别使用绿色、红色、黄色、蓝色。成功提示默认 1800ms，错误默认仅手动关闭，警告默认 3000ms，信息默认 2800ms；`duration` 单位为毫秒，`0` 表示仅手动关闭。每条均提供关闭按钮，主动调用 `dismissTip` 也使用相同退场效果。系统启用减少动态效果时立即移除。

## 可撤销的延迟指令

```tsx
import { showDelayedTip } from "./Tip";

showDelayedTip("即将移入回收站", {
  delay: 5000,
  onExecute: () => api(`/files/${file.id}/trash`, {}, "POST"),
});
```

延迟指令到倒计时结束才调用 `onExecute`，并非先执行再恢复。`delay` 单位为毫秒，默认 5000。倒计时期间提示保持显示，并提供醒目的“撤销”文字按钮；撤销、关闭或 `dismissTip(id)` 都会取消待执行的指令。宿主卸载也取消所有等待中的指令。开始执行后显示“执行中”并锁定撤销和关闭，完成后退场；执行失败则显示需要手动关闭的错误提示。每条指令独立计时，仅执行一次。执行函数中应再次检查业务权限和目标有效性。

已有组件需要保留错误状态用于加载、禁用等逻辑时，可使用 `useTipError()` 替代 `useState("")`。`setError(非空消息)` 发送全局错误提示，并保留内容区错误；`setError("")` 仅清除组件状态。支持 `useTipError({ duration: 0 })`。该 Hook 会保留错误状态，内容区的错误提示应继续渲染；不要再为同一错误额外调用 `showTip`。查询、后台轮询和预览读取失败同样调用 `setError`，浮动提示与内容区错误同时出现。同一组件在提示仍显示时重复收到相同错误会去重。第三个返回值 `setInlineError` 只更新内容区、不产生浮动提示，用于登录页承接已有 notice 这类非请求失败文案。

字段验证、附件失败标记、文档解析失败占位、启动失败重试和任务的持久失败详情仍属于对应内容本身，在原位置展示。临时操作结果通过全局提示展示。

提示通过稳定的 portal 容器挂载到当前原生模态框内，并使用手动 popover 保持在顶层，避免模态框使关闭按钮不可交互。入场动画通过 Web Animations API 在每条提示创建时仅执行一次，关闭弹窗、迁移提示容器或重新显示 popover 时不会重播，避免提示闪烁；关闭提示时取消仍在运行的入场动画并执行退场动画。新增提示不会获取焦点；底层页面的非提示区域仍可正常操作。

## 复制提示文本

错误提示默认提供复制图标，点击复制完整错误文本（不会复制省略号截断的内容），成功后短暂显示对勾。复制失败时按钮会提示重试，原提示仍保留。`copyText: false` 可隐藏按钮；其他类型可用 `copyText: true` 开启复制。也可用字符串传入与显示摘要不同的完整信息：

```tsx
showTip("请求失败，请复制详情协助排查", {
  kind: "error",
  copyText: "完整错误信息\n请求编号：request-123",
});
```

同一条错误、同一类型且该提示仍在显示时，无论由几个组件上报都只保留一张卡片，后到的调用直接复用已在显示的那条；换类型（例如 error 改成 warning）才会新增。

## 多行文本提示

通过 `multiline: true` 开启多行展示，保留原始换行并自动折行，完整显示文本，不使用单行省略。多行文本默认带复制按钮，复制完整内容。宽度上限、堆叠动画和按类型设置的默认停留时间保持一致，可显式设置 `duration: 0` 等待手动关闭。

```tsx
showTip("第一行说明\n第二行完整内容", {
  kind: "info",
  multiline: true,
  duration: 0,
});
```

## 内容区与空列表

请求失败、操作失败、查询和后台轮询失败统一只通过右上角浮动错误提示呈现，不再在内容区另画一条红色错误条：同一条失败出现两遍会让用户分不清哪条是新的，也会在模态框和页头把版面顶开。组件里的 `error` 状态继续保留，用于加载、空态和按钮禁用等判断，只是不再渲染成红块。

以下内容仍留在原位置，不属于“重复的错误提醒”：字段校验与必填提示、验证码错误、登录页 `auth-notice`、带“重新加载”入口的持久失败详情、附件上传失败的角标、文档解析失败占位，以及上下文压缩结果这类状态说明。

列表查询正常返回 `[]` 或 `{ items: [] }` 是成功的空结果，只渲染“暂无数据”或“没有符合筛选条件的内容”，不调用 `showTip` 或 `setError`，也不把空数组转成错误。查询接口报错调用 `setError`，只弹浮动提示。

## 位置与批量关闭

提示区域默认距离页面顶部 72px，右侧留白 18px，并适配安全区域。当仍显示的仅手动关闭提示超过 6 条（从第 7 条起）时，“全部关闭”独立悬浮在提示堆叠上方，不占位、不推动提示。自动消失提示、正在退场提示以及延迟执行提示不计入此阈值。

点击“全部关闭”会让当前可关闭提示统一向右渐隐，并取消仍在倒计时的延迟指令；已经执行中的指令继续保留直到完成，避免暗示已经取消了正在执行的操作。也可调用 `dismissAllTips()` 批量关闭。内容区状态不受影响。
