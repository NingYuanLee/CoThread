# 主题系统

界面主题色的唯一真源是 `web/theme-palette.css`，其余产物均由脚本生成。手工编辑生成文件会在下次生成时被覆盖，历史上因"改调色板却没重新生成"导致过所有边框与背景色消失的故障。

## 文件分层

| 文件                         | 是否生成 | 作用                                                                       |
| ---------------------------- | -------- | -------------------------------------------------------------------------- |
| `web/theme-palette.css`      | 否       | 572 个基准色（forest 配色），所有主题的色相来源                            |
| `web/theme.css`              | 是       | 6 个主题 × 572 个 `--c-*` token                                            |
| `web/theme-overrides.css`    | 否       | 深色主题微调层：表面阶梯、边框提亮、文字提亮、状态语义色、强调色、危险按钮 |
| `web/theme-fallback-map.css` | 是       | 为只在 `var(--c-xxx, 字面量)` 回退位出现、从未定义的 token 生成深色等效值  |

`web/main.tsx` 的引入顺序固定为 `theme.css` → `style.css` → `theme-overrides.css` → `theme-fallback-map.css`，保证覆盖层晚于基础样式生效。

业务样式（`web/workspace.css`、`web/style.css` 等）只写组件规则，**不要把调色板或覆盖层里的 `--c-*` 块复制进去**。业务样式派生的 chunk（如 `workspace.css`）在 `theme-overrides.css` 之后加载，重复定义会反压深色阶梯：暗夜曾因 `workspace.css` 混入两份调色板副本，卡片被压回 `#0c0d0d`、面板 `#0e0f10`，比页面底 `#17181a` 还黑。2026-10-28 已删除这些副本（共 6,191 行），主题 token 只留在 `theme.css` / `theme-overrides.css` / `theme-fallback-map.css` 三处。

## 改主题的流程

1. 调基础配色：改 `web/theme-palette.css` → `npm run theme`
2. 调深色表现：直接改 `web/theme-overrides.css`（不会被生成覆盖）
3. 业务 CSS 新增了回退 token：`npm run theme:fallback`

## 主题清单

`shared/ui-theme.js` 的 `UI_THEMES` 与 `scripts/generate-ui-themes.mjs` 的 `recipes` 必须一致，否则选择器里会出现点了没效果的主题：

forest（松风）、tech（靛蓝）、dusk（暮紫）、sand（暖沙）、ink（墨玉，深色）、night（暗夜黑，深色）。

## 门禁

`npm run lint` 末尾的 `scripts/check-theme-generated.mjs` 会把 `theme.css` 与 `theme-fallback-map.css` 重新生成到临时文件并逐字节比对，不一致直接报错并提示应运行的命令。生成器支持 `THEME_OUT` / `THEME_FALLBACK_OUT` 环境变量覆盖输出路径，校验过程不会改动仓库文件。

### 交互三态（按钮 / 卡片 / 列表项）

| 状态 | 底色 | 适用 |
| --- | --- | --- |
| 默认 | 所在层的表面色 | 画布上的卡片 `#1b1b1c`；面板内的行 = 透明（即面板色）；芯片类（项目页签）默认抬一档 `#232324` |
| 悬停 | `#353638` | 侧栏 / 顶栏图标按钮、列表行、卡片、选择器、菜单项统一用它 |
| 按下 | `#43454a`（中性） / `#2563eb`（项目页签） / `#1e40af`（其它蓝底） | 中性按钮与可选行再深一档；顶栏项目页签选中是 `#2563eb`，按下保持**同一个**蓝色；引用块、管理空间入口、问老翁按下压到 `#1e40af`（更深 `#172554`） |
| 选中 | `#43454a` + 描边 `#61666b` | 列表行、卡片、选项；已选中再悬停仍保持 `#43454a` |
| 强调选中 | 蓝色阶 `#2563eb`（字 `#e5f0ff`） | 项目页签、开关等有语义的选中态，不并入中性选中 |

四档单调递增（`#1b1b1c` → `#353638` → `#43454a`）。**悬停必须明显亮于所在表面**：悬浮层是 `#2c2c2e`，所以悬停色不能只比面板高一档，否则在弹窗里看不出来。

实现要点：

- 具体选择器集中在 `web/theme-overrides.css` 第 9 节；不要给单个组件另造 hover / 选中色。
- 夜间被 `:hover` / `:active` 复用的令牌（`--c-e9eee5`、`--c-eef2ea`、`--c-f4f7f2`、`--c-edf3e7`、`--c-dfe8d8`）统一映射到 `#353638`，这是「悬停」唯一的来源（约 40 处交互规则引用，静态复用仅约 10 处）。
- 选中态用 `--state-selected`（`#43454a`）与 `--state-selected-stroke`（`#61666b`）两个变量，避免各组件再引用基础表面令牌（那样会让选中和默认同色）。
- **强调态的按下不能落回中性档**：选中/底色是蓝色的元素，`:active` 必须留在蓝色阶。顶栏项目页签按下保持选中色 `#2563eb`（用户明确要求按下与选中一致）；其余蓝底控件（引用块、管理空间入口、问老翁、主按钮）压到 `#1e40af`，更深的底用 `#172554`。这条用 `!important` 压过中性按下规则，是有意为之；新增蓝底控件时记得一起补 `:active`。
- **div 包 button 的结构要防「内层按钮盖住外层底色」**：项目页签是 `.project-tab`（div，负责底色）+ `.project-tab-name`（button）两层。内层按钮必须用 `background: transparent !important` 保持透明，否则中性按下规则（`button:active → #43454a`）会把内层刷成灰色，选中的蓝色就看不见了。同类结构（行内可选按钮）新建时按这个处理。

### 使用规则

1. 底色、文字、图标、边框只从灰阶取；强调只从蓝色阶取；语义色只从绿 / 橙 / 红阶取。
2. 边框用实色档位（`#353638` / `#43454a` / `#61666b`），**不要**用 `color-mix(... transparent)`，否则会产生色阶外的中间色。
3. 代码 / JSON 语法色同样走色板：key 蓝、string 绿、number 橙、literal 红、comment 灰。
4. 新增色相（例如紫色）必须先补一份色阶、加进生成器的色相分派，再到覆盖层接角色；不能先手写。
5. 手调位置：表面 / 文字 / 语义 / 强调 → `web/theme-overrides.css`；浮层玻璃变量 → `web/overlays.css`（`check-overlays` 强制）；回退 token → `scripts/generate-theme-fallback-map.mjs`（夜间三档固定 `#cfd3d6` / `#43454a` / `#232324`）。
6. 墨玉与四个浅色主题不受这套色板约束，仍按各自调色板生成。
7. 文档预览区：容器与「未加载 / 无法预览」占位（`.doc-browser-preview`、docx/xlsx/pptx/pdf 的衬底、HTML 预览视口、截图预览底）统一 `#1b1b1c`；docx 页、pdf 页、幻灯片这些「纸面」保持白色，那是文档自身的颜色。见 `theme-overrides.css` 第 10 节。
8. 右侧文档库页签条用最深档 `#0f1115`（比面板更暗，把页签行压成一条「槽」），活动页签与内容区跟左侧栏一致用 `#1b1b1c`；默认页签透明、悬停 `#232324`、页签文字默认 `#adb2b8`、悬停/选中 `#e9ecf2`；页签之间的竖线与全局描边/发丝线同色 `#43454a`。见 `theme-overrides.css` 第 11 节。
9. 顶栏项目页签里的项目标识（`.project-mark`）完全对齐左侧栏「项目管理」图标：底色 `#353638`（`--c-e9eee5`）+ 图标/字母 `#cfd3d6`；选中页签是蓝底，标识字跟着页签字走 `#e5f0ff`。见 `theme-overrides.css` 第 12 节。
10. 左侧栏右缘加 1px 发丝线 `#43454a`（与全局描边同色）。注意 `.sidebar` 是 `overflow:hidden`，原来的 `::after` 半像素描边画在右边缘外侧会被裁掉、实际不可见，所以这里直接给真实 `border-right` 上色。见 `theme-overrides.css` 第 13 节。
11. 层叠顺序固定为四级：画布 `#151517` → 面板 / 页面左侧栏 `#1b1b1c` → 悬浮层（弹窗整体：顶栏 + 左侧菜单 + 内容，以及浮层面板、菜单）`#2c2c2e` → 输入类下拉（单选 / 多选）`#353638`。**弹窗内部只用一种底色**（顶栏、左菜单、内容都是 `#2c2c2e`），并且左菜单与内容之间**不画分隔线**，分区只靠留白；**下拉必须比它所在的弹窗亮一档**，否则浮在弹窗上看不出来。见 `theme-overrides.css` 第 14 节，弹窗标题用 `overlays.css` 的 `--overlay-header-bg`。
12. 任务列表 / 项目记忆里的内联多选下拉（任务状态、任务类型等 `.project-memory-subtype-options`）同样按"下拉"处理用 `#353638`。它原来取 `--c-fff`（= 面板色 `#1b1b1c`），和任务弹窗左侧列表 `#1b1b1c` **完全同色**，这是"下拉和左侧菜单分不出来"的直接原因。
13. 多选下拉里的复选框走蓝色阶：原生 `accent-color` 在暗夜设为 `#2563eb`。原规则取 `--c-5d8b55`，夜间被量化成中性灰 `#81858c`，勾选后看不出强调色。
14. 弹窗内文字统一用**正常正文色** `#e9ecf2`，不再按灰阶分档；**只有禁用态**才暗一档（`#81858c`），主按钮 / 危险按钮的禁用态保留自身白字。做法：在弹窗作用域（`[data-overlay="dialog-shell"]` / `dialog[data-overlay]`）内把文字 token 全部重声明为 `#e9ecf2`，再单独给 `:disabled` 和 `::placeholder` 指定 `#81858c`；浮动 label 单独一条 `!important` 覆盖原聚焦色。状态色（蓝/绿/琥珀/红）与 `--stroke` 描边不动。见 `theme-overrides.css` 第 15 节。
15. 输入框浮动 label 的遮线底色（`--field-mask`）在弹窗内改为 `#2c2c2e`。它默认取 `--c-fff`（面板色 `#1b1b1c`），label 骑在边框线上时会比弹窗背景暗一块；弹窗里输入框本身是透明的，所以遮线色应当等于弹窗底色。
16. 个人设置弹窗外层容器（`.workspace-settings`）底色统一成 `#2c2c2e`，否则内容区比同一弹窗的顶栏 / 左菜单 / 底栏深一档。该元素背景会被一个不可读的外部样式表覆盖，规则写在 `overlays.css` 里并用更高选择器权重 + `!important` 压住。
17. 项目记忆弹窗右列（`.project-memory-side`）同属弹窗内部，底色统一 `#2c2c2e` 并去掉与左内容之间的 1px 竖线，与其它弹窗保持同一处理。
18. 弹窗内的底栏与字段右侧小按钮（`.project-settings-footer`、`.profile-field-action`）也统一 `#2c2c2e`。检查口径：弹窗内部不应再出现 `#1b1b1c` 的页内底色（只允许控件/徽标用的 `#232324`、选中态的 `#43454a`、强调蓝与头像遮罩等语义色）。
