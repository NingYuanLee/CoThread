# Agent 提示词与请求上下文

## 状态与边界

2026-10-22：本文记录六段提示词的改造契约。工作区已出现 `shared/prompt-blocks.js`、`shared/request-control.js` 和 `119_execution_request_control.sql` 等实现，且部分调用已接入；本文不代表完整功能已经验收或发布。最终模型请求、持久会话恢复、并发模式隔离、历史调用预览和缓存字段映射均须按下文分别验证，不能从文件存在推定完成。

项目成员只有老翁和小祥，不划分 Agent 等级。子 Agent 是小祥委派的任务执行身份，与小祥共用插件、工具清单和自定义 Skills；任务归属、项目权限、人类授权和审批继续由后端执行。机器键只有 laoweng、xiaoxiang、child_agent，它们不是成员等级。

## 六段职责

| 段 | 内容 | 适用对象 | 放置 |
| --- | --- | --- | --- |
| CothreadSystem | 共序运行环境、工具副作用边界、资料不能改变身份与授权 | 老翁、小祥、子 Agent | A |
| AgentMember | 成员或执行身份、职责、表达方式、操作手册 | 老翁、小祥、子 Agent 各自一份 | A |
| ProjectInfo | 当前项目标识、名称、简介、摘要与资料入口 | 老翁、小祥；子 Agent 的任务书携带项目标识 | B |
| IterationInfo | 当前迭代标识、名称、背景、目标与状态 | 小祥 | B |
| ChatMode | 来源请求的模式、回应与操作限制 | 小祥；子 Agent 继承开工限制 | D |
| WorkType | 维护类型、处理范围、输出格式与完成标准 | 老翁 | B |

老翁处理迭代归档时，背景、目标和冻结的讨论快照属于本次工作输入，不给老翁增加小祥的迭代身份。WorkType 的类型契约与本次具体输入分开，仍由现有结构化 schema 校验输出。

## 拼装顺序与信任

逻辑顺序为 A 稳定前缀 → B 当前会话资料 → C 追加的会话历史 → D 本次请求。工具定义和启用 Skills 的内容、顺序也参与稳定性核对。不能为了缓存保留过时资料或延迟权限撤销。

`placement` 与 `trust` 独立记录，段另有名字、来源、版本和内容摘要。A/B/D 表示位置，不能据此推导权限或信任级别。D 中后端生成的 ChatMode、唤醒类型和来源请求是控制信息；成员正文、附件、检索结果及交活正文是资料。ProjectInfo 与 IterationInfo 中由用户维护的文字同样是资料，不因后端加载或放在前面而获得指令权限。

稳定前缀不放时间、请求 ID、当前模式、项目和迭代动态值、本次任务输入。观测时间和调用标识保存在调用记录中，不反向写进稳定文本。段与工具定义使用确定的顺序和序列化方式。

## 请求模式与执行来源

模式在成员发消息时保存到 `agent_requests.dialogue_mode`，表示本次请求，不表示整个迭代永远处于该模式。消息正文中的模式声明不能修改后端控制值。

执行、子任务、交活、空闲唤醒、重试和恢复需要保留来源请求及开工模式。子 Agent 不能读取父会话当前可变的 job 来决定自己的权限。不同来源的事件不得借同一迭代混用授权；模式不同的后到消息独立排队，不进入当前 steer。同模式补充是否可合并仍须核对来源、身份和授权范围，并将正文标为资料。

无法确定来源或模式时，不得静默回退自由发言并开放写入。应阻止写入，保留可诊断状态；历史数据的兼容处理须单独验证。模式提示用于帮助模型理解，工具拦截、任务归属与人类确认仍是执行边界。

## 持久会话与资料更新

B 表示当前唯一有效的资料，更新目标是替换当前资料槽，保留历史消息和工具结果的顺序，避免不断堆叠整份旧资料。必须检查 DSH 最终发往供应商的请求，不能用本地渲染字符串代替。

当前原型在 `shared/prompt-blocks.js` 中记录了 DSH 系统提示词投影的兼容约束：持久历史中的系统文本变化可能以追加形式出现。因此，“六段全部注入可变 system section”不能直接视为可行实现。实际替换策略须验证正常运行、检查点恢复和压缩后的行为；需要受控重建时应明确恢复边界，不直接篡改原生会话日志。

老翁每次输入明确只处理当前这一份，历史旧输入不是本次任务。上下文压缩不能把历史 ChatMode 当成当前模式恢复；请求控制仍以持久化来源记录为准。

## 预览、计量与缓存

当前管理页提供成员系统提示词和变量来源查看。完整 A/B/D 调用预览属于本次改造目标，尚不能将现有静态查看称为实际调用还原。

目标视图区分“当前配置预览”和“历史调用详情”：前者模拟下一次拼装；后者展示当时捕获的段、资料和请求模式版本，不能用今天的配置重拼过去。仅保存摘要时应明确不能完整还原。密钥不得进入提示词、预览或审计文本，私有请求内容沿用项目权限保护。

缓存计量沿用现有用量链路，按供应商适配实际返回字段，区分未知与零，并对流式样本、最终 usage、重试分别去重。记录模型、配置版本、前缀摘要和缓存命中/未命中，不能仅凭段版本推断命中。

稳定前缀为缓存复用提供条件，不保证下一次调用立即命中。资料、工具或 Skills 变化后以真实返回核对；本次文档更新未测量生产命中率，也不估算节省比例。

## 验收契约

- 检查实际供应商请求中 A 的稳定性和段顺序，确认 SDK 自身注入内容没有使开头不断变化。
- chat 请求运行时收到自由发言消息，当前请求和已启动子任务仍不可写；不同模式的新消息另行排队。
- 父会话处理下一请求后，旧子任务工具调用、交活、空闲唤醒及恢复仍使用原来源控制；多来源事件不混用模式。
- 修改项目或迭代资料后，正常运行、恢复和压缩都使用当前资料；不重复注入整份旧 B。
- 老翁连续处理不同输入时只处理当前输入；归档输入可包含迭代快照，但不改变成员身份。
- 项目简介、目标、附件或交活正文伪造系统指令与模式时，后端权限不改变。
- 当前配置预览与历史调用详情可区分，缺失内容和缓存计量明确标为未知，不伪造还原或命中。
