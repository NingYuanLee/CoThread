# 项目记忆可用性评估

评估日期：2026-10-25。范围：五类记忆（发言 / 文档 / 任务 / 讨论 / 项目整体）的写入、召回、管理与界面呈现。

## 1. 结论

| 结论                     | 说明                                                                                                                    |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| **无阻塞**               | 模型无关的写入、召回、管理、关系与界面逻辑均有自动化证据，构建通过。                                                    |
| **可用（模型无关闭环）** | 建项目 → 邀请成员 → 发言 → 讨论记忆 → 记忆列表/作业面板 → 口径调整/回滚 → 失败重试拒绝规则，真实 HTTP 走查 16/16 通过。 |
| **待验（依模型）**       | 发言记忆、任务记忆、项目整体记忆的结算写入与「问老翁」召回依赖老翁模型；当前环境无模型，未实机跑通生成质量。            |
| **未实机验（界面）**     | 无浏览器验证通道，面板与详情只做了类型检查 + 构建 + 代码走查，未做点击级验证。                                          |

## 2. 走查方法与证据

1. **真实 HTTP 走查**（临时脚本，连测试库建真实服务）：负责人/成员登录 → 创建项目 → 邀请成员 → 创建迭代 → 双方发言 → 讨论记忆补跑 → 读取记忆 → 作业面板 → 改口径 → 回滚 → 重试拒绝。结果 16 步全 PASS。
2. **单元/集成测试**：`tests/memory-*.test.js`、`document-memory`、`task-memory` 共 19 个用例全绿；路由集成用例覆盖 `/memory/jobs`、PATCH/DELETE、retry、discussion 的权限与状态码。
3. **构建**：`npm run build` 通过。

## 3. 逐环节结论

| 环节         | 状态                     | 证据 / 边界                                                                                                                                                                                               |
| ------------ | ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 发言记忆     | 写入逻辑可用（模型依赖） | `utterance-memory` 单测：按成员维度、只记说过什么；结算与成员理解落库时同步写入。未实机验证模型摘要质量。                                                                                                 |
| 文档记忆     | 可用                     | `document-memory` 单测：正式文件版本落库即写单文档记忆，同文件夹聚成文档组并连 `relates`；zip 自动列清单、图片自动记尺寸；tar.gz 等暂不解析。仅正式区生效。                                               |
| 任务记忆     | 可用（采集；模型依赖）   | `task-memory` 单测：耗时/重试/失败/返工聚合、人类与子 Agent 分开计数；任务候选随结算注入。                                                                                                                |
| 讨论记忆     | 可用                     | 结算候选版 + 宽窗口版（整迭代 ≤500 条发言）；归档确认自动执行、可手动补跑；连参与者、`derives` 到项目整体。                                                                                               |
| 项目整体记忆 | 可用（模型依赖）         | 结算写 `subject=project`；讨论记忆默认继承到最新现行整体条目。                                                                                                                                            |
| 召回         | 可用                     | `memory-search` 单测：对象/成员收窄、关键词 + 一键关系展开、出处与召回计数；老翁走只读 MCP，小祥与子 Agent 走工具桥（能力 `project_memory_recall`），均有能力清单断言。                                   |
| 管理空间     | 可用（静态）             | 作业面板（五类口径、最近运行、积压、立即运行、调整口径、失败重试、讨论补跑、轨迹/历史/会话、回填历史）、按类型/成员筛选、详情可改对象类型并建删关系；小祥监控不再含老翁。后端有集成证据，界面未实机点击。 |
| 存量数据     | 可用                     | 历史条目保留为「未分类」可筛选；`POST /memory/backfill` 按出处归类并折算旧成员/文档摘要，幂等；旧条目无关系边需手动补。                                                                                   |
| 口径覆盖     | 可用                     | PATCH/DELETE 集成用例；停用/阈值/提示词已生效（单测覆盖触发与拒绝）。                                                                                                                                     |

## 4. 已知限制（不阻塞）

- 单一事实源已落 wiki，主要读取点（成员认识、项目导读、文档摘要索引、协调器 prompt、项目列表）已切为 wiki 优先 + 缓存兜底；旧版本文档摘要与队列 `through_sequence` 仍依赖缓存数据。
- 模型相关作业在本环境未实机执行，生成内容的质量（去重、摘要准确度）待有模型环境复验。
- 文档记忆已自动解析 zip 清单与图片尺寸；tar.gz、7z 等仍需老翁用沙箱列目录后补。
- 讨论宽窗口按迭代聚合，未做语义话题拆分。
- 浏览器端交互未实机验证。
