## 当前实现与能力范围

- 项目创建和历史回填建立四条根索引；页面读取时按当前可见文件和主题生成导航，入口可在项目记忆中打开。单文件索引以文件身份关联当前可用版本，同名文件不共用页面；新文件进入内容处理队列，目录变化按实时文件树显示路径。
- 文本、图片视觉输入、ZIP 目录以及有界的 DOCX/PPTX/XLSX 文字提取已接入；Word 97 二进制 `.doc` 与旧版 `.xls` 也按文件头识别后提取正文（覆盖 WPS 把二进制文档存成 `.docx` 后缀的情况）。图片的模型识别文字单独标明需核对；Office 提取标为“识别部分”并说明未覆盖范围。PDF、音视频及其他不支持的内容当前不会自动提取，保留“暂不支持”的结果和原因；不应将其视为已完成内容识别。
- 基于明确的另存关系或正文对项目内唯一文件名的引用，可自动建立关联组；人工可以建立、修正或移除，人工处理优先。被引用文件出现新版本时，系统会读取原引用版本重新核对；仍有可靠依据才更新，无法核对时隐藏。引用来源变更后也不能继续沿用旧依据。引用方先处理时会保留最多 200 个文件名形态的候选，目标随后出现时再核对原文；超过上限、未被识别为文件名的引用及任意语义关联仍不能保证自动发现。
- 文件或版本回收后，索引、根导航、关联展开和协调器摘要读侧排除失效内容；恢复时重新选择可用版本。索引关联及历史迁移依赖已有来源，旧页没有足够出处时无法自动保证精准拆分。
- 正式文件存在同一版本 ID 原位替换内容的路径：内容哈希或 MIME 改变时，旧摘要、识别文字、主题及自动引用依据失效，文件重新入队。模型运行完成时再次核对哈希与 MIME，避免旧分析覆盖替换后的内容。
- 2026-11-03 此前版本曾通过文件索引专项和完整测试；其结果不能作为本轮改造的全量验收。本轮新增验证与限制见文末。

## 目标

将原“主要文档”调整为“文件索引”：为项目传统文件库建立可搜索、可理解、可追溯的 Markdown 入口，帮助 Agent 找到并按需读取原文件。覆盖正式文件和其他区域，不以是否“重要”作为建立基础索引的前提。Markdown 的标题、正文、类型、关联和全文搜索先用于召回；是否增加其他检索方式根据实际效果评估。

索引不是原文件的替代品。每条内容应区分文件事实、提取文字、模型描述与不确定信息，并链接可访问的原文件及具体版本。可直接搜索的文本可简述；难以直接读取的图片、压缩包等需要相应提取。索引详细程度以可发现性、可读性和信息价值决定，不单由是否正式决定。

## 三类 Markdown

1. **根文件夹索引**：对应文档树的四个根区域，每个区域一条；不为各层子文件夹单独建索引。记录主题导航及单文件、关联索引入口，不复制所有文件摘要。正式文件突出用途、适用范围和明确的现行或替代关系；对话缓存以文件主题组织，保留迭代、对话等出处，标明过程材料；沙箱产物以主题组织、类型辅助，保留任务和产出来源；小程序区域区分源码及各类产物。具体分类随内容演进。
2. **单文件索引**：以稳定文件身份为单位，每个文件一条，记录名称、类型、位置、用途、主题、内容描述、适用场景、关联、对应版本和识别结果。文件移动或改名更新同一索引；同一文件新版本更新当前说明并保留必要的版本追溯。文件身份是否延续以文档库真实对象关系为准，不凭名称猜测。
3. **关联文件索引**：围绕共同主题或用途汇总有明确关系的文件，可跨根区域，解释各文件的作用和关联依据，链接单文件索引。文件名、内容、引用及明确业务关系均可提供线索，但同目录或相似名称单独不足以证明关联。允许自动建立，标明自动发现与依据，允许人工修正；不确定时不建组。人工修正应优先于后续自动更新，具体冲突策略待实现时细化。

单文件索引基础骨架：文件信息、这是什么、主要内容、什么时候查它、关联与出处、识别结果。根索引是导航，不强制每项同样详略。各条目可通过关系和来源相连，需在读侧保持权限一致。

## 提取策略

- 文本、Markdown：提取结构和主题，说明用途，避免复述全文；细节回原文。
- 图片、截图及扫描内容：提取可见文字，并用视觉能力描述画面、图表或界面；区分识别文字与视觉解释，不确定之处明确标注。
- PDF 和 Office：按可用能力提取正文及结构，扫描页或关键图表可补充视觉处理；未覆盖范围需标明。
- 旧版 Office 二进制（OLE2 容器）：按文件头识别，不按扩展名；Word 97+ 用 FIB 与 piece table 取正文，图片、批注不读取，旧版 `.xls` 交由表格解析器，`.ppt` 暂不支持。文件长度不是 512 字节整数倍时视为下载不完整，内存补零后解析并在结果原因中记录缺失字节数；加密容器返回“已加密”，不冒充正文。
- 压缩包：列出目录和主要文件类型，按资源限制选择性读取内容；不凭名称推断内部事实。必要时为有独立检索价值的内部文件建立子索引，关联包及具体版本。长文档重要部分也可按需建立片段入口，不默认逐文件或逐页拆分。
- 音视频、未知或暂不支持的格式：有能力时提取内容；否则仅记录可靠元数据及“暂不支持”的原因，不把元数据冒充内容摘要。

解析器、视觉、OCR 和转写的实际可用范围需在实现时验证；大型文件、压缩包解压、嵌套深度和资源消耗应设置上限并记录截断范围。文件内容视为数据，不执行其中的指令或代码。

## 触发与更新

符合范围的文件创建或出现新版本时建立基础索引并登记待处理；短时间连续版本可合并，处理时固定版本 ID、哈希和 MIME，完成前核对当前版本，旧结果不得覆盖新版本。改名、移动或关联变化更新导航和相关索引，不必重复解析未变化的内容。区域变化需刷新旧、新根索引，并按新用途补充说明。关联组随成员、依据和文件状态变化而更新；不因一次模型遗漏自动删除人工修正。

根索引由可靠的文件树和单文件索引汇总，分批增量更新，可重建；关联推断是独立步骤。单文件索引、根导航和关联组分别记录更新状态，某一环失败不应伪称整体完成。处理幂等，重复事件、并发和重试不产生重复条目或丢失新事件。

## 删除、权限与异常

- 文件进入回收站：对应记忆标记作废（内部状态仍为 `superseded`），保留摘要，默认检索不展示；恢复后核对已发布摘要的内容指纹，再决定复用或重新识别。删除的是版本而非文件时，需根据仍可用版本确定当前索引指向。
- 彻底删除：默认不返回不可访问的内容，不提供失效原件链接作为有效出处；历史和审计保留遵循实际清除行为及权限，具体保留字段实施前确认。不得依赖索引绕过删除或权限。
- 基础索引存在不等于内容已识别：区分“识别完整”“识别部分”“暂不支持”及“等待识别”；处理失败单列为处理状态，记录版本、覆盖范围与原因。解析失败可重试；不支持的格式避免无限空跑，能力或文件变化后可重新处理。
- 写入前检查文件仍存在、版本仍适用和用户/项目权限；部分提取失败保留成功部分与缺口。模型和工具失败不覆盖可靠旧说明为虚假完整结果。
- 检索与关联展开均遵循原文件访问权限；模型描述应可回到具体原件核验。面板展示待处理、失败、识别覆盖和重试入口；记忆作业的「文件索引与关联」卡片常驻「待修复关联」入口，点击打开失效关联清单，修正或移除后从清单消失。

## 当前实现差距（局部核对）

- `server/documents/project-library.js` 定义四类根区域；小程序固定子目录包括小程序源文件、小程序 Web 产物、PC 管理后台和云函数，不能只把后两者遗漏。根区域具体创建方式不同，实施时按实际文档树处理。
- `server/project-memory.js` 已有文档摘要队列、文本/图片处理和重试路径，但并不证明上述各格式、全区域覆盖及三类索引均已实现；需审计各文件入队点和模型能力。
- `server/documents/library.js` 区分文件、版本的回收和永久清除，还存在因引用而保留记录的路径；索引生命周期必须逐项对齐，不能把所有清除都视为物理删除。
- `server/mcp.js` 已提供 `read_document` 和按版本分片下载等入口；这不等于 Agent 已能语义解析所有二进制格式。
- 现有作业键、`document` 类型及旧摘要缓存的兼容与迁移须单独设计；“文件索引”是产品命名，不要求立即更改机器键。

## 落地顺序与验证

1. 盘点四区域文件树、对象身份、权限、版本及清除行为，核实现有队列覆盖和提取能力。
2. 定义三类索引的数据身份、版本/来源/状态、人工修正优先级及搜索权限；建立单文件基础索引和幂等更新。
3. 接入各格式提取，覆盖图片文字及视觉理解、压缩包清单和不可读降级；明确资源限制与重试。
4. 增量生成四个根索引和关联组，支持依据追溯及人工修正；处理移动、恢复、删除与并发。
5. 通过真实检索任务评估能否找到原文件，并验证版本竞态、删除恢复、权限隔离、解析失败、压缩包边界及旧数据兼容；再决定是否需要新的检索方式。

## 日志扫描和识别队列（2026-11-03 改造）

文件版本写入、另存、移动、删除等文档业务记录操作日志，不直接建立文件记忆或加入文件识别队列。记忆侧独立消费已提交日志，使用逐条消费凭据而非时间戳游标；消费凭据与待核对请求同一事务提交。文件身份另存于日志，避免物理删除时外键清空后丢失；旧日志中已丢失的身份不能恢复，由首次和每日项目补查兜底。文件夹变更、批量操作及无法定位文件的日志触发分页项目补查，核对当前真实文件与版本。

核对建立基础索引，并按新增、更新、删除处理。仅元数据变动不调用模型，内容指纹和 MIME 相同的新版本可沿用摘要。识别队列保留处理类型、触发来源、排队时间、处理状态、目标内容指纹和错误；按可执行任务的入队时间顺序选择。手动重新识别重新入队，不删除上次成功摘要。记忆卡片上的立即运行只唤醒识别队列，不触发文件扫描，也不提前强制执行尚未到期的自动重试。

每批最多取同项目 50 个到期文件，在项目文件索引会话中按文件逐轮处理，逐项记录处理类型、来源与结果；单项失败继续处理其他文件。模型必须调用 `save_file_index_summary`，仅返回 JSON 摘要不能完成任务。工具暂存通过校验的结果，后端在本轮运行正常结束后，再次核对文件、当前可用版本、排队状态和内容指纹，在同一事务发布摘要并移除队列。相同提交可重复调用，改写同一次已提交结果会被拒绝；暂存后文件变化或运行失败都不会发布旧结果，暂存记录随所属版本或项目物理删除而清理。失败记录原因并按退避重试（1 分钟 → 5 分钟 → 30 分钟 → 2 小时 → 6 小时，最多 5 次后停止自动重试，等人工重新识别；同一版本已有摘要且内容未变时直接出队，不调用模型），无法直接读取且无可靠摘要的文件延后 30 天，用户可手动重新识别。处理中任务超过 15 分钟后，只有取得文件锁才能恢复排队，避免误重排仍在运行的任务。文件被删除后对应记忆状态改为作废，默认检索排除不可访问的原文件；恢复时核对实际内容和已发布摘要的指纹，不能用最近扫描到的内容指纹冒充摘要指纹；相同内容的新版本复用摘要并推进版本出处。归档项目的后台核对与识别不会改写已封存记忆。保留上次摘要供文件列表显式查看，默认读取会排除版本或内容已变化的旧摘要；原文件被回收的旧版本不作为可访问摘要返回。

文件识别覆盖收进标准列表弹窗，支持搜索、识别结果和处理状态筛选及分页，分别显示新增或更新、排队状态和原因。扫描记录包含新增、更新和删除，识别运行历史记录批次中每个文件的结果及触发来源；旧运行没有逐文件明细。删除记录只保留文件名和操作元信息，不存放文件内容。项目记忆、文件覆盖、扫描记录及运行历史在打开或手动刷新时读取，不再定时轮询或切回页面自动刷新。

扫描批次与立即扫描（2026-11-03 追加）：每次逐文件变化都归属一个扫描批次。项目级扫描（每日定时、目录或批量变更、手动立即扫描）各建一个批次，记录触发来源、开始与完成时间和状态；日志驱动的单文件核对按 10 分钟时间窗口聚合为“日志触发”批次。历史明细由迁移按项目与 10 分钟窗口回填批次归属，保证旧数据也能按批次查看。手动扫描要求项目写权限，归档项目拒绝；已有待办项目扫描时复用该次扫描，不重复排队。批次在分页展开结束且该批逐文件请求清空后关闭；进程中断残留的进行中批次和超过窗口的日志批次，在打开扫描记录或维护循环时确认无待办后关闭。扫描记录弹窗打开即批次列表，每行右侧“明细”打开该批次的明细弹窗；批次的数量来自明细实时统计。

## 迁移与恢复

新增 203–209 号迁移，覆盖日志独立身份、消费凭据、核对请求、队列状态、已发布摘要指纹、运行明细、扫描记录和工具提交记录；218 号迁移新增扫描批次表，并为扫描明细、逐文件请求和项目补查加批次关联，219 号迁移增加日志触发来源并按时间窗口回填历史明细的批次。新增列逐条添加，迁移器只在列及索引的实际定义吻合时容忍重复 DDL；中途失败后重启可继续。219 号首次实现里回填 UPDATE 的派生表引用了未暴露的 `created_at`，启动迁移直接报 `ER_BAD_FIELD_ERROR` 并退出 Server，修正为使用子查询已暴露的 `bucket` 后重跑通过；迁移失败后重跑会跳过已完成语句，历史明细已全部回填批次。回填仅初始化缺失指纹，避免重跑迁移将旧摘要绑定到已经替换的内容。首次及每日补查不调用模型，识别仍由独立处理任务执行。
