# 按来源治理记忆：改造与优化方案

日期：2026-11-03（北京时间）。状态：本地实现与验收记录，尚未部署。第 1、3—6 节为设计基准，第 2 节为改造前的历史基线，第 7 节以后记录实际落地与边界。基于当前未提交工作区，不代表线上行为。
2026-11-04 简化：项目现状改为每项目一份 Markdown（`project_status`），随项目进程结算覆盖；本文涉及现状节点、修订、来源指纹与每日巡检的描述已下线，见 [项目进程设计](18-project-process-design.md)。
原则：决定都有出处。

## 1. 讨论结论

记忆生命周期只有现行与作废。现行不等于真实；作废不改写内容或抹去历史出处。取消草稿和转正机制。五大类是用途分类，三大来源决定治理规则，二者分别表达。AI 的疑问、冲突和原因解释是独立判断，不是记忆自身的真实性属性。权重表示对当前问题的参考价值，不是正确率；旧的错误说法在解释历史决定时仍可能最重要。

| 来源           | 更新规则                                                                 | 作废权限                           |
| -------------- | ------------------------------------------------------------------------ | ---------------------------------- |
| 群消息         | 记录谁何时说了什么；补充与纠正新增发言并关联；议题摘要可更新，原发言保留 | 仅人类明确执行                     |
| 项目—迭代—任务 | 当前状态据实覆盖；已发生事件累积；错误依据真实业务事实更正               | 人和 AI 均禁止                     |
| 项目文件       | 已确认的新内容替代正式内容时，旧索引作废、新索引现行；历史修订保留       | 文件维护服务按真实业务事件自动执行 |

项目删除不使创建事件作废；文件索引作废也不作废文件创建、确认或替换的事件。生命周期与访问权限分开，历史读取仍遵守权限和永久清除规则。

## 2. 改造前实现核对（历史基线）

- `migrations/121_wiki_pages.sql`、`server/memory-timeline.js` 和 `web/ProjectMemory.tsx` 使用 `draft/current/superseded`，包含草稿计数、确认和归档转正。
- `server/conversation-memory-store.js` 新建群聊记忆时直接设为 current；`server/project-memory.js` 的项目结算仍创建 draft，普通条目更新还有来源与类型限制。
- `server/memory-search.js` 会在消息编辑或删除后排除出处完整性失败的记忆；已有 conversation revisions，但哈希本身不能还原原文。
- `server/project-status-node.js` 有唯一现状页和修订，但历史来源变化会隐藏旧正文；`server/document-memory.js` 按 artifact 覆盖索引页面。
- `server/documents/service.js` 的 `updateLinkedOfficialFromSource` 可替换正式文件 v1 内容而保持 version_id 不变，仅保存版本 ID 无法固定旧内容。
- `wiki_answer_citations` 未固定记忆修订；记忆检索按全文相关度和更新时间排序，没有按当前/历史/解释用途展开纠正链。

以上为实施前的静态核对，相关问题已按第 7 节改造。不能用本节推断当前代码或线上现状。

## 3. 改造模型

1. 为 `wiki_pages` 增加由服务端确定的 source_family（conversation、project_activity、project_file），保留五类 subject_type；不能由模型或元数据接口改来源。
2. 状态最终只允许 current、superseded。record_kind 可区分 statement、event、current_state、index、synthesis，但属于用途字段，不是第三种状态。议题阶段、任务状态、文件识别状态和作业状态保持独立。
3. 引入不可变记忆修订和来源快照：分别保存记忆正文修订及其实际依据、作者、发生时间、记录时间、原文/结构化字段和访问边界。哈希只检测变化，不能代替原内容。
4. 决定与回答固定引用当时实际使用的修订和来源快照。普通关系可调整，但已被决定引用的证据不可因关系删除而消失。
5. AI 判断和人工反馈单独保存判断者、理由、时间及依据，不将“有疑点”做成记忆事实字段。
6. 多来源页面不能按第一条出处决定权限；业务事实、群聊解释、文件索引应拆分或根据可验证来源重建。无法确定的存量项保留并标缺口。

## 4. 来源改造

### 群消息

发言按稳定消息/观点身份保留。A 说周一、B 说周五均可现行；核验只判断是谁说过及摘要是否忠实，不判断他们说法的客观真伪。A 明确改口时新增纠正发言并关联原发言，不覆盖原文。只有真实人类可明确作废，并留下原因和操作者。消息变化不得自动让已形成记忆消失；保留可合法访问的历史快照并标出原来源变化。决定解释时根据问题召回旧发言、纠正关系及相关行为，AI 因果推断须明确标出。

### 项目—迭代—任务

创建人、时间、归属、当前状态和执行轮次只从业务表或操作日志读取，缺失就标记未记录。当前状态随业务事实覆盖，历史事件持续累积；项目/迭代/任务记忆禁止作废。使用稳定对象 ID 替代按标题归并。同名任务不合并，改名不重复建页。总量使用完整聚合、明细分页；执行、失败、重试、重开分别记录，普通编辑不能直接算返工。并发旧结果不得覆盖新状态。

### 项目文件

保留 artifact 稳定导航及当前索引指针，增加内容修订级索引身份。正式文件内容被已确认沙箱产物原地替换时，即使 version_id 不变也保存不可变内容修订、来源产物版本、确认记录和替代关系；旧索引作废，新索引现行。仅产生未确认沙箱版本不替代正式索引。识别失败不能拿旧摘要冒充新内容。当前检索使用最新可见性，历史依据按权限读取旧修订。

## 5. 检索与界面

`search_memory` 增加 purpose=current/history/explain 与 asOf。排序结合相关度、主体/事件匹配、时间、明确纠正关系、业务新鲜度及人工重要程度；召回次数和 AI 疑问都不代表正确性。查询当前安排优先使用明确纠正后的发言；查询最初发言返回旧发言；查询历史决定原因时返回决定的固定出处和后续纠正。

UI 只保留现行/作废筛选，移除草稿计数、转正和清算勾选。展示来源、允许操作、状态截至时间、历史修订、纠正链和独立的 AI 判断。

## 6. 实施顺序与验收

P0-A：来源策略、修订、来源快照和固定证据引用；先保证出处再切生命周期。P0-B：两态、群消息真人作废、业务记忆禁止作废、事实更新和移除转正。P0-C：文件内容修订、确认后自动替代、历史决定固定引用。P1：问题用途排序、纠正链和判断展示。P2：存量核对、缺口登记、迁移和运行验证，并同步更新记忆相关工程文档。

迁移先扩展、再回填、切换读写、最后收紧数据库约束。取消旧草稿后一律保留为现行，现行不代表真实；来源缺失或混合的内容单独登记证据缺口，不能据此推定作废权限。旧 page_id 不可自动绑定最新修订冒充当时依据。

验收覆盖：A/B 矛盾发言均现行；A 纠正后原话可查；B 因旧安排生气可追到当时依据；所有 AI 入口不能作废群消息；业务事件和当前状态准确且业务记忆不能作废；同名任务不合并、完整统计不截断；正式文件 version_id 不变但内容更换时旧索引作废且历史决定指向旧修订；未确认沙箱版本不改变正式索引；五类无草稿流转；历史出处不受 top-K 和当前文件过滤截断。

## 7. 本地实际落地

- 迁移 210—217：两态约束、三来源、存量缺口审计、独立判断、原文快照、记忆与文件内容修订、文件内容身份、业务事件历史、任务创建决定出处。旧草稿转现行留审计；迁移基线明确标记，不伪造迁移前的历史。来源无法确定、混合来源及历史上曾被作废的业务记忆保留核查记录，不擅自恢复或重判旧处置。
- 群消息：保存原话、作者、发生时间。新发言不覆盖旧发言；同人明确改口建立 corrects 关系。当前查询弱化被明确纠正的旧话，历史与原因查询仍可返回。消息编辑不让有快照的旧记忆消失。人工作废须真实登录、写权限和原因，不改正文。AI 不具备群消息作废入口。
- 业务事实：项目创建人和时间、全量迭代及任务身份、当前状态、执行数直接读取业务表。事实面板使用只读一致性快照；明细和事件分页。创建、受跟踪字段更新、删除形成独立业务事件，无关活跃时间或心跳更新不重复写入。不能确定更新操作者时存空，不冒称创建者。任务页按稳定 ID 更新，同名不合并；普通 revision 编辑不能直接算返工，完成后重开依据真实状态事件计数。
- 文件：artifact 保持导航身份，版本和内容指纹决定索引身份。正式 v1 原地替换也先保存旧字节，生成新索引并自动作废旧索引。旧页及固定修订保留，不被新的来源版本覆盖。确认时重新校验最新产物，未确认产物不替换正式内容。替换日志保存来源版本和确认 ID。修正另存正式文件时关联方向反写的问题。
- 文件组合：人工移除只设置独立的展示隐藏时间，不改变记忆生命周期；重新保存可恢复展示。历史仍按原文件权限读取。永久清除及物理删除文件版本时同步删除历史文件字节，不能通过修订下载绕过边界。
- 决定出处：回答固定实际阅读的记忆修订和材料快照，生成期间正文变化也不改成最新正文；文档阅读返回实际内容修订。任务创建在同一事务保存当时请求原文、显式采用的记忆修订、附带文档的内容修订和任务目标。检索过的材料不会自动冒充已采用的依据。错误或越权依据使任务创建整体回滚。记忆详情反查使用它的任务，任务详情可打开当时出处。
- 工具与界面：移除记忆草稿计数、确认转正和归档勾选。新增人工作废、独立反馈、历史分页、固定修订对话框、业务事实面板。MCP 与 DSH 接入 read_memory_history、read_memory_revision、read_project_facts，search_memory 支持用途和历史截至时间，get_task 返回记录的决定依据。旧 confirm 接口退役，写权限检查后返回 410。

## 9. 迁移、恢复与覆盖边界

1. 尚未发布、提交或推送。本轮迁移仅在独立测试库执行。上线须按正常发布流程先备份，并检查新增表、触发器权限、存量分类审计及文件修订存储容量。不要先跑旧服务再收紧状态枚举，旧服务仍可能写入草稿。
2. 数据库新增约束和触发器与新代码配套。失败应停止业务写入并根据迁移记录修复，不能只回滚服务到仍写草稿的版本。旧内容和审计表应保留，恢复数据库应使用已核实的备份方案。
3. 不能还原历史上未保存的消息原文、已覆盖的文件字节或当时未记录的决定依据。旧消息仅在哈希完全匹配时回填原文，旧引用不能绑定最新正文冒充历史。历史查询只承诺返回当时实际记录的修订。
4. 当前硬事实来自业务事实工具和面板。项目现状文字、项目进程叙述仍经过现有模型提取与出处核验，不能把模型叙述当作数据库事实；查询精确状态、数量和创建信息应读取业务事实。
5. 固定决定依据覆盖问答、记忆结算和新任务创建。旧决定没有快照的仍标未记录；任务后续重排、重新指派等沿用各自的行为日志，尚未统一为所有操作提供显式记忆依据参数。不能宣称全部历史决定均已补齐固定证据。
6. 当前检索仍有 top-K、摘要出处最多 3 条及关系邻域最多 40 条的展示限制。完整已记录出处通过历史分页读取，决定已固定的修订通过 ID 读取，不依赖关系遍历。更细的主体匹配、人工重要程度与业务新鲜度综合排序仍属后续优化，现阶段实现明确纠正关系降权和三种查询用途。
7. 历史读取遵守项目成员、原消息与原文件访问边界。迭代被永久删除后，其消息快照不会继续对外读取；项目业务删除事件保留事实身份，但不越过项目访问权限。来源嵌套的固定修订保存当时的来源依赖，后续重新关联不能绕过旧文件或消息的访问边界。
   较早修订若只有关联页 ID、未保存当时的嵌套来源，则不使用关联页现在的来源关系推定旧访问权限，需保留缺口并核查。项目现状历史优先继承已固定的来源快照。
8. 迁移 217 按真实来源与同项目关系修复唯一可确定的旧反向关联，保留审计；多个正式目标的情况只登记缺口，不猜测目标。新另存、确认链和存量修复均有专项回归。
9. 自动化验证不包含真实模型输出质量、真实浏览器点击或线上发布验收。
