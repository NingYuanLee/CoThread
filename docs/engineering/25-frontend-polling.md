# 前端轮询与标签页可见性

工作台里定时拉取后台数据的接口有多个，统一走 `web/use-poll.ts` 的 `usePoll`。

## 行为

- 挂载时立刻拉一次，之后按 `intervalMs` 周期拉取。
- 标签页隐藏时停表，不发请求；回到前台立刻补一次，再恢复周期。
- 组件卸载后停止计时；`load` 回调收到 `active()`，返回 false 表示已卸载，此时不要再写状态。
- `load` 回调还收到 `signal`：整个 effect 生命周期共用一个中止信号，effect 卸载时中止在途请求。隐藏标签页只停表，不取消在途请求。
- `deps` 变化时重新开始计时。

`web/WorkspaceApp.tsx` 的本地执行器列表（15 秒）与 `web/WorkspaceTopbar.tsx` 的站内信计数（15 秒）都改用它。其余轮询（会话活动、项目活动、通知面板、Agent 监控）本来就自行处理可见性。

2026-11-07 起，任务列表（`web/use-project-tasks.ts`，5 秒）与迭代任务统计（`web/use-thread-task-stats.ts`，15 秒）也改用 `usePoll`：这两处原本各自用 `setTimeout` 续期，不监听标签页可见性，切换标签页后仍在打服务端。任务列表仍保留「仅任务视图打开时轮询」的门禁；迭代任务统计原先没有中止信号，现在会随组件卸载取消在途请求。

## 为什么

切走标签页后这些请求仍在打服务端：既浪费流量，也占数据库连接池。工作台首屏本身一次要并发十几条查询，连接池正是排队的主要来源。

## 测试

`tests/poll-visibility.test.js` 把 hook 里与可见性相关的判定等价重放并断言：挂载即拉取、隐藏停表、回到前台补一次、挂载时已隐藏则先不拉。没有 React 渲染测试环境，测试同时断言源码确实按该判定实现，防止两边漂移。

本文件只写已确认的现行行为。
