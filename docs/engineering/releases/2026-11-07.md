## 1. 修复内容

**分页条数收口。** 新增 `server/limits.ts` 的 `clampLimit(value, def, min, max)`，统一 16 处 LIMIT/OFFSET 的取整与区间。MySQL 的 LIMIT 只接受整数：字符串拼接报 `ER_PARSE_ERROR`，参数化传小数报 `ER_WRONG_ARGUMENTS`，两者最终都被上层错误处理映射成 500；此前路由层只做 `Number()` 不取整，`?limit=10.5` 可直接触发。`server/cloudbase.ts` 有一个语义不同的私有同名函数（服务于腾讯云查询而非 MySQL LIMIT），保持独立。

**下掉两个从未生效的管理入口。** `POST /api/admin/projects/:id/leader-recovery` 与 `POST /api/admin/projects/:id/memory/backfill` 自 2026-11-03 由提交 `a628fc6` 加入起，就没有被登记进 `shared/admin-permissions.js` 的权限表，`adminPermissionForRequest` 对这两个路径返回 `false`，被 `server/routes/admin.ts` 的守卫一律 403；前端 `web/SystemManagement.tsx` 的「核定负责人」与「回填历史」按钮可点但必然失败。本轮删除这两条路由与对应按钮，连带清理只服务于它们的 `can_recover_legacy_roles` 字段。后端能力（`recoverProjectLeaderOperation`、`server/memory-backfill.ts`）与项目侧 `POST /api/projects/:id/memory/backfill` 保留不变，后台自动回填不受影响。

**断开静态循环依赖并补门禁。** `server/memory-graph.ts` 与 `server/child-agent-session.ts` 原从 `./service.ts` 取 `HttpError`，而该类本体在 `server/http-error.ts`（该文件注释明确说独立出来正是为了避免这个环），造成 8 个模块的运行期静态环。改从叶子模块取后环断开。新增 `scripts/check-server-cycles.mjs`：对 `server/` 全量做静态 import 图的环检测（Tarjan 强连通分量），口径只算运行期真的加载的静态依赖（`import type` 编译期擦除不计边，动态 `import()` 不构成初始化期环），并被 `scripts/check-boundaries.mjs` 的规则 8 复用。

**shared/ 纳入类型检查。** 新增 `tsconfig.shared.json`（`allowJs` 与 `checkJs` 都是 `true`），接入前 `shared/` 有 314 条类型错误，接入后为 0。新增 `scripts/check-shared-declarations.mjs` 校验 `.d.ts` 声明与实现导出的漂移；新增 `scripts/check-migration-numbering.mjs` 校验迁移数字前缀唯一性（已上线的 144、155 两组重复走白名单放行并打印原因——改名会让已应用迁移的 `name` 失配、部署直接失败）。

**发布门禁修正。** `scripts/lint.js` 在 push 事件下原用 `HEAD^...HEAD` 计算改动范围，只覆盖最后一次提交；现按推送前的提交计算，PR 路径不变。发布清单新增 `commit`、`commitDirty`、`sha256`、`bytes` 四个字段，由打包入口写入，人工记录以清单为准。

**前端包体缩减。** `web/MarkdownDocumentPreview.tsx` 改为按需加载，`react-markdown` 与 `remark-gfm` 移出首屏静态依赖图：主 chunk 从 178.9 KB 降到 13.6 KB，含 micromark 的两个 chunk（44.8 KB 与 112.1 KB）已不被入口 chunk 引用。清理 `web/workspace.css` 里 588 条无引用规则与 38 个本来就存在的空 `@media`/`@supports` 块，源文件 673,760 → 569,923 字节，生产共享 chunk 475,039 → 405,617 字节；动态拼接的类名逐个枚举取值后确认在用并保留。任务列表与迭代任务统计改用 `usePoll`，标签页隐藏时停表；迭代任务统计补上中止信号。`web/WorkspaceApp.tsx` 稳定关键引用，`web/ConversationStage.tsx` 包一层 `memo`。

## 5. 本轮遗留与后续事项

- **`tsconfig.shared.json` 未进发布包。** 打包入口的路径清单不含它，线上实例因此没有这个文件；运行期不需要（Node 原生擦除类型不读 tsconfig），但线上无法执行 `npm run typecheck:shared`。若要在 ECS 上跑门禁，需把它加入 `scripts/ecs-pack.mjs` 的 paths。
- **管理空间项目详情里的「角色迁移」提示文案保留。** 它仍如实反映 `project_role_migration_issues` 的数据状态，但已没有可点的修复入口，文案里的「需要核对后设置」失去了操作指向。是否改文案属于产品判断，本轮未动。
- **CSS 按域拆分本轮只做了清理死样式。** `web/workspace.css` 里没有任何一个域是连续块（documents 68 段、project-management 67 段、shell 184 段、跨域 323 段），跨域规则 773 条、顺序敏感 2110 对，把 admin 域彻底独立化需要搬走 276 条公共类并逐条保证相对顺序，收益（admin 独占规则仅 109 条 / 17,754 B）与回归风险不匹配。方案已备（新增双方共用的 CSS 文件、admin 独占规则进 admin.css、顺序敏感规则用脚本自动判定复制位置），下一轮单独执行。
- **`/api/tasks/:id/agent-logs` 等接口的条数区间已统一**，但 `public/docs.html` 全文未描述这些 limit 参数，公开文档无需同步。
- **未做登录后的真实业务验收。** 本轮只完成健康接口、页面资源与代码指纹核对，真实 Agent 会话、模型调用、任务派发与老翁记忆整理均未在生产实机执行；页面与健康接口通过不等于全部业务已验收。
