# 接口加载与耗时诊断

工作区首屏使用 `/api/workspace` 一次返回用户、项目列表、选中项目和最近会话；浏览器仅记住选中的 ID。会话未加载完时显示加载状态。站内信关闭时仅轮询计数，打开时读取分页列表，并缓存最近打开的页面；后台标签页暂停轮询。

## 查看耗时

运行 `node scripts/probe-api.mjs https://cothread.z2l.top`，对首页和公开健康接口各做三次只读采样。不输出响应内容或凭据。登录后的工作区、站内信请求可在浏览器网络面板查看以下响应头：

| 指标 | 含义 |
| --- | --- |
| `Server-Timing: app` | 从应用中间件进入到发送响应头的时间 |
| `init` | Makers 初始化等待时间，包含其中的数据库调用 |
| `db` | 数据库调用占用的时间区间，并发区间去重 |
| `db_sum` / `db_max` | 数据库调用累计耗时 / 最慢一次调用耗时 |
| `db_count` | 数据库调用次数（description） |
| `X-CoThread-Request-Id` | 关联浏览器响应和云端慢请求日志 |

单位均为毫秒。`init`、`db` 与 `app` 有包含关系，不能相加。数据库耗时包含连接池等待及云端到数据库的往返，不等于数据库引擎内部的纯 SQL 执行时间。当前库结构已完成迁移时仅查询一次迁移记录，不再逐条检查或申请迁移锁。

应用超过 1 秒的请求和 5xx 自动输出 `Request timing` 日志；临时设置 `REQUEST_TIMING_LOG=true` 可记录所有请求。日志不包含 SQL、参数、消息正文或查询字符串。流式接口的响应头反映首包前耗时，完成日志还包含流持续时间。

## 如何判断瓶颈

- 首字节慢、`app` 小：检查网络、平台排队或进入应用前的冷启动。探针中的 `networkAndPlatformMs` 是首字节减去 `app` 的近似值，不能单独视为网速。
- `init` 大：检查云函数初始化、连接建立和迁移检查。
- `db` 大：检查连接池、慢查询、云函数和 RDS 是否同区域，以及跨区域链路。
- 下载时间大：检查响应体积、用户带宽和静态资源缓存。

先取得部署后的分段数据，再决定调整 EdgeOne 配置或服务区域。更换边缘节点不能直接修复云函数到数据库的慢链路。公开健康接口采样不能替代已登录站内信接口的实际测量。
