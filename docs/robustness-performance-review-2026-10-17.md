## 架构判断

当前 React 工作台 → HTTP/MCP → 领域服务 → MySQL 的主链路适合现有单实例、小团队部署。Service 与任务领域已按职责拆分，文档内核保留独立写入边界；本次架构门禁检查为 0 处违例。继续沿现有模块边界优化请求与资源生命周期，比立即增加分布式组件更容易验证收益。

本次重点是异步请求所有权：缓存写入、实时连接切换和页面可见性变化之后，旧请求均不能继续发布状态。取消网络请求与拒绝过期结果需要同时存在，不能只依赖 AbortController。

## 已复现的问题

| 问题 | 复现证据 | 目标行为 |
| --- | --- | --- |
| 手动缓存更新被旧轮询覆盖 | 浏览器先写入新消息，再完成旧请求，缓存显示“过期轮询” | 手动写入使较早请求失效，旧成功或旧权限错误均不得覆盖新状态 |
| 手动写入绕过缓存容量 | 上限 12，连续 500 次 update 后仍能读到 500 条记录 | 所有写入共用容量与更新顺序规则 |
| SSE 与轮询切换时内容回退 | SSE 断线 → 轮询挂起 → 重连并收到新流 → 旧轮询返回，页面退回“旧轮询内容” | 每次连接切换拥有独立代次，旧回调不得发布或重新调度 |
| 隐藏的监控页持续请求 | 模拟 document.hidden 后，监控请求计数仍从 1 增至 10 | 隐藏时停止自动轮询并取消在途请求，恢复可见时立即刷新 |
| 回滚错误掩盖原始事务错误 | 故障注入下，403 业务错误或提交结果不明错误被 rollback 的连接错误取代 | 尽力回滚，保留原始错误，始终执行连接释放；写入与事务不重放 |
| 本地消息推动游标导致增量拉取遗漏 | 拉取游标直接取最后一条本地消息的序号；并发远端消息 N 尚未读取，本地先保存 N+1 后会直接拉取 N+1 之后的数据 | 游标只由已拉取的服务端分页推进；乐观或刚提交的消息不推动游标，加载历史不使新消息游标回退 |
| Agent 清理失败跳过会话锁释放 | close 的沙箱回收、目录清理等步骤与锁释放顺序串联；沙箱回收故障注入后可能直接跳过锁释放 | 锁释放放到 close 最外层 finally，前面任何清理步骤失败都进入锁释放 |
| 超时命令留下后台子进程 | 运行 `(sleep 3; printf orphan > after-timeout.txt) & wait`，超时 1 秒后返回，原实现仍产生文件 | 独立超时器先结束进程树，等待终止完成后返回；Windows 用 taskkill /T /F，POSIX 使用独立进程组 |

### 事务连接状态补强

进一步故障注入确认：原通用事务封装在 BEGIN 或 ROLLBACK 失败后仍会归还连接，可能把未确认结束的事务带回池中。现统一通过 `discardConnection` 销毁此类连接，保留原始错误；正常提交或成功回滚仍复用连接。归档的同连接事务也遵守这条规则，状态不确定时直接丢弃锁持有者，不再发送额外解锁 SQL。

真实数据库验证：在事务中插入一行后让业务失败，再注入回滚传输故障；连接销毁后，新会话可插入相同主键，证明未提交行和行锁都已释放。归档准入同时注入业务错误与回滚失败，验证原始业务错误保留、旧连接没有回池、会话锁可重新获取。

## 第三阶段：工作器关闭与锁的排空顺序

### 修复前复现

新增真实数据库故障闸门测试：让一个协调器通道已进入查询但保持挂起，再调用执行器 stop。原实现的 `IS_FREE_LOCK` 返回 1，证明旧任务尚未结束，全局执行器锁已空闲；断言期望为 0，测试失败。旧实现清理期间还记录了 `Pool is closed`，说明调用方无法等待任务结束再关库。原始日志为 `tmp/performance-qa/shutdown-before.log`，本轮临时库 `cothread_architecture_test_34964` 已清理。

### 修改范围

- 工作器 stop 立即停止新调度，返回可重复等待的同一个排空 Promise；在途调用结束后才能完成。
- 执行器停止时先停全部通道，等各通道排空后释放命名锁。重复停止共用完成 Promise；锁归属检查避免重叠及停止后发布过期检查结果。
- 服务入口通过 `createShutdown` 同时停止 HTTP 接收和工作器调度，等 HTTP 与工作器都结束，再关闭 Vite 和数据库。重复信号共用一个关闭过程；错误和超过 30 秒的关闭以退出码 1 结束，防止无限等待。期限计时器保持引用，真实子进程验证挂起任务不会导致进程过早以成功状态自然退出。
- 健康检查与执行器回归测试改为等待 stop 完成，替代固定睡眠或不等待的清理。

本轮修复的是正常停机时的所有权与资源释放顺序，没有增加任务强制取消协议。若锁连接已经断开，MySQL 无法继续为旧进程保留全局互斥；已经运行的外部任务也不因此自动取消。长连接 HTTP/SSE 或不可取消调用仍可能触发 30 秒失败退出；完整跨进程中止与外部子进程回收继续单独核查，不把排空等同于这一问题已全部解决。

| 另外加入 3,000 条其他会话消息 | 5.873 ms | 0.647 ms | 两者均为 4 |
| 缺失会话游标，需读取全部历史 | 21.559 ms | 18.115 ms | 两者均为 2,000 |

## 第十一阶段：同进程沙箱重连的生命周期与回收入口

本轮先读取记录、Git 状态与验证进程；未发现遗留验证或其它写入者，保留已有工作区改动。继续核查 provider.connect 与回收路径，不修改数据库结构或外部提供商接口。

### 修改前证据

新增两个真实 Windows/Git Bash 场景，均在原实现失败，日志 `tmp/performance-qa/sandbox-reconnect-before.log`：

- 原句柄启动命令并落盘 ready 标记，随后 sleep 3 秒；connect 同一 sandboxId 得到另一个句柄并调用 kill。原命令仍退出码 0、输出 survived。原因是 connect 每次构造独立实例，新的 children 集合为空，回收并不拥有原进程。
- kill 已成功后，旧句柄再次 run，仍通过 mkdir 重建目录并正常退出。killed 只在 spawn 后补一次终止，无法阻止快速命令完成和目录复活。

### 修复

- 按绝对沙箱根路径登记弱实例引用，同进程 connect 复用仍存活的实例，共享 children、退休状态与回收过程；Windows 对 key 大小写归一，避免同一目录的大小写别名分裂所有权。
- 使用 WeakRef 而非永久强持有实例；FinalizationRegistry 仅在当前登记仍是原弱引用时清理，防止迟到回收误删后续登记。成功 kill 主动删除登记并注销。未将此表述为已测量的堆内存收益或严格的缓存条数上限。
- 登记使用同步 get-or-set：即使 create 的 mkdir 已创建目录但其 Promise 尚未交回，期间发生 connect 并开始命令，create 完成时也采用已经登记的活实例，不覆盖它的任务所有权。
- kill 同步关闭新入口，并共享同一个完成 Promise。已运行子进程立即进入原进程树终止路径；已接纳的异步目录准备/文件写入同时排空，二者完成后才删除根目录，防止迟到 mkdir/write 复活目录。
- run 在准备目录之后、spawn 之前再次检查退休状态。files.makeDir/write、run 与 setTimeout 均拒绝退休句柄；已接纳的文件写入允许完成，但删除会等待它，因此不会在回收完成后重新写出目录。
- 删除失败时保留退休状态和实例登记，清空失败的 kill Promise，允许重新 connect 后重试回收；成功后保留已完成 Promise，重复 kill 幂等。只在完成删除后清理登记。

## 第十三阶段：侧表未变时的快照指纹传输协议

本轮先读记录、Git 状态与验证进程，保留既有改动。针对主三张侧表 UPDATE/DELETE 的初步检索就有 43 处匹配，立即引入持久事件日志需要更大范围的写入覆盖与迁移。因此先实现由真实快照生成指纹的显式 opt-in 协议，减少未变载荷，不引入 TTL 缓存、迁移或写入失效状态。

### 实现及正确性

- `view=chat&sideState=initial` 启用；服务端正常完成鉴权、权限检查和原始读取后，对六个集合 reviews/runs/replies/updates/requests/connectorTasks 及用户/迭代/投影作用域计算 SHA-256 token。匹配时返回 unchanged 与六个占位空数组，变化、删除或未知 token 返回完整 snapshot。不传参数、view=full、Service/MCP 默认行为兼容。
- contextUsage 等计算仍使用完整回复集合，再做传输投影；消息、事件、未读和元数据仍独立更新。没有新数据库表、触发器、迁移、权限缓存或跨池结果缓存。
- 客户端共享合并函数仅在仍持有匹配的完整快照时恢复 unchanged；否则一次 initial 重同步。弱登记关联迭代、token、数组引用与长度，乐观侧表替换不再沿用旧 token；WorkspaceApp 本地更新主动清除它。侧表按不可变值使用，引用检查不宣称识别任意嵌套字段原地修改。
- 读取逻辑提取到 `shared/thread-reader.js`，供 WorkspaceApp 与隔离浏览器直接调用，保留消息分页、乐观消息、取消和资源缓存请求身份规则。threadPollKey 纳入 token，修补仅用量字段变化时可能不更新界面的边界。
- 协议与约束见 [chat-side-state-protocol.md](chat-side-state-protocol.md)。它是快照指纹/未变传输省略，不是单调的行级变更游标。
