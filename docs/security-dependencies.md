# 依赖风险记录

本文件记录已知的、**有意保留**的依赖风险与判断依据。新增或撤销一条都要写清复查条件。

## axios 0.27.2（保留，不覆盖）

### 事实

- `@cloudbase/node-sdk@3.18.3` 将 `axios` **精确锁定**在 `0.27.2`（不是 `^`）。全仓库仅此一个消费者，共序自身代码不直接调用 axios。
- 已知公告：
  - **CVE-2026-101902**（NVD，2026-09-28）：axios 默认实例在未显式指定 `method` 时会读取 `Object.prototype` 上被污染的方法值，使 `axios({ url })` 可能发出改变状态的请求。受影响范围 `>=0.27.2 <0.34.0` 与 `>=1.0.0 <1.20.0`，修复版本 0.34.0 / 1.20.0。
  - **GHSA-wf5p-g6vw-rhxx**：Axios CSRF / `XSRF-TOKEN` 泄露（moderate）。
  - 社区另报告 0.x 线存在若干 HIGH 公告。
- `npm audit` 在本仓库**无法运行**：registry 指向 npmmirror 镜像，未实现 audit 接口
  （`POST /-/npm/v1/security/advisories/bulk` 返回 404 `NOT_IMPLEMENTED`）。因此依赖公告不会被例行工具发现；
  需要覆盖时应针对官方 registry 运行或改用其他扫描器。

### 可达性判断

- 调用路径为**服务端到腾讯固定端点**，URL 由 SDK 构造；操作者只能影响集合名与文件路径，**不存在用户可控的请求 URL**，SSRF 类公告基本不可达。
- `XSRF-TOKEN` 泄露属浏览器侧问题，服务端调用不适用。
- CVE-2026-101902 是**读取侧利用链**，需要同进程内另有一个原型污染源。共序进程会解析成员提交的 JSON 与 MCP 参数，目前没有已知污染源，但这不是保证。

### 决定与理由

**保持锁定，不使用 npm `overrides` 强行升级。** 理由：axios 1.x 存在破坏性变更，而 `@cloudbase/node-sdk` 的行为
正确性无法在缺少真实 CloudBase 环境时验证；强升后若 SDK 静默出错，后果比公告本身更严重。上游 3.18.3 已是当前最新版。

### 复查条件（满足任一即重新评估）

1. `@cloudbase/node-sdk` 发布新版本并提升 axios 版本。
2. 共序新增任何**用户可控 URL** 传入 CloudBase SDK 的调用路径。
3. 进程内引入新的原型污染面（例如新增反射式合并不可信 JSON 的工具）。
4. CVE-2026-101902 出现公开的、可在本进程组合利用的污染源。
5. 若届时仍无法升级，备选方案是把 CloudBase 访问按微信 CI 的方式隔离到子进程，以限制影响面。
