共序 CoThread 是一个以「项目—迭代—文档版本」为主线的团队协作工作台。 项目是长期工作空间，一次迭代对应一个群聊；成员用各自的本地 AI 读取上下文、提交产物， 团队人工审核之后归档，结论与出处一并留痕。

Product

共序是什么

它不只是一个聊天窗口，而是把「讨论」和「交付物」绑在一起的工作台。聊天记录负责上下文，文档库负责成果，两者靠版本号精确关联。

🧭

项目即长期空间

一个账号可加入多个项目，各项目分别分配负责人 / 成员 / 只读权限。账号目录与项目成员分离，新账号不会自动获得任何项目权限。

💬

迭代即群聊

消息按数据库序号排序，多人页面定时刷新；聊天里直接显示 AI 执行进度、工具输入与结果，支持停止与失败重试。

🗂️

成果即版本

产物保存为不可覆盖的文档版本，带 SHA-256 校验与并发版本编号；上传 ≠ 审批通过，审核与归档由人工完成。

Capabilities

以下能力均以当前版本实际实现的功能为准，按协作链路归类。

账号与权限

登录、全局账号目录与项目成员分离；同一账号可加入多个项目，负责人可新建通用账号，权限按项目粒度分配。

负责人 / 成员 / 只读

文档版本与审核

二进制内容入库，5 MiB 单文件限制、SHA-256、不可覆盖的版本与并发版本编号，并保留人工审核记录。

不可覆盖
🔗

精确引用与归档

消息引用精确到文档版本；归档事务一次保存结论、消息、审核、版本摘要与执行结果，归档后不可修改，下一迭代仍可继续引用旧版本。

可追溯
🤖

内置 DSH Agent

可读取项目资料、在 ACS 中创建与编辑文件、执行命令与测试，并把成果保存为文档版本。每个迭代独立会话与工作区。

会话快照入 MySQL
📦

沙箱按需创建

工作区按需创建，续期 15 分钟；过期后可从已保存文档恢复。沙箱临时文件可能过期，只有提交进文档库才算正式留存。

15 分钟续期
🧰

MCP 工具集

7 个 Streamable HTTP 工具自带使用说明：从连接指引、项目与迭代上下文、读取版本，到发消息与提交文档；调用者身份由服务端凭据确定。

Bearer 鉴权
🔑

本地 Agent 连接

账号单令牌、30 天有效、可重置；哈希鉴权 + AES-256-GCM 加密保存，按项目成员权限访问，浏览器中默认遮罩显示。

可重置
🌲

文档库与文件树

右侧项目文档与弹窗复用同一文件树，支持拖拽整理、多级折叠、新建文件夹/文档、上传、移动、重命名、回收站恢复、版本切换、预览与下载。

梳理讨论

Workflow

一次协作怎么走完

从讨论到归档，每一步都留下可回溯的记录；AI 负责执行，人负责决策。

STEP 01

讨论与澄清

在迭代群聊里提出需求、补充要求与引用已有版本，上下文由消息序号与引用关系固定下来。

STEP 02

Agent 执行

勾选「交给 Agent 处理」，Agent 读取项目资料，在 ACS 独立工作区里创建与编辑文件、运行命令与测试。

STEP 03

提交为版本

成果保存为新的文档版本（含 SHA-256），进入文档库；本地 AI 令牌不能审批，也不能归档。

STEP 04

人工审核归档

人工审核通过后归档，事务保存结论、消息、审核与版本摘要；归档后不可修改，后续迭代可继续引用。

Architecture

架构与存储

轻量但明确的分工：ACS 是唯一执行后端，MySQL 是业务数据与附件的持久化存储，宿主机只做编排。

前端 / 协作界面web/

React 页面：迭代群聊、执行进度、文档库文件树、版本预览与下载。

服务端server/

HTTP API、权限校验、协作业务、MCP 工具与 ACS 接入；MCP 工具由服务端凭据确定调用者身份。

执行后端ACS

唯一执行后端，负责沙箱创建、命令执行与文件读写；宿主机仅编排 Agent，不直接执行工具。

持久化MySQL 8.4

业务数据、文档原始字节与不可变版本、会话快照与工具过程。每个文件最多 5 MiB，沙箱回收不会删除已提交文档。

Project layout
# 项目结构
web/          React 页面
server/       HTTP API、权限、协作业务、MCP、ACS
migrations/   版本化 MySQL 结构
scripts/      安装初始化、迁移、示例、连接检查
tests/        真实数据库集成测试
docs/         架构与部署说明
.local/       本机 MySQL 程序、数据、私有配置（不入库）
  • 文档版本不可覆盖，消息引用精确到具体版本号
  • 归档事务一次落库：结论、消息、审核、版本摘要、执行结果
  • 令牌以哈希鉴权 + AES-256-GCM 加密保存，重置即全部失效
  • 当前未接入对象存储，附件本体保存在 MySQL
Get started

本机启动

需要 Node.js 22.19+（本机已具备 Node 24），本地 MySQL 8.4.9 便携版监听 127.0.0.1:3307，不注册系统服务。

# 初始化与启动
npm install
npm run setup
npm run mysql:start
npm run db:migrate
npm run db:seed
npm run dev

# 打开 http://localhost:3100
# 初始账号取自 .env 的 ADMIN_EMAIL / ADMIN_PASSWORD
  • npm run build：类型检查与前端生产构建
  • npm test：真实 MySQL 集成测试，独立随机库、结束后清理
  • npm run db:backup：完整备份业务数据与文件内容
  • npm run app:start / app:stop：Windows 下启动本地库并后台运行生产版
  • 安装 Docker 的机器可用 compose.yaml（mysql:8.4.9），但不要与便携版同时占用 3307

连接本地 Agent：在工作空间设置里创建账号令牌，按 Streamable HTTP 配置 MCP 客户端；令牌缺失或过期时，安装文档会自动创建或更新。

Scope

当前边界

首版面向小团队单实例试用。以下能力尚未包含，请不要把当前版本当作完成全部生产加固的公共 SaaS。

🚧

暂不包含

  • 邮件邀请、SSO、密码找回
  • 推送通知、全文搜索
  • 文件在线编辑、对象存储
  • 多实例作业调度
🧭

使用前提

  • 审核、归档与成员管理仍由人工进行
  • 云端部署需配置 HTTPS 反向代理与数据库 TLS
  • MySQL max_allowed_packet 建议 ≥ 32 MiB
  • 升级 DSH 时需同步验证会话恢复适配器
