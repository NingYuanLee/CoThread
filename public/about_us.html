Product

共序是什么

它不只是一个聊天窗口，而是把「讨论」和「交付物」绑在一起的工作台。群聊负责上下文，文档浏览器负责成果，两者靠不可覆盖的版本号精确关联。

🧭

项目即长期空间

一次独立部署对应一家公司。一个账号可加入多个项目，各项目分别分配负责人 / 成员 / 只读。公司目录只有人类成员（含超管）；新账号不会自动获得任何项目权限。左侧「项目管理」维护本项目人类成员、连接器与项目级 Agent。

💬

迭代即群聊

一次迭代对应一个群聊。消息按数据库序号排序；聊天里显示小祥的执行进度、工具输入与结果，支持停止、失败重试，以及基于已有上下文的「梳理讨论」。

🗂️

成果即版本

项目下全迭代共享文档库。正式文件、对话缓存、任务产物分开放。产物保存为不可覆盖版本（SHA-256）；上传和 Agent 发布都不等于审批通过，审核与归档由人完成。

本页为纯静态介绍页，与仓库 README 同步，不接入后端，也不包含任何真实令牌或账号信息。

Workspace

打开项目以后

三栏各司其职：左侧收纳项目与人，中间把事聊清楚，右侧永远是文件而不是成员面板。侧栏可以收缩，把宽度留给讨论和预览。

左侧

迭代与项目管理

列出当前项目的迭代讨论，可查看已归档。底部打开「项目管理」（人类成员、连接器、项目级 Agent）和「小祥 Agent 监控」（L1 / L2 / L3）。

中间

迭代群聊

默认勾选「交给 Agent 处理」。可引用精确文档版本、把附件丢进当天对话缓存目录，看执行过程并停止或重试。

右侧

文档浏览器

一棵树看本项目共享的正式文件、对话缓存与沙箱产物。点选即可预览 Markdown、代码、图片、PDF 以及 Word / Excel / PowerPoint。

边界

谁能改什么

缓存只来自对话框或 MCP 上传；产物只由 Agent 生成（含按缓存修改后的结果）。人不能在这两区直接改内容，可查看、引用、下载、审核、重命名、回收。「需要修改」会弹窗填意见后发到当前群聊。

Capabilities

已实现的核心能力

以下均以当前仓库实际功能为准，不是路线图。

🔐

成员与权限

账号名或已绑定邮箱登录。公司级成员管理只有人类（含超管）。项目成员是本项目人类及其连接器，加上项目级 Agent（L1）；权限按项目分配负责人 / 成员 / 只读。

Agent 不进公司目录
🧾

文档版本与审核

二进制入库，单文件 5 MiB、SHA-256。缓存仅对话/MCP 上传，产物仅 Agent 生成，正式文件来自确认另存或人工上传。点「需要修改」须说明内容并发到当前迭代。

不可覆盖
🔗

精确引用与归档

消息引用精确到版本号，且可引用本项目文档库任意有效版本。归档一次保存结论、讨论、审核与版本摘要，已确认产物另存到正式文件；归档后本迭代不可改，文档库仍共享给后续迭代。

可追溯
🤖

小祥：一个身份，三层干活

对用户始终是「小祥」。L1 挂在项目（知识库），L2 挂在迭代（调度），L3 挂在任务（执行槽）。同时最多 7 个执行任务加 1 个接待名额。

监控页可看内部职责
📦

沙箱与会话快照

本机走本地沙箱，云端走 Makers 原生沙箱。临时文件可能过期；正式留存必须发布进文档库。会话快照写入 MySQL，重启不自动重放副作用操作。

长期成果必须入库
🧰

MCP 与本机 Agent

7 个 Streamable HTTP 工具让成员本地 AI 读上下文、发消息、提交产物。Windows 连接器属于项目人类成员，把确认后的任务交给本机 Cursor / Codex / Claude Code 会话与 Git。

Bearer 账号令牌
🌲

文档浏览器

右侧固定文件树：正式 / 缓存 / 产物。预览 Markdown、文本代码、图片、PDF 以及 Word / Excel / PowerPoint；其余格式请下载原件。

Office 预览
✨

梳理讨论

在输入框预填一条基于助手已有上下文的请求，成员发送后按普通 @ 小祥处理，不再弹出消息条数选择，也不要求重新读完整会话。

走群聊，不另开通道
🖥️

云端与本机

Git 推送 main 后由 EdgeOne Makers 构建。生产站点 cothread.z2l.top。本机 Node 22.19+ 与便携 MySQL 8.4 即可开发。

单实例试用
Workflow

一次协作怎么走完

从讨论到归档，每一步都留下可回溯的记录；AI 负责执行，人负责决策。

STEP 01

讨论与澄清

在迭代群聊里提出需求、@ 小祥或交给本机 Agent，引用已有版本。上下文由消息序号和引用关系固定下来。

STEP 02

小祥执行

二级判断是否开跑；三级在独立沙箱里改文件、跑命令。忙时会明说暂时只陪聊，不会把请求悄悄排队。

STEP 03

发布沙箱产物

云端 Agent 成果进入项目沙箱产物（含 SHA-256）。对话附件只进缓存，正式文件独立上传。本地 AI 令牌不能审批，也不能归档。

STEP 04

人工审核归档

确认或「需要修改」（弹窗说明后发到当前群聊）。归档后本迭代锁定，已确认产物另存正式文件；文档库仍给后续迭代共用。

Architecture

架构与存储

一家公司对应一次独立部署和一套数据库。项目、迭代、任务层层收纳；人类成员、连接器与三级 Agent 挂在不同层，互不混进公司目录。

🏢

协作层级

公司（独立服务与库）→ 项目（长期空间与共享文档库）→ 迭代（群聊与本轮任务）→ 任务（可指派、确认、执行的工作项）。

👥

角色层级

成员管理仅人类（含超管）。项目成员：本项目人类、其连接器、L1。迭代成员：本项目人类、本迭代 L2、任务级 L3。聊天里对外仍是小祥。

前端 / 协作界面web/

React 工作台：可收缩侧栏、迭代群聊、文档浏览器、项目管理弹窗、小祥监控与 Office 预览。

服务端server/

HTTP API、权限校验、协作业务、MCP 工具与沙箱路由；MCP 工具由服务端凭据确定调用者身份。

执行后端Local / Makers

本机固定本地沙箱；Makers 使用请求注入的原生沙箱。检查点有配额，长期成果必须发布到文档库。

持久化MySQL 8.4

业务数据、文档原始字节与不可变版本、会话快照与工具过程。每个文件最多 5 MiB，沙箱回收不会删除已提交文档。

Project layout
# 项目结构
web/               React 工作台
public/            静态页（含本页）
server/            HTTP API、权限、MCP、沙箱路由
cloud-functions/   EdgeOne 云函数
agents/            Makers 长任务
migrations/        版本化 MySQL 结构

  • 文档版本不可覆盖，消息引用精确到具体版本号
  • 归档事务一次落库：结论、消息、审核、版本摘要、执行结果
  • 令牌以哈希鉴权 + AES-256-GCM 加密保存，重置即全部失效
  • 当前未接入对象存储，附件本体保存在 MySQL
Get started

本机启动

需要 Node.js 22.19+（本机已具备 Node 24），本地 MySQL 8.4.9 便携版监听 127.0.0.1:3307，不注册系统服务。

# 初始化与启动
npm install
npm run setup
npm run mysql:start
npm run db:migrate
npm run dev

# 打开 http://localhost:3100
# 初始账号见 .local/initial-admin.json
  • npm run build：类型检查与前端生产构建
  • npm test：真实 MySQL 集成测试；须独立 TEST_DATABASE_URL，禁止清库开发库
  • npm run db:backup：完整备份业务数据与文件内容
  • npm run app:start / app:stop：Windows 下启动本地库并后台运行生产版
  • 安装 Docker 的机器可用 compose.yaml（mysql:8.4.9），但不要与便携版同时占用 3307

共序 MCP：由本机 Agent 连接器在授权后自动申领账号令牌，并写入 Cursor / Codex / Claude Code 的 Streamable HTTP MCP 配置；令牌临近过期时连接器自动续期，无需手抄。

Scope

当前边界

首版面向小团队单实例试用。以下能力尚未包含，请不要把当前版本当作完成全部生产加固的公共 SaaS。

🚧

暂不包含

  • SSO、邮件邀请入项目
  • 推送通知、全文搜索
  • 文件在线编辑（可预览）、对象存储
  • 多实例作业调度
🧭

使用前提

  • 审核、归档与公司级成员管理仍由人工进行
  • 云端部署需配置 HTTPS 反向代理与数据库 TLS
  • MySQL max_allowed_packet 建议 ≥ 32 MiB
  • 升级 DSH 时需同步验证会话恢复适配器
