共序详细文档

这里写清楚怎么用、怎么接、怎么部署。价值叙事在关于我们；命令和最短路径在仓库 README.md。

当前面向小团队单实例试用。不包含 SSO、推送、全文搜索、文件在线编辑、对象存储和多实例作业调度。Markdown / 图片 / PDF / Office 可在浏览器预览。

本机启动

需要 Node.js 22.19+。本地 MySQL 为官方 8.4.9 Windows ZIP 版，不注册系统服务，监听 127.0.0.1:3307。Agent 命令依赖 Git Bash。

npm install
npm run setup
npm run dev

之后日常只需 npm run dev。打开 http://localhost:3100。首次 setup 把初始账号写进 .local/initial-admin.json 和 .local/登录信息.txt。登录可用账号名或已绑定邮箱。

开发网关默认在 3100：/api 与 /mcp 转到 API（3101），其余转到 Vite（3102）。默认监听 0.0.0.0 时可连 RDS；仅强制 loopback 监听时才会拒绝远端库，确需覆盖时设 COTHREAD_ALLOW_REMOTE_DB=1。

公司 · 项目 · 迭代 · 任务

一次部署对应一家公司：服务独立、MySQL 隔离。公司之内是项目管理，项目之内是迭代，迭代之内是任务。

层级含义
公司单次独立部署。账号、项目、文件都在本实例 MySQL，与其他部署互不影响
项目长期工作空间：共享文档库、长期记忆、项目成员
迭代一次讨论群聊：消息、本轮 L2；文档仍用项目文档库
任务可指派、确认、执行的工作项：L2 的子 Agent，或人类 / 本地执行器执行

角色与小祥

公司目录只有人类成员（含超级管理员）。Agent 不写入 users 表。聊天里 @ 的是「小祥」（L2）。L1 是项目知识维护；执行任务的是 L2 的子 Agent，不叫小祥。

层级谁在这里
成员管理仅人类，含超级管理员。系统管理里的「成员管理」
项目成员本项目人类、其本地执行器、项目级 Agent（L1 老翁、L2 小祥）
迭代会话各迭代独立群聊与 L2 DSH 会话；子 Agent 隶属于 L2，不单独列成员
层级对内挂载职责
L1老翁 · 知识库管理员项目成员认识、文档摘要、正式文件整理、归档总结与长期记忆
L2小祥 · 任务调度员项目内同一角色，各迭代独立会话快速回应，重活派子 Agent，交活后再向群回报
子 Agent任务执行者L2 的任务槽独立执行；结束前必须向 L2 交活

单个迭代最多同时 7 个子 Agent 执行任务；L2 负责调度与群聊发言。本地 AI 通过 MCP 发消息不会触发助手回复循环。

三栏布局

  • 左侧：当前项目的迭代列表（含已归档只读）；底部打开「项目管理」和「小祥 Agent 监控」（L1 维护、各迭代 L2、子 Agent 槽位、上下文用量与手动压缩）。
  • 中间：迭代群聊。输入框左下切换对话模式；可引用版本或文件夹、上传附件、「帮我梳理群聊 / 帮我创建任务」快捷预填、停止或重试执行。群顶展示二级上下文用量。
  • 右侧：标准模式为文档浏览器；云开发模式为小程序工作台（见下文）。可全屏浏览文档树。

三种对话模式

对话模式决定这一条消息唤醒小祥时的规则。在迭代群聊输入框左下角点「+」打开菜单，三项与界面副标题一致：

  • 自由发言 — 默认 @ 与参与规则
  • 有问必答 — 必回，仅只读查询
  • 小程序云开发 — 联动云开发侧栏

当前迭代所选模式会记在浏览器 localStorage（按迭代 ID），换设备或清站点数据后需重新选择。发送消息时会把 dialogueMode 一并提交；服务端写入该次 agent_requests 记录。选中非默认模式时，输入框旁显示模式标签，点 × 恢复自由发言。

右侧栏顶部的「标准模式 / 小程序云开发」与对话模式联动：点「小程序云开发」会切到云开发对话模式并展开右侧；从云开发模式切回「标准模式」会恢复自由发言（若当前正是云开发模式）。选「小程序云开发」对话模式时也会自动打开右侧云开发面板。

模式何时用小祥行为
自由发言
default		 日常需求讨论、改文档、开任务、跑沙箱 多人项目未 @ 时可按需沉默（见下）；@ 小祥 或触发必回规则时走轻量或完整调度；可用完整写入与任务工具。
有问必答
chat		 答疑、对口径、只读查资料，不希望误改库或误开任务 每条成员消息都会回复；禁止创建/更新任务，禁止写入或修改项目文档、沙箱文件、小程序源码与云资源；仅查询、列表、读取类工具。服务端会注入只读 steering 约束。
小程序云开发
cloudbase		 做微信小程序 + 腾讯云开发（函数/库/存储/预览发布） 按云开发语境理解需求；右侧展示云开发工作台；子 Agent 在权限内可使用项目已配置的 CloudBase 受控工具。须先在项目管理完成小程序与云开发配置并通过连接测试。

按需参与（仅自由发言）

仅在自由发言模式且多人项目、未明确 @小祥 时生效。助手先判断是否要参与，可沉默；沉默不产生群聊消息，也不启动沙箱。

  • 必回：明确 @小祥；项目中只有一名人类成员与助手；句首「小祥，…」；催促不说话；同内容连发满 3 次；紧跟助手发言的短评（感谢/追问等，不含纯「好的/收到」）。
  • 可沉默：纯确认、冷却期内闲聊（约 60 秒，必回规则可打断）。
  • 轻量回复：只整合讨论、不跑完整调度；要写文档/总结/改文件或语气着急时，会提示再 @小祥 进入完整模式。
  • 连发多条待判消息会合并为一条可见回复；本地 Agent 消息不触发助手。

会话上下文

每个迭代 L2 对应独立 DSH 持久会话。群顶与监控页展示 token 用量与组成（系统、工具、讨论、文件结果、压缩摘要等）。接近容量时自动压缩较早内容为摘要；也可手动排队压缩（当前运行结束后执行，不删群聊记录）。子 Agent 与 L1 维护会话各自独立预算，详见仓库 docs/architecture.md。

涉及 HTML、网页或可视化产物时，子 Agent 须用受控截图工具验收（项目文档预览或沙箱内 HTML），不能仅用退出码代替。本机需 npm run setup:preview-browser 安装 Chromium。

文档库三区

全部迭代共享同一套项目文档库。

  • 对话缓存：对话框上传或 MCP upload_cache_draft / kind=cache_draft 分片。按 Asia/Shanghai 自然日进日期文件夹。内容对人可引用、下载、审核、软删除；不可在库里直接改正文。Agent 不能往这里新增。
  • 沙箱产物：主要由云端 Agent 在沙箱中生成并发布。人工不能把对话附件丢进这一区。
  • 正式文件：已确认的缓存/产物可另存至此，或人类（及 MCP kind=official_file）上传。正式文件不分版本叠加。同目录同名会改成「名称 (2)」，不覆盖。

群聊与 MCP post_message 可引用文件版本（refs）或文件夹（folderRefs，展示文件夹本身，不自动展开文件列表）。读取文件夹内容用 list_documents 的 folderId / recursive。

点「需要修改」必须填写意见，确认后发到当前迭代：沙箱产物 @小祥；对话缓存若不是本人上传则 @来源人，本人上传则 @小祥。上传和发布都不等于审批通过。

归档固定本轮讨论与引用版本；已确认产物最新版另存到正式文件。归档后本迭代不可改，文档库留给后续迭代。删除为可恢复软删除。回收站可在文件树底部永久清空：未被引用的文件会删除；仍被消息或任务引用的版本会保留内容，但不能再恢复。

小程序云开发

共序把项目级微信小程序身份、CloudBase 环境与迭代级群聊、右侧工作台绑在一起：源码与文档仍在项目文档库；预览、查库、管函数和发布在右侧六个页签完成；改代码、调云资源由小祥在沙箱与受控云工具中执行（对话模式选「小程序云开发」或右侧切到该页签）。

项目配置

路径：项目管理 → 小程序与云开发（需项目负责人或成员中的管理权限）。建议按页面顺序操作：

  1. 小程序身份：微信 AppID、小程序名称、默认预览页面路径（如 pages/index/index）；上传私钥（miniprogram-ci 用）粘贴后由后端加密保存，不入库明文、不写进文档树。
  2. CloudBase 环境：分别填写开发与生产环境 ID、Publishable Key；生产项可留空以沿用开发。另保存 CloudBase API 凭据（SecretId / SecretKey）供服务端代调。开发预览走开发环境；体验版上传、Admin 与正式发布走生产环境。
  3. 连接测试：保存后点「连接测试」——服务端用凭据只读查询云函数，并向微信请求生成预览码校验上传私钥。通过后工作区开放；不会上传正式版，也不保证真机云函数权限（须微信侧 AppID 与云环境已绑定或共享授权）。
  4. CloudBase 身份认证（可选）：按开发/生产环境同步匿名、用户名、邮箱、手机号登录开关；配置 Admin 首个账号供 Admin 预览登录。修改生产环境需确认。

配置状态在页头展示；验证失败会显示上次错误原因。只读成员可查看，不可改密钥。

右侧工作台

连接测试通过且当前迭代处于云开发对话模式（或手动点右侧「小程序云开发」）时，右侧替换为小程序工作台，顶栏六个页签：

页签用途
Dimina 预览按配置的小程序路径与机型尺寸预览小程序界面（开发环境）
Admin 预览预览 CloudBase 静态托管的管理端页面，配合身份认证登录
云数据库浏览集合、筛选与查看文档（只读/管理以权限与 Agent 工具为准）
云存储查看与管理云存储对象
云函数查看云函数列表、配置与调用相关操作
生产发布与正式发布、静态托管部署相关的操作入口

页签与预览状态会记在浏览器本地，便于刷新后恢复。文档库「标准模式」随时可切回，继续浏览正式文件 / 缓存 / 产物。

与小祥协作：在「小程序云开发」对话模式下 @ 小祥，可创建任务并由子 Agent 修改小程序相关文件、调用项目已授权的云开发工具（查/写数据库、云函数、云存储等）。「有问必答」模式下即使切到云开发侧栏，仍不能写入云资源。密钥与 Publishable Key 不会出现在群聊正文。

任务池

迭代内可创建辅助任务（L2 Ask）、沙箱正式任务、人类任务（本人执行或下发本地执行器）。人类任务创建时可引用正式文件版本（最多 30 个）。状态含待指派、待确认、待开始、执行中、等待中、阻塞，以及已拒绝 / 已放弃 / 已完成 / 已取消 / 已失败。状态变更和本地执行器汇报会 @ 任务来源人。任务详情「复制任务信息」与「复制会话信息」「复制项目信息」一样，会带上 MCP 服务地址、项目、迭代、任务 ID 和调用规则。

网页上传

对话框附件进入当天对话缓存；文档树正式文件菜单可上传到正式文件区（含子文件夹）。网页走带 SHA-256 的分片会话，单文件上限 20 MiB。服务端合并后再验整文件哈希，截断不会入库。

MySQL max_allowed_packet 建议至少 32 MiB。头像仍单独限制 5 MiB。

MCP 分片与校验

许多 MCP 宿主会把单次工具参数截在约 10KB。整包 Base64 被砍断后，文件会前半中文正常、末尾乱码——这是截断，不是 GBK。共序侧表现为：

  • upload_cache_draft / upload_official_file 的 contentBase64 上限约 10000 字符，且必须带完整原始字节的 SHA-256。
  • 原始文件 > 6144 字节（含大多数 md、zip）禁止一次提交，必须分片。

步骤

  1. 对完整原始字节算 SHA-256（64 位十六进制），不要对 Base64 字符串哈希。
  2. start_file_upload：对话缓存 kind=cache_draft + threadId；正式文件 kind=official_file + projectId（folderId 可省略）。填 byteSize、sha256。不要改默认 chunkSize=6144。
  3. 按原始字节切片，不要切 Base64。第 i 片是 bytes[i*chunkSize:(i+1)*chunkSize]，最后一片可更短。每片单独 Base64、单独 sha256，调用 upload_file_chunk。
  4. complete_file_upload 再交整文件 sha256。核对返回的 id、sha256、byteSize。

工作台「复制会话信息」和正式文件树「复制项目信息」会带上这段规则以及 ID。zip / application/octet-stream / 带 charset 的 MIME 按文件名推断，不会因此拒绝。

共序 MCP

账号一个令牌、30 天有效。由本地执行器在授权后申领并写入 Cursor / Codex / Claude Code。网页个人设置不再作为日常配令牌入口。疑似泄露时在本地执行器重置 MCP 令牌，旧令牌立即失效。

写入的配置等价于：

{
  "mcpServers": {
    "cothread-mcp": {
      "type": "http",
      "url": "https://你的站点/mcp",
      "headers": { "Authorization": "Bearer <账号令牌>" }
    }
  }
}

首次连接先调用 get_connection_guide。无需安装 SKILL。完整协议在 initialize instructions 与该工具返回中。

工具清单

完整列表以连接后 tools/list 为准（当前共 28 个工具）。只读侧含项目/迭代/成员上下文、文档目录与版本下载、消息与任务查询、L1 诊断；写入侧含 manage_document / manage_folder、分片上传、upload_cache_draft、post_message（refs + folderRefs）、任务 accept / reject / update、retry_l1_task。

只有 post_message 会发群聊。上传、改文档、改任务默认不自动发言。创建任务、转交、审批、归档不通过普通 MCP。只读成员不能上传或发言；归档迭代不能改。MCP 服务器名 cothread-mcp（旧名 cothread 请改名）。

本地执行器

Windows 单文件程序（npm run connector:build），由系统外部渠道分发，网页不提供安装包。一个账号同一时间只保留一台本地执行器，可绑多个项目。每个项目选 Git 仓库，可选仓库内路径。本地路径只保存在电脑上。

「交给本机 Agent」：项目内任意可编辑成员的本地执行器在线即可。任务需被指派成员确认后锁定到一台设备，在本机以 Cursor / Codex / Claude Code 的交互式会话执行。

  • 开始：按当前 HEAD 建独立 Git worktree，打开 Agent，首条提示引用任务卡。
  • 会话中：人在窗口里打字和审批工具；Agent 用共序 MCP 回报。关窗不算完成，任务变为暂停，本地执行器可续租。
  • 完成 / 失败：由人在本地执行器点击。完成可带 Git Diff 回群。

两套令牌：ctc_ 设备令牌只用于本地执行器通讯；账号 MCP 令牌供 Agent 以该成员身份读写共序。

本机与命令

npm run mysql:stop    # 关闭本地数据库
npm run dev:stop      # 停开发网关 / API / Vite；MySQL 保持运行
npm run build
npm start             # 生产静态页 + API
npm test              # 须独立测试库（TEST_DATABASE_HOST_* + TEST_DATABASE_AUTH），禁止清日常库
npm run db:backup
npm run db:restore-check

npm test 会清空目标库全部表后重新迁移，绝不能指向生产库或正在用的开发库 cothread / cothread_dev。本机可在同一台 3307 上另开 cothread_test。

也可用 compose.yaml 跑官方 mysql:8.4.9。不要同时让 Docker 与便携版 MySQL 占用 3307。

服务器 / 容器

  1. MySQL 8.4，导入完整备份（含附件）或空库迁移。
  2. 配置 DATABASE_HOST_INTERNAL / DATABASE_HOST_PUBLIC（host:port/dbname）与 DATABASE_AUTH（user:password）；可选遗留整段 DATABASE_URL。TLS 时 DATABASE_SSL=true。
  3. 测试库同样用 TEST_DATABASE_HOST_* + TEST_DATABASE_AUTH，库名须含独立单词 dev 或 test。
  4. 监听、站点与 Secure Cookie 已在代码写死；保留 CREDENTIAL_ENCRYPTION_KEY，与库备份分开保管。
  5. npm ci && npm run build，单实例 npm start。ECS 探活通过后再切 current，见仓库 docs/cloud-environment.md。

当前仅支持单服务实例。权威会话快照在 MySQL；.local/agents 需可写缓存。

ECS 发布

生产为阿里云 ECS 单实例 + RDS，只有这一条部署路径。npm run build && node scripts/ecs-pack.mjs 打包后，在机器上执行 RELEASE_TGZ=... bash scripts/ecs-promote.sh：新版本解压到 /opt/cothread/releases/<id>，临时端口探活 /api/health，通过后才原子切换 current 并重启 cothread；失败则删除本轮 release。变量清单见仓库 docs/cloud-environment.md。生产默认 https://cothread.z2l.top。
