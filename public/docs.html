User guide

共序使用手册

这本手册给已经会用协作工具、想弄清共序有哪些功能、以及这些功能按什么规则运转的人。界面尽量少让人学；这里不把「第一次点哪里」当成正文，而是说明每项能力在维持什么、何时生效、何时故意不生效。产品介绍见关于我们。

当前是一套服务上的小团队。下面写的是使用者能碰到的行为。安装、数据库和服务器发布不在这里。

这份手册写给谁

会用，和知道系统在守什么，不是一回事。共序把很多判断做成了默认行为：没被 @ 可以不说话，上传了也不算通过，停止了也不能把已经写出的文件收回来。这些不是界面没做完，而是规则。弄清规则之后，才知道该把一件事放进群、放进任务、放进正式文件，还是留到归档时再决定。

四条运转原则

  1. 过程与成果分开。群是这一轮的过程。文档库是项目的成果。结束一轮讨论不会把文档库清掉，也不会自动把草稿晋升成正式文件。
  2. 引用锁版本。消息和任务引用的是当时那一版。文件后来改了，旧消息打开的仍是它引用的那一版。决定可以回溯，是因为引用没有被后来的保存覆盖。
  3. 助手可以做，确认权在人。上传、发布到沙箱产物、整理出归档方案、提交生产发布，都只是提出或执行。通过、归档确认、生产批准，必须由有权的人做。小祥不能代确认、代批准、代清空回收站。
  4. 身份和会话不混用。知识整理、群里调度、具体执行、你自己电脑上的仓库，各用各的会话和权限。一个迭代的上下文不会变成另一个迭代的记忆；本机助手以你的成员身份连接，不会反过来把服务器密钥带下去。

四层对象

一次部署是一家公司自己的空间：账号、项目和文件都在这套服务里，和其他部署无关。公司里面再切三层，是为了让「长期要留的」和「这一轮正在吵的」不要放在同一个生命周期里。

对象 生命周期 为什么单独成一层
项目 长期 成员、文档库、小程序凭据、代码仓库连接、项目长期总结都挂在项目上。换一轮讨论不应该把这些拆掉
迭代 一轮讨论 消息、背景与目标、这一轮的小祥会话、任务编号都属于这一轮。结束时可以冻结，而不冻结整个项目
任务 一件可派、可确认、可执行的工作 群消息是说法，任务是可追踪的执行。交接到下一轮时，任务身份还在，只换展示编号和所属迭代

顶栏是项目。左侧是这个项目的各轮迭代，分「活跃中」和「已归档」。中间才是这一轮的群。右侧是项目级成果：标准模式下是文档库，CloudBase 模式下是这一轮要用的运行与发布面板。凭据仍在项目上，不在某一轮消息里。

人、老翁、小祥

公司账号目录只包含人类；项目成员中另有老翁和小祥两名 Agent。Agent 不占人类账号，停用、重置密码和平台角色分配只对人类账号生效。

谁 挂在哪 负责什么 不负责什么
老翁 整个项目。四件维护各有一套可接续的会话，不进某一轮群聊 认识成员怎么说话、给文档做事实摘要、整理正式文件的归类和命名、在归档时写方案并在人确认后更新项目长期总结 不进群，也不出现在 @ 列表里。不代替人做归档确认
小祥 项目里的一名 Agent，与老翁不分等级；每一轮迭代单独一套会话 在群里协作。可以直接使用工具，也可以把工作委派给最多 7 个子 Agent，再把结果说回群里 不把子 Agent 当成成员。把任务派给某人，或改别人名下的任务，必须有人类授权。不在「有问必答」里改任何东西
子 Agent 小祥委派的执行槽，每个任务自己的会话 改文件、跑受控命令、按授权动云资源。使用小祥的插件和 Skills。结束前必须向小祥交活，成功失败都算交 不叫小祥，不单独列在成员里，不能自己批准发布或确认归档，也不能扩大任务归属

老翁和小祥没有上下级。老翁做知识维护，小祥做群聊协作，两边不共用同一次思考。老翁的四件维护（认识成员、文档摘要、迭代归档、项目记忆）在「小祥监控」里分别有卡片：同项目多次做同一件，接的是同一套上下文。每一轮的小祥互不看见对方的会话。子 Agent 第一次可以带着这一轮的快照出发，之后只接收这条任务上追加的要求，不再把整段群聊灌进去。

一轮里同时执行的云端子 Agent 最多 7 个。这是并发槽，不是成员名额，不表示成员等级。槽满了，沙箱正式任务会停在待指派，有空位再继续；不会悄悄多开第 8 个。子 Agent 用的插件和 Skills 与小祥相同。

项目里的身份和管理空间里的平台角色是两套账，见两套权限。项目侧：一个项目只有一位项目主，由现任转移。项目管理由项目主指定，不能同时又是项目主，也不能从只读成员直接提升。归档只属于这轮迭代的创建人或当前项目主，项目管理不能单凭身份归档。

项目身份 边界
项目主 项目资料、成员、连接器、小程序凭据；可转移项目主；可发起、撤回、重试、确认归档；可批准生产发布
项目管理 协助项目内管理。不能单独归档，不能移走或改写项目主
成员 讨论、上传、建任务、引用文档、在授权范围内使用云开发工作台
只读成员 看讨论和文档。不能发言、上传、改任务、改密钥

工作台对应什么

三栏不是装饰，是三套状态的入口。

  • 左侧选轮次。未读条数和未读 @ 标在迭代上。归档过程中会标「归档中」。底部「项目管理」维护项目级事实（基础信息、项目成员、连接器、小程序与云开发）。「小祥监控」看老翁四件维护、各轮小祥、执行槽和上下文，不在这里改群。
  • 中间是这一轮。三个页签分工不同：「对话」是人能引用的发言；「轨迹」是这一轮助手实际调用过什么，用来核对它做过的事，不是第二套聊天；「背景与目标」是这一轮的方向，进行中可改并留下变更记录，归档一开始就冻结。
  • 右侧是成果与运行。「标准模式」浏览文档库，「CloudBase」打开运行时面板。两者和对话模式联动，见下文。全屏和拖宽度只改变看的方式，不改变文件属于项目这一事实。

背景与目标谁都能在进行中提议，但写入要有原因。小祥只有在事实清楚、而且当前不是有问必答时，才能自己更新，并且必须写下原因。记录按时间留下改之前的内容；还没有审核者时显示「未审核」。这不是一条审批流，只是让方向变化可追溯。

输入框左下角的「+」选择的是下一条消息的约束，不是把整轮永久改成另一种产品。模式记在这台浏览器的这一轮上，换设备要重选。快捷语「帮我创建任务」只是预填一条 @ 小祥的草稿，发送之后仍按普通消息和当前模式处理。

四种对话模式

模式是发给小祥的约束，不是皮肤。服务端按你发出的那一条记录模式。选错模式时，能力会真的消失，而不是只少一个按钮。

模式 约束 适合
自由发言 默认参与规则。可以沉默，也可以走完整调度：写文档、派任务、进沙箱 日常把事情做完
有问必答 每条成员消息都要回。工具被收成只读：不能建或改任务，不能改文档、沙箱、小程序源码和云资源。也不能改背景与目标 对口径、查已经存在的资料，防止顺手改库
仅小程序 按微信小程序理解本次需求，做源码、Dimina 预览与微信上传；不采用 CloudBase 开发流程 不涉及云函数、云数据库或云存储的小程序工作
CloudBase 按微信小程序和腾讯云开发理解需求，并打开右侧工作台。子 Agent 只能用这个项目已经配好并测通的云能力 改小程序、查云、准备发布

对话模式与右侧「标准模式 / CloudBase」联动。选择「仅小程序」或「CloudBase」会打开右侧工作台；在右侧选择 CloudBase 时，已有的「仅小程序」模式保持不变，其余模式会切到 CloudBase。从右侧切回标准模式时，「仅小程序」和「CloudBase」都回到自由发言。是否只读以发送消息时的模式为准，不能仅凭侧栏是否打开判断。密钥不会因为开了侧栏就出现在群正文里。

按需参与

只有自由发言、项目里不只有你一个人、而且你没有明确 @ 小祥时，才会先判断要不要张嘴。判断的目的是让群还像人在讨论：不是每句「好的」都插入一段助手发言，也不是该干活时只回「我这就开始」。

  • 直接进入完整回复，不再先问要不要参与：明确 @ 小祥；句首写成「小祥，…」或「小祥 …」；或者当时项目里只有你一个人类和助手。人类人数按项目成员算，不按在线人数，也不把老翁、小祥、子 Agent 算成人。单独一个「小祥」不算点名。
  • 硬规则，必须短回：催它为什么不说话；同一内容连发满 3 次；紧跟它上一条发言的短评（感谢、追问、夸一句）。单纯的「好的」「收到」不算短评。
  • 可以不回：纯确认；它刚说过话之后大约 60 秒里的闲聊。上面的硬规则可以打断这 60 秒。
  • 轻量回复：只把眼下的讨论收成一句理解，不启动完整调度，也不打开沙箱。要写文档、总结、改代码、派任务，或催它开工时，这句先不发出：草稿如果已经在答应，或者这件事本身就是实活，整句换成「需要麻烦你再@小祥，我才会真的开始。」不再把许诺和提醒叠在一起。拿不准时再问一次，需要才把这句接在后面。轻量路径不会因此升级成完整调度。

一段连发只会落下一条可见回复，并把其间还没被回答的消息吸收进去。它先起草，发出前若又来了新消息，就改稿或不发。模型嘴里说「以后每条都回」不作数，规则不以聊天承诺改写。沉默只留下内部状态，群里没有那条消息，沙箱也不启动。本机助手或小祥自己发出的消息不会再触发一轮回复，避免自己和自己循环。

上下文与压缩

上下文是模型这一次能看见的工作记忆，不是群记录本身。群消息、任务和文档都在库里；上下文是从中装进这一次会话的那一份。

每一轮小祥有一份长期会话，容量按调度来设计：默认大约 25.6 万 token，用到约七成就自动压缩，而不是拖到模型极限再一次性丢掉前面。老翁的维护会话和子 Agent 的任务会话是做完就结束的，单次可以顶到大约 100 万 token，用来扛一轮大批量整理或一次长任务。按需参与的那一下轻量判断不走这些预算。它先看最近 12 条：正文合计超过 4000 字，就从最旧的一条开始丢掉，直到装得下；只剩最新一条仍然超过，就不再叫模型，直接不插话。点名、催沉默、连发和短跟帖仍用短句，不把过长正文交出去。没超限时全文进入判断，不再把每条截短。

对话区展示的是这一轮小祥的用量。组成大致是：系统指令、工具定义、成员讨论、助手回复、文件与工具结果、压缩摘要、还没装进去的新消息。没被读过的文档正文不占这份用量。展示用的是估算，用来判断挤不挤，不是账单上的精确扣费。

压缩把较早的内容换成一段摘要，并保留最近一段原文（调度会话大约留 3.2 万 token）。群聊、轨迹、维护记录和文档都不删。自动压缩发生在下一轮开始前，以及执行步骤之间。你点「立即压缩」只是排队：当前这轮跑完才执行，快照真正写完才算压缩完成，失败可以再试。所以压缩改变的是助手接下来怎么回忆，不是你们已经说过的话。

文档库四区

一个项目的所有迭代共用一套文档库。分成四区，是为了把「人刚丢进来的」「助手做出来的」「已经认账的」「小程序工程」从权限上拆开。混在一个文件夹里，就无法同时满足只读、可发布、可确认。

区 谁可以往里放 原则
对话缓存 人在对话框上传，或本机助手随消息送入。按北京时间的自然日进日期文件夹 对人可引用、下载、审核、软删除。不能在库里改正文。小祥不能往这里新增，避免助手把草稿伪装成你的附件
沙箱产物 主要是云端执行：在沙箱里生成、修改后发布 对话框附件进不了这里。人可以预览、下载、确认、另存，不能把聊天附件直接丢进产物区冒充执行结果
正式文件 人上传，或把已确认的缓存、产物另存进来 这是认账之后的资料。不按版本号往同一条上叠加；同目录同名会变成「名称 (2)」，不覆盖。不走「需要修改」那条打回流程
小程序 小程序工程的固定工作区 四个子目录是稳定的：小程序源文件、小程序 Web 产物、PC 管理后台、云函数。预览和发布读的是这里，不是某条聊天附件

正式文件整理已于 2026-10-25 下线：入口关闭，正式文件区不再因整理而锁定，历史整理记录仍可查看。文档摘要是另一件事：给正式文件、沙箱产物和对话缓存写事实摘要，供以后的助手查阅，不代替你确认文件。

项目长期总结在项目管理的基础信息里看。它不是聊天记录的复制。归档方案准备阶段不写它；只有人确认归档之后，才排队给老翁把这一轮的结论沉淀进去。所以总结里出现的内容，应是已经认过的结论，而不是草案。

版本与审核

引用锁的是版本标识，不是「当前这个文件名」。群消息和任务可以引用文件版本，也可以引用文件夹；文件夹引用展示的是文件夹本身，不会自动把里面的清单展开。一条消息最多引用 30 个文件。要看文件夹里现在有什么，应在文档树里打开，而不是假定旧消息会跟着更新。

上传成功和助手发布成功，状态都不是「已通过」。点「需要修改」必须写意见，确认后发到当前这一轮：沙箱产物 @ 小祥；对话缓存如果不是你传的就 @ 上传者，是你传的则 @ 小祥。这样打回的是「谁该改」，而不是在库里直接覆盖。

已确认的缓存或产物要进入正式文件，必须显式「另存为正式文件」。归档不会替你做这次复制。删除是软删除，回收站在文件树底部。永久清空时：没有被消息或任务引用的文件会真正删掉；仍被引用的版本留下内容，历史消息还能打开，但不能再恢复到树上。小祥和本机连接都不能清空回收站，避免助手把审计痕迹清掉。

在输入框里去掉一个还没发送的已有项目文件，只是取消引用。去掉一个刚上传的附件，则会把那个缓存文件送进回收站。发送之后，文件留在文档库，不随消息滚动消失。

上传与预览

对话框选文件或粘贴文件，进入当天的对话缓存。正式文件区的上传菜单进入正式文件，可以指定子文件夹。单文件上限 20 MiB。网页上传会在合并后核对整份内容，传了一半的字节不会入库。从本机助手上传较大文件时也一样：连接会自动分片再核对整份，是为了防止中途被截断后还显示成一份正常文件。你不需要自己切，也不需要手算校验值。

群正文按 Markdown 显示表格和任务列表，但图片不嵌进对话，只显示「图片链接」。指向本站某一版文档的链接在侧栏打开那一版，外链新窗口打开。文档预览覆盖文本和代码、图片、PDF、Word、Excel、PowerPoint。Markdown 不执行里面的原始网页，也不加载外部图片。没有在线编辑：要改内容，就产生新的文件或新的产物，而不是在预览里改旧版本。

项目记忆

项目记忆是项目级的沉淀，不是文档库里的一类文件。它由老翁整理：日常群聊里的结论、任务变更、正式文件的新版本都会进入待整理队列，老翁按节奏把它们写成条目。人只做两件事——确认某一条，或指出某一条不准确。没有「自己写知识页」这一步；右侧栏原来的「知识页」面板已经下线，问老翁回答里的引用会直接打开项目记忆并定位到那一条。

打开后是左右六四开，左边读、右边找：

区域 给谁 看到什么
左栏 导读 刚加入的人 这个项目做过什么、现在到哪一步、先读哪几条，以及最近一次归档后的更新
右栏 时间轴 参与过、想回忆的人 圆点串起时间轴，每条先显示时间和类型，下面是标题卡片，可以搜索；点一条弹出详情
记忆详情 要核对的人 正文、出处、所属迭代的结论与任务去向，以及确认、纠错

条目有三种状态。草稿是进行区：老翁日常整理出来、可能还没定的内容。现行是沉淀区：经过人确认的内容。被替代是退场的旧结论，保留可查。问老翁只用现行条目回答，草稿不参与。时间轴顶部可以按状态筛选，默认只看草稿和现行的，要翻旧结论再勾上被替代。

确认和纠错都会再问一次：确认这条记忆会转成现行、以后问老翁用它回答；纠错会把它标成待裁决，老翁下次结算时参考你写的备注。两个弹窗右上角都能切全屏，关闭用右上角的叉或 Esc。

入口在左侧「项目记忆」。第一次进入某个项目时会自动打开一次，关掉就回到群聊，之后随时可以从左侧打开；从组织主页点项目会直接落在项目记忆。每次归档之后如果有新变化，入口会提示。

迭代归档时清算

每轮迭代归档时，除了写下这一轮的结论，还会对记忆做一次清算：归档确认页会列出这一轮整理出的草稿，勾选的当场转为现行；互相冲突的标成待裁决，被取代的条目退场。没勾的草稿不会自动转正，也不会卡住归档，会留在进行区并计数提示。确认完成后会显示清算结果：转正几条、保留几条、替代几条、待裁决几条。

项目归档等于关账：项目从工作台消失，项目记忆随项目一起封存，成员不能再打开或修改；要接着用，由管理员恢复项目。

任务如何被安排

任务是可派发的工作，不是群里的一句话。每一轮内部有展示编号，上限 9999。交接后底层仍是同一件任务（来源、产物、执行历史都留着），只是在新一轮重新编号。所以「这件活换了一轮」和「新开了一件活」能分开。

三种来源，调度方式不同：

  • 辅助任务：小祥要问一句或做一段不落成正式沙箱发布的查询。当时必须有空闲执行槽，创建后直接执行。
  • 沙箱正式任务：要改项目文档或在云端做完并发布。有空槽就执行，没有就待指派，槽空出来再接，不用人再点一次。
  • 人类任务：先待确认。被指派的人拒绝，或发起人取消，就结束。确认之后由本人做，或下发到这个人在本项目已授权的本地执行器。创建时可以带上正式文件版本，最多 30 个。

小祥可以随时安排自己负责、或已经派给子 Agent 的任务。把任务派给某个人，或改动别人名下的任务，必须这一轮里有人类明确授权。子 Agent 围绕绑定任务工作，可以使用共享工具，但不能扩大任务归属或借用人类授权。对人的任务如果要重来，会回到待确认，而不是直接在对方电脑上再跑一遍。

状态用来区分「还没人接」「在跑」「在等」「已经结束」。你会看到待指派、待确认、待开始、执行中、等待中、阻塞，以及已拒绝、已放弃、已完成、已取消、已失败。状态变化和本机执行器的汇报，会在来源迭代 @ 任务来源人。结束态不再启动还排着队的工作；归档时，没跑起来的待确认、待指派和阻塞任务可以由人决定留下或交接，见归档。

「复制任务信息」「复制会话信息」「复制项目信息」把连接地址、项目、迭代、任务和调用约束复制出去，是为了让本机助手对准这一件，而不是凭聊天猜 ID。点停止只停止还没做完的过程，不能撤销已经发生的外部操作，也不能收回已经保存的版本。

CloudBase

小程序能力拆成两半：项目上的身份和密钥，以及某一轮里的预览、数据和发布操作。源码在文档库的小程序区，不在聊天附件里。这样换一轮讨论时，AppID 和云环境不用重配，而某一轮的群不会变成全项目的发布开关。

凭据放在项目上

入口是「项目管理 → 小程序与云开发」，项目主或有管理权限的成员可写，只读成员只能看。

  1. 小程序身份：AppID、名称、默认预览路径。上传私钥保存后不再以明文出现在文档树或群里。
  2. 两套云环境：开发和生产各自的环境 ID 与 Publishable Key。生产可留空并沿用开发，但含义不同：开发预览走开发环境；体验版上传、Admin 和正式发布走生产环境。另有一套接口凭据供服务器代调，不交给浏览器长期保存。
  3. 连接测试：用凭据做只读核对，并向微信要一次预览校验私钥。通过后工作台才开放。它不上传正式版，也不代替微信侧把 AppID 和云环境授权绑好。
  4. 身份认证（可选）：按环境同步匿名、用户名、邮箱、手机号登录，并准备 Admin 的第一个账号。改生产环境会再确认一次。

页头的通过或失败是上次测试的结果。密钥配错时，工作台不开放，而不是开放了再在群里报一串密钥。

连接测试通过，且这一轮处于云开发对话模式（或你点了右侧「CloudBase」）时，右侧六个页签是运行面，不是第二套配置：

页签和机型记在这台浏览器，方便刷新后续上看。在云开发模式下 @ 小祥，子 Agent 可以改小程序区里的文件，并调用已授权的云能力。有问必答打开同一侧栏也不能写。

谁可以发布

体验版和生产发布故意拆开。体验版是给真机看的测试包：有项目写权限就可以在 Dimina预览里上传，不进共序审批。提审和正式上线仍在微信后台，共序不代点。上传体验版不等于提交审核。

Admin 生产静态站和云函数会作用到生产环境，所以走审批。新建申请时勾选目标和说明。待审批由项目主批准或拒绝；批准后立即执行，没有「已批准待人去点发布」的中间态。申请人在待审批时可以放弃自己的申请。小祥可以替人提交和查看，不能批准。项目主自己提交的可以自己批；小祥提交的只能由项目主批。

  • 申请绑的是提交时的源码。待审批期间源码变了，这张单失效，必须重提。否则会批准旧说明、发出新代码。
  • 待审批超过 24 小时失效。
  • 同一项目、同一发布目标，同时只能有一张待审批。
  • 执行失败不自动重试。原因留在申请和发布记录里，避免失败被下一张单悄悄盖掉。

归档与交接

归档冻结的是这一轮的过程，不是项目。发起人只能是这轮迭代的创建人或当前项目主。开始前会检查还有没有在跑的任务、助手回合、执行器、工具、沙箱或上下文压缩；有的话保持进行中，并告诉你卡在哪。检查和「又启动一个任务」用的是同一把锁，避免一边开始归档、一边又跑起来。

状态 写入 人要做什么
进行中 消息、任务、背景与目标都可以按权限变 正常协作
归档中 这一轮的普通写入冻结。文档库不冻结 老翁根据冻结时的讨论、引用版本和任务快照整理方案。创建人或项目主可调整、撤回或确认。整理失败可重试或撤回，撤回回到进行中
已归档 只读 回看结论和每件未完成事项的去向。旧版本仍可被新一轮引用

方案准备阶段只产出草案，不改项目长期总结，也不往原群里写业务消息。人必须对全部未完成事项做决定，不能漏一件、也不能混进别人的任务。每件三选一：

  • 仅归档：留在这一轮，业务状态保持原样，只是不再启动还排着队的工作。
  • 录入新迭代背景：写进承接迭代的背景，不生成任务。
  • 生成新迭代任务：任务身份、产物和执行历史延续，新一轮重新编号，调度改由新一轮的小祥负责。

没有要交接的任务时，可以只归档、不建下一轮。只要有任务要交接，就必须有承接迭代，否则任务会失去所属轮次。确认在一次提交里做完：固定人的决定、标记留下的任务、把交接任务挪到新轮并收口旧队列、把原迭代标成已归档，然后才排队更新长期总结。重复确认不会再建一轮。撤回和确认只会成功一个；晚到的整理结果不能写回已经撤回或已经被替换的那一版方案。小祥不能代替人按确认。

账号与通知

登录标识是用户名，或已经绑定的邮箱。注册、绑定、更换邮箱、重置密码都用 10 分钟内有效的邮箱验证码。邮箱不用于邀请进项目；进项目是成员关系，不是邮箱域名。

「在当前设备记住登录信息」只存在这台浏览器，最多 8 个账号，供登录页快捷进入和个人设置里切换、退出、清除。它不是服务器上的受信任设备列表。换浏览器或清站点数据就要重新登录。头像上限 5 MiB，和文档的 20 MiB 分开算。

站内信是成员关系和对你的点名，不是第二套聊天。分类为全部、@我的、加入项目、移出项目。迭代上的未读是「你还没读到的消息条数」；读到最新后未读清零，该位置及以前的 @ 通知标为已读。@ 可以点姓名、用户名或邮箱；输入 @ 列出当前能提到的人。老翁不在这个列表里。

项目图片（PNG、JPEG、WebP，不超过 512 KiB）是项目的识别标记，没有图或加载失败时用名称首字。它出现在项目列表和站内信里，不参与文档版本。

顶栏主题只改变这台界面的外观。书本图标是本手册。

两套权限

项目身份决定你在某一个项目里能写什么。平台角色决定你在管理空间里能看哪些菜单、能按哪些按钮。同一个人可以两边都有，但不会自动打通：项目主不会因此变成超级管理员；超级管理员也不等于每个项目的项目主。

管理空间用同一套登录。每个人都有「我的工作」（我的项目、我的迭代、我的任务），角色关不掉，而且只读。没有别的权限时，只能看到与自己有关的范围：你加入的项目、其中的迭代，以及你创建、作为来源、被指派、承接或确认的任务。

菜单 能决定什么 不能决定什么
我的工作 跨项目查看自己的项目、迭代、任务，可筛选 不能在这里改状态。接受、转派、执行、取消仍回工作台
组织工作 跨项目看项目、迭代、任务。项目可新增、结项、恢复。进行中的迭代可改名称 运行中或已结束的任务、已结项项目、已归档迭代，不能在这里改资料。工作台里的结项按钮尚未开放，结项只在这里
账号权限 账号的新增、停用、恢复、重置密码、分配角色。角色按菜单、页面、功能授权 变更记录和登录记录人人可开；没有「查看全部」时只看自己的账号。重置密码会使该账号现有登录失效

超级管理员拥有全部平台权限，不必再挂角色。普通成员默认没有组织工作、账号管理和平台管理。多角色取并集。只勾选页面是只读，不含新增和编辑；只勾选菜单则进不了页面。每次请求都重新读权限，撤销后下一次就生效，不用等重新登录。

模型配置

入口在管理空间的平台管理，地址是 /admin/model-settings。打开页面需要「模型配置」权限；保存需要另外的「保存模型配置」。没有保存权限时可以看当前生效项，不能改。

页面标出来源、版本和更新时间。还没有已保存配置时，来源是环境变量；校验通过并保存成功后，改为已保存的配置。默认模型同时给老翁、小祥和子 Agent。可以勾选「老翁使用独立模型」，单独写老翁的地址、模型名和推理强度。

API 密钥加密保存，页面不回显。已经配过时，输入框留空就是沿用已存密钥。第一次保存必须填写默认密钥。老翁改成独立模型、且还没有为他存过密钥时，老翁的密钥也要填。

点「校验并保存」时，默认模型要通过普通响应、完整流式响应和结构化输出三项检查；启用老翁独立模型时，该模型也要通过同样的检查。校验没通过，继续用保存前的配置。校验已经通过、但保存没有成功，同样保留旧配置，不会换成半截新值。若别人刚保存过，会提示「模型配置已被更新，请刷新后再保存」。先点「重新读取」，看到新的来源、版本和时间，再保存。

切换模型不用重启服务。已经在跑的工作保留它启动时捕获的模型。同一迭代里还有子任务在跑时，这一轮的新请求会等那些子任务结束后再换模型。服务把当前生效的配置留在内存里给后续请求用，不是每一次模型调用都去库里查一遍。

插件管理里的对象只有老翁和小祥。以前记在子 Agent 名下的 Skills 会合并显示在小祥配置中，历史记录保留。之后子 Agent 继续用小祥的插件和 Skills，不能在这里单独加一套工具或权限。

委派出去的管理员不能发出超出自己范围的权限，不能改比自己更高的角色或账号，也不能给自己改角色。不能停用自己的超级管理员身份，也不能停用最后一位仍有效的超级管理员。结项后的项目只读，工作台列表不再出现。

连接器在项目管理里，不在管理空间。目前可登记 GitHub 和云效 Codeup，把外部仓库指到这个项目。令牌是否已配置会显示，明文不回显。修改需要项目管理权限。本机执行器用的是你电脑上的仓库路径；连接器解决的是「项目认识哪个远程仓库」，不是代替本机执行器。

本机助手与连接

本机助手解决的是云端沙箱碰不到你的 Git 仓库。Windows 本地执行器由管理员在系统外分发，网页不提供安装包。一个账号同时只保留一台执行器，可以绑多个项目。每个项目选仓库，可选仓库内路径；路径只留在你的电脑上。

授权之后有两套凭证，用途不同。设备凭证只让这台执行器和共序说话。账号凭证让 Cursor、Codex 或 Claude Code 以你的成员身份读写共序，所以它能做的事不会超过你在这个项目里的权限：只读成员不能上传或发言，归档中的迭代不能改。执行器把连接写进助手，个人设置的 MCP 配置里可以查看已授权设备并解除绑定。怀疑泄露时在执行器里重置账号凭证，旧的立即失效。不要把凭证抄进群。

「交给本机 Agent」并不自动在你电脑上开工。项目里要有可编辑成员的执行器在线，任务还要被指派的人确认，然后才锁到一台设备。开始时按当前版本做独立的 Git 工作副本，再打开助手，第一条就是这张任务。你在窗口里打字并批准它要用的工具。关窗口不是完成，任务变为暂停，执行器可以续上。完成或失败由你在执行器里点；完成可以带回 Git 差异。

通过这条连接，助手可以读项目和这一轮的上下文、列文档、下载某一版、发群消息、分片上传、接受或拒绝派给它的任务、汇报进度。它不能创建一套新的审批、不能确认归档、不能批准生产发布、不能清空回收站。上传和改任务默认不会自动在群里再发一条；只有明确发消息才会出现在对话里，而且这种消息不会把小祥再叫醒一圈。

有意不做的事

  • 没有在线编辑、没有全文搜索、没有对象存储。文件字节在这套服务的库里，单文件 20 MiB。
  • 没有单点登录，没有手机推送。通知是站内信。
  • 没有多台服务器一起抢着跑任务。停止不能回滚已完成的外部副作用。
  • 自定义 Skill 不能变成新工具或新权限。
  • 工作台不能结项。结项与恢复在管理空间，结项后项目从工作台消失并只读。
  • 体验版不是生产发布。生产发布不是微信提审。
  • 云端命令约 90 秒封顶。本机执行没有隔离，只适用于可信任务。
